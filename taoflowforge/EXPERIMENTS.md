→ **本数据集批量可用率 2/8，复用前提 = 输入预处理（抠背景+主体居中）**。

**关键发现（修正 E-02 的判据）**：
1. **"主体占比 >30%" 判据在预处理输入下失效**——干净输入下模型输出更多顶点/面（剃须刀 3392→7539），\n   stage2 拓扑阶段同时产出数千个 1~几面的**微尘碎块**，总面数被 inflate，占比自然下降。\n   但碎块在视觉上可忽略（网格微尘），**真实可用性看视觉完整性而非占比**。\n2. 连通体数（3000~36000）与输入干净度无关，是 stage2 拓扑固有的碎块噪声，下游使用应统一过一遍\n   最大连通体提取（或 trimesh remove_unreferenced + 小面数过滤）。\n3. 单图重建天花板仍在：背面是幻觉、细薄结构（表带/天线）丢失——这是方法本身限制，非输入问题。\n\n**预处理侧的坑（已固化在 05 脚本）**：\n- SAM3 文本 prompt 对物体名敏感："router" 全灭（含 electronic device），补链\n  `x shaped router` 救回立姿图、折叠姿态图仍 0 实例（prompt 词表盲区，非图问题）。\n- prompt 驱动已改为**回退链**（逗号分隔逐词尝试，首个产出 mask 者命中），\n  兜底词：厨房类 "kitchen appliance"、电子类 "electronic device"。\n- 驱动从 vggt_human 的 `sam3_face_masks_worker.py` 换成自研 `05_sam3_masks.py`\n  （直接调 `set_text_prompt`，省去逐文件夹 init 开销；env=sam3，ckpt 复用 vggt_human_ms）。\n\n---

## 2026-10-28 环境搭建阶段（先于推理）

### 已核实的环境事实
- 上游 requirements.txt 有 bug：`Pillow==12.0.0` ↔ gradio 5.50.0（要求 pillow<12.0）
  冲突，pip 新解析器直接 ResolutionImpossible。00a 运行时 sed 降级 Pillow==11.3.0。
- open3d 0.19（pip wheel）依赖系统 libgomp.so.1；libgcc-ng 15.x 不再捆绑，
  `conda install -c conda-forge libgomp` 解决（WSL 无 sudo，apt 不可用）。
- `--offload` 上游 choices 为 auto/on/off（默认 auto），README 早期写的 "stage" 有误，
  02 脚本已修正——**以 cli.py 为准**。
- ModelScope SDK 下载有总时限：26GB 权重 1 小时报 `[E1001] 下载总时限已耗尽`，
  续传时限不放大 → 大权重走 Windows 侧迅雷/curl 直下 resolve 直链更稳。
- stage0.pt 若不内嵌 dino_encoder.* 权重 → 推理必须 `--dino-checkpoint`
  （备用镜像：ModelScope `facebook/dinov3-vitl16-pretrain-lvd1689m`，非 gated）。
  下载完成后用 `04_check_weights.sh` 一键探测。
