## 2026-10-28 E-01 首跑基准：剃须刀单图（3090）✅

| 指标 | 值 |
|---|---|
| 输入 | `/mnt/d/dataset/物体三图数据/剃须刀/01000000.jpg`（1024²，seed=42，offload=auto） |
| **总耗时** | **344s ≈ 5 分 44 秒**（metadata 各阶段之和 306s + 模型加载 ~38s） |
| 分阶段 | stage0 占据 59.5s（50 步，1022 cells）｜stage1 顶点 162.9s（90 步三级 64→128→256→512，3396 顶点）｜stage2 拓扑 78.1s（50 步，7665 面）｜后处理 5.5s |
| 峰值显存 | ~4.7 GB / 24 GB（GPU 利用率仅 16%，stage1 主要 CPU 专家分页，与论文设计一致） |
| 输出 | 3392 顶点 / 11043 面（含补洞 +3378），holes 18→0，归一化 [-0.5,0.5]³ |
| mesh.glb | 产物在 `~/output/taoflowforge_results/剃须刀_01000000/`（mesh.obj 675K） |
| **质量** | 主体剃须刀完整（最大连通体 4418 面，封闭实体，柄+刀头可辨）⚠️ 但**3829 个连通体**，除主体外 3828 个全是背景纸张杂物碎片（合计占面数 61.6%）→ 不抠背景直接喂原图的必然后果 |
| 结论 | **一张约 6 分钟，批量 8 物体（单视角）约 45-50 分钟**；输入必须先抠背景/裁杂物，否则网格被碎片淹没 |

## 2026-10-28 E-03 补充样例：耳机（反例）⚠️

| 指标 | 值 |
|---|---|
| 输入 | `/mnt/d/dataset/物体三图数据/耳机/01000002.jpg`（该文件夹帧号与剃须刀不同名，注意） |
| 总耗时 | 422s（stage0 33s / stage1 200s / stage2 79s，8346 顶点 → 28869 面） |
| 质量 | ❌ **失败**：11887 个连通体、无主导实体；大片平板是护肤品包装盒，耳机主体几乎丢失 |
| 根因 | ①白色耳机盒 vs 白色背景**同色弱对比**，占据场分不出主体；②主体在画面顶部且占比小；③下方大面积高对比杂物（黑盒+文字）喧宾夺主 |
| 结论 | 该数据集并非"干净白底商品图"——**主体居中 + 背景强对比是硬前提**；批量跑之前要么抠背景+主体裁切，要么换输入 |

**样例质量对比**：

| 样例 | 耗时 | 连通体 | 主体 | 结论 |
|---|---|---|---|---|
| 剃须刀 01000000 | 344s | 3829（最大占 38.4%） | 完整封闭实体 | ✅ 可用（取最大连通体即可） |
| 耳机 01000002 | 422s | 11887（碎片为主） | 淹没 | ❌ 输入不合格 |

## 2026-10-28 环境搭建阶段（先于推理）

### 已核实的环境事实
- 上游 requirements.txt 有 bug：`Pillow==12.0.0` ↔ gradio 5.50.0（要求 pillow<12.0）
  冲突，pip 新解析器直接 ResolutionImpossible。00a 运行时 sed 降级 Pillow==11.3.0。
- open3d 0.19（pip wheel）依赖系统 libgomp.so.1；libgcc-ng 15.x 不再捆绑，
  `conda install -c conda-forge libgomp` 解决（WSL 无 sudo，apt 不可用）。
- `--offload` 上游 choices 为 auto/on/off（默认 auto），README 早期写的 "stage" 有误，
  02 脚本已修正——**以 cli.py 为准**。
- ModelScope SDK 下载有总时限：26GB 权重 1 小时报 `[E1001] 下载总时限已耗尽`，
  续传时限不放大 → 大权重走 Windows 侧迅雷/curl 直下 resolve 直链更稳。
- stage0.pt 若不内嵌 dino_encoder.* 权重 → 推理必须 `--dino-checkpoint`
  （备用镜像：ModelScope `facebook/dinov3-vitl16-pretrain-lvd1689m`，非 gated）。
  下载完成后用 `04_check_weights.sh` 一键探测。
