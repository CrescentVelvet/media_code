# 四方法前馈重建横评：算法思路与实验结果

> 数据：`D:/dataset/手部微动样例/01e954de1b8a4cde9315c976f4dcb964-佳佳抱枕`（Remy 采集包，32 视角，504 px 输入）
> 硬件：RTX 3090 24 GB，WSL2。所有数字为 2026-11-06 实测，不是论文引用值。

## 0. 一句话结论

前馈直出高斯已经能 **13.5 秒** 出一份可直接渲染的 PLY；接传统 3DGS 能把观感拉到"能看"，代价是 **20 分钟以上（约 100 倍）**。
但三条路线在 32 视角 / 504 px 这个输入条件下**都没有达到汇报可用的保真度**，而且**失败模式各不相同**——
说明瓶颈不在同一个环节，换方法解决不了另一个方法的问题。

## 1. 三条技术路线（差别不在骨干，在"要不要做逐场景优化"）

| | 路线 A 前馈直出高斯 | 路线 B 前馈 + 短精调 | 路线 C 前馈几何 + 逐场景优化 |
|---|---|---|---|
| 代表 | DA3 原生高斯头、QuerySplat | InfiniSplat v2 | DA3+3DGS、VGGT-Ω+3DGS |
| 机制 | 一次前向逐像素/逐查询解码 位置·尺度·旋转·不透明度·SH，直接写 PLY | 前馈定几何 → 3000 步只调 SH/scale/opacity/quat，位置冻结 | 前馈出深度/位姿/点云 → 组装 COLMAP → 30k it 光度优化 |
| 端到端 | 13.5 s / 38.5 s | 34 s + 163 s ≈ 3.3 min | 20.4 min / 22.9 min（前馈只占 3~10%） |
| 产物 | 610 万 · 314 MB ｜ 37 万 · 33 MB | 594 万 · 386 MB | 175~189 万 · 414~448 MB |
| 主失败模式 | 视角间质量不稳 | 重影 | 漂浮物 / 转动闪烁 |

关键认识：**QuerySplat 不是独立骨干**，它是"冻结 VGGT-Ω aggregator + 自己的查询式高斯头"，
所以"VGGT-Ω 直出高斯"和 QuerySplat 是同一条路线、同一份 39 秒的结果，不应算成两个方法。

## 3. 失败现象与归因（区分已证实 / 推断）

| 方法 | 现象 | 已证实的 | 仍是推断的 |
|---|---|---|---|
| DA3 原生高斯头 | 视角 0 好，视角 8 大片拖影，视角 16 人物整体消失 | 渲染激活正确（`exp(scale)`，raw 会 OOM）；导出只保留 SH DC | 逐视角逐像素出高斯 + 位姿/深度误差在宽基线下直接摊开 |
| QuerySplat | 全图糊 | 阈值不是主因：0.05→0.005 高斯 22.2 万→37.1 万（+67%），视觉几乎无变化 | 查询预算（37 万高斯）本身表达力上限 |
| InfiniSplat v2 | 重影 + 糊 | 位置冻结下精调 +7.30 dB（20.72→28.02）→ 几何大体对、外观覆盖不足；重影 = 同一空间多份几何副本 | 副本来源（视角批次间的深度不一致） |
| VGGT-Ω + 3DGS | 大量漂浮物 | — | 深度噪声 init 经 densify 膨胀（与 da3_human 04/04b 的 −2 dB 结论同源） |
| DA3 + 3DGS | 转动时身上闪烁 | — | 同上 |

**复现正确性**：InfiniSplat 官方 DTU 示例 holdout NVS = PSNR 13.102 / SSIM 0.5852，
与 `EXPERIMENTS.md:741` 历史记录**逐位一致** → 链路本身没问题，与论文的差距来自域外数据 + 视角少。

## 4. 评测缺口（现在还不能排名）

1. 没有 **holdout NVS**（当前全是训练视角 in-sample 渲染）。
2. 没有 **Sim(3) 对齐后的 Chamfer**（GT 点云 `pcd.ply` 手边就有，未用）。
3. 没有 **同相机重渲染**（各方法各用自己的导出分辨率/视场，构图不一致，fig1 已注明）。
4. 动态/两态冲突场景未纳入（`手部微动样例` 另有 9 个场景未跑）。

这四条不补，"谁更好"就只能停在观感层面。

## 5. 关于"以 DA3-GS 为基座，换 2DGS 原语 + 加高分辨率纹理头"的评估

### 5.1 方向是对的：两个改动各自对准一个已观察到的失败

- 视角 8 / 16 拖影与消失 → 几何假设问题 → **surfel（2DGS）比椭球更贴面**，薄、便于消 floater。
- 高频细节糊、且 PLY 只带 SH DC → 外观表达容量问题 → **纹理/双头**是正解方向（几何密度与外观容量解耦）。

### 5.2 但必须讲清四个约束

1. **换头 = 必须训练，不是推理改动。** DA3 权重里的 `gs_head`（GSDPT, out=38）/`gs_adapter`（sh_degree=2）是训练过的；
   换成 2DGS 头或纹理头都是随机初始化，不微调就是噪声。这属于训练项目排期，不能按"改个脚本"估工。
2. **2DGS 头不是"少一个尺度"那么简单。** 要回归 2 个切向尺度 + 法向，光栅化走 surface 模式，
   还需法向/深度畸变一致性监督；而 2DGS 的既有优势（法向一致、可提 TSDF 网格）主要在
   **per-scene 优化 + 密集视角**下成立，32 视角前馈条件下收益未验证。且它**修不了位姿/深度误差**——
   而我们看到的拖影更像位姿一致性问题。
3. **纹理头的细节必须有来源。** 输入仍是 504 px 的话，纹理头再"高分辨率"也只是把 504 插值放大。
   真要细节，得挂**高分辨率特征支路**（pyramid / 局部 deformable 采样从原图取特征）；
   直接让骨干吃 1008 px 是 4× token、≈16× 注意力开销。折中是"低分辨率出几何 + 局部窗口采样出颜色"。
4. **许可证**：DA3 里"度量深度 + 位姿一体"的只有 NESTED-GIANT-LARGE-1.1 / GIANT-1.1，**CC BY-NC 4.0**；
   Apache 档（BASE/SMALL、DA3METRIC-LARGE）凑不齐度量+位姿。要商用或大规模训练，这个必须提前定。

### 5.3 建议的动手顺序（便宜的先做，能一票否决结构改动的先做）

| 阶段 | 动作 | 成本 | 想回答的问题 |
|---|---|---|---|
| **P0** | 输入分辨率 504→1008 重跑 DA3-GS | ~20 min | 细节是否随分辨率走？决定纹理头该做"分辨率"还是"容量" |
| **P0** | 导出改为保留 SH rest（只改导出，不改模型） | ~10 min | 视角 8/16 的劣化里，有多少是"视角相关外观被丢掉" |
| **P0** | 视角 32→64（82 帧里加密） | ~30 min | 拖影是否随覆盖密度下降？区分"几何精度"与"覆盖不足" |
| **P1** | 前馈 init + 3~5k 步 **2DGS 短精调**（不训前馈模型） | ~半天 | 能否用 2~4 分钟换掉 20 分钟——**性价比最高的那条** |
| **P2** | 冻结骨干，双头解耦：几何头（低分辨率）+ 外观头（高分辨率特征 → SH/纹理） | 训练项目 | 外观容量是否是真瓶颈 |
| **P3** | 原语消融 2DGS vs 3DGS（同一双头、同一数据） | 训练项目 | surfel 假设值不值这个改动 |

顺序与 `da3_human/EXPERIMENT_PLAN.md` 的消融优先级一致（D1 offset 界 > D4 剪枝 > D2 双头解耦 > D3 2DGS vs 3DGS > D5 pose residual）：
**2DGS 排第 4，双头排第 3**——先做便宜的，别一上来改原语。

### 5.4 如果目标只是"做出可用的高保真资产"

P1（前馈 init + 短优化）大概率比训新头更快见效：13.5 s 拿到几何初值，再用 3~5k 步把外观和细节补上，
时间上仍是"分钟级"，而且不用碰 1.4B 骨干的训练。要重新训练前馈头，得先有 P0 的结论撑着。
