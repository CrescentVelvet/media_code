# 四方法前馈重建横评：算法思路与实验结果

> 数据：`D:/dataset/手部微动样例/01e954de1b8a4cde9315c976f4dcb964-佳佳抱枕`（Remy 采集包，32 视角，504 px 输入）
> 硬件：RTX 3090 24 GB，WSL2。所有数字为 2026-11-06 实测，不是论文引用值。

## 0. 一句话结论

前馈直出高斯已经能 **13.5 秒** 出一份可直接渲染的 PLY；接传统 3DGS 能把观感拉到"能看"，代价是 **20 分钟以上（约 100 倍）**。
但三条路线在 32 视角 / 504 px 这个输入条件下**都没有达到汇报可用的保真度**，而且**失败模式各不相同**——
说明瓶颈不在同一个环节，换方法解决不了另一个方法的问题。

## 1. 三条技术路线（差别不在骨干，在"要不要做逐场景优化"）

| | 路线 A 前馈直出高斯 | 路线 B 前馈 + 短精调 | 路线 C 前馈几何 + 逐场景优化 |
|---|---|---|---|
| 代表 | DA3 原生高斯头、QuerySplat | InfiniSplat v2 | DA3+3DGS、VGGT-Ω+3DGS |
| 机制 | 一次前向逐像素/逐查询解码 位置·尺度·旋转·不透明度·SH，直接写 PLY | 前馈定几何 → 3000 步只调 SH/scale/opacity/quat，位置冻结 | 前馈出深度/位姿/点云 → 组装 COLMAP → 30k it 光度优化 |
| 端到端 | 13.5 s / 38.5 s | 34 s + 163 s ≈ 3.3 min | 20.4 min / 22.9 min（前馈只占 3~10%） |
| 产物 | 610 万 · 314 MB ｜ 37 万 · 33 MB | 594 万 · 386 MB | 175~189 万 · 414~448 MB |
| 主失败模式 | 视角间质量不稳 | 重影 | 漂浮物 / 转动闪烁 |

关键认识：**QuerySplat 不是独立骨干**，它是"冻结 VGGT-Ω aggregator + 自己的查询式高斯头"，
所以"VGGT-Ω 直出高斯"和 QuerySplat 是同一条路线、同一份 39 秒的结果，不应算成两个方法。

## 3. 失败现象与归因（区分已证实 / 推断）

| 方法 | 现象 | 已证实的 | 仍是推断的 |
|---|---|---|---|
| DA3 原生高斯头 | 视角 0 好，视角 8 大片拖影，视角 16 人物整体消失 | 渲染激活正确（`exp(scale)`，raw 会 OOM）；导出只保留 SH DC | 逐视角逐像素出高斯 + 位姿/深度误差在宽基线下直接摊开 |
| QuerySplat | 全图糊 | 阈值不是主因：0.05→0.005 高斯 22.2 万→37.1 万（+67%），视觉几乎无变化 | 查询预算（37 万高斯）本身表达力上限 |
| InfiniSplat v2 | 重影 + 糊 | 位置冻结下精调 +7.30 dB（20.72→28.02）→ 几何大体对、外观覆盖不足；重影 = 同一空间多份几何副本 | 副本来源（视角批次间的深度不一致） |

| DA3 + 3DGS | 转动时身上闪烁 | — | 同上 |

**复现正确性**：InfiniSplat 官方 DTU 示例 holdout NVS = PSNR 13.102 / SSIM 0.5852，
与 `EXPERIMENTS.md:741` 历史记录**逐位一致** → 链路本身没问题，与论文的差距来自域外数据 + 视角少。

## 4. 评测缺口（现在还不能排名）

1. 没有 **holdout NVS**（当前全是训练视角 in-sample 渲染）。
2. 没有 **Sim(3) 对齐后的 Chamfer**（GT 点云 `pcd.ply` 手边就有，未用）。
3. 没有 **同相机重渲染**（各方法各用自己的导出分辨率/视场，构图不一致，fig1 已注明）。
4. 动态/两态冲突场景未纳入（`手部微动样例` 另有 9 个场景未跑）。

这四条不补，"谁更好"就只能停在观感层面。

## 5. 关于"以 DA3-GS 为基座，换 2DGS 原语 + 加高分辨率纹理头"的评估

### 5.1 方向是对的：两个改动各自对准一个已观察到的失败

- 视角 8 / 16 拖影与消失 → 几何假设问题 → **surfel（2DGS）比椭球更贴面**，薄、便于消 floater。
- 高频细节糊、且 PLY 只带 SH DC → 外观表达容量问题 → **纹理/双头**是正解方向（几何密度与外观容量解耦）。

### 5.2 但必须讲清四个约束

1. **换头 = 必须训练，不是推理改动。** DA3 权重里的 `gs_head`（GSDPT, out=38）/`gs_adapter`（sh_degree=2）是训练过的；
   换成 2DGS 头或纹理头都是随机初始化，不微调就是噪声。这属于训练项目排期，不能按"改个脚本"估工。
2. **2DGS 头不是"少一个尺度"那么简单。** 要回归 2 个切向尺度 + 法向，光栅化走 surface 模式，
   还需法向/深度畸变一致性监督；而 2DGS 的既有优势（法向一致、可提 TSDF 网格）主要在
   **per-scene 优化 + 密集视角**下成立，32 视角前馈条件下收益未验证。且它**修不了位姿/深度误差**——
   而我们看到的拖影更像位姿一致性问题。
3. **纹理头的细节必须有来源。** 输入仍是 504 px 的话，纹理头再"高分辨率"也只是把 504 插值放大。
   真要细节，得挂**高分辨率特征支路**（pyramid / 局部 deformable 采样从原图取特征）；
   直接让骨干吃 1008 px 是 4× token、≈16× 注意力开销。折中是"低分辨率出几何 + 局部窗口采样出颜色"。
4. **许可证**：DA3 里"度量深度 + 位姿一体"的只有 NESTED-GIANT-LARGE-1.1 / GIANT-1.1，**CC BY-NC 4.0**；
   Apache 档（BASE/SMALL、DA3METRIC-LARGE）凑不齐度量+位姿。要商用或大规模训练，这个必须提前定。

### 5.3 建议的动手顺序（便宜的先做，能一票否决结构改动的先做）

### 5.3-bis P0 已跑完（2026-11-06 晚），结论与上面一致但更硬

三项干预全部判 B，量级都在 ±0.3 dB（详见 `P0_EXPERIMENTS.md`）：

| 干预 | ΔPSNR（`REF_STRATEGY=first`，相对各自 baseline） |
|---|---|
| 保留 SH rest @参考视角 | **+1.23 dB** |
| 保留 SH rest @其余 31 视角 | **−0.25 dB** |
| 输入分辨率 504→1008 | **−0.34 dB**（参考视角 −3.35 dB，锐度 −29%，前向 7 s→282 s） |
| 视角数 32→50 | **+0.09 dB** |

**结论：瓶颈是「跨视角几何/位姿一致性」，不是外观容量、不是输入分辨率、不是视角密度。**
证据是 `fig8_p0_evidence.png` 左图那条曲线：质量随"相机中心到参考视角的三维距离"单调衰减，
0 m 处 20.8 dB，> 0.5 m 掉到 10~11 dB，1.8 m 外的 8 个视角整片糊掉（锐度 < 20）。
同一份前馈输出在参考视角附近就能到 20.8 dB——**不是"不会做"，而是"跨视角不一致"**。

⇒ 计划据此调整：**P1（前馈 init + 3~5k 步短精调）升级为首要动作**（短精调正是压跨视角不一致的手段）；
纹理头/双头继续后置；2DGS 原语维持最后。

**口径提醒（写进汇报）**：DA3-GS 的观感强烈依赖参考视角位置。fig1/fig6 用的视角 0/8/16 在
`saddle_balanced` 运行里离参考视角（19）有 11~19 圈，属于该方法的**劣势视角**；
汇报时应同时给"参考视角"与"远离参考视角"两类视角。

### 5.3-quater R-2 已跑完（2026-11-07 02:35），SH rest 判 B

|---|---|---|---|---|
| DC-only 初值 | 原生 | 25.21 | 0.8594 | 822 |
| **+SH rest 初值** | 原生 | **25.44** | 0.8635 | 857 |
| DC-only 初值 | 初始 deg=2 | 25.14 | 0.8574 | 818 |
| **+SH rest 初值** | 初始 deg=2 | **25.40** | 0.8620 | 854 |

1. 两套 degree 时间表的 Δ 几乎相同 → 不是"SH 没被用够"；
2. 逐视角 Δ 从 **+0.84 到 −0.35**（std 0.35），均值被视角波动淹没，换个视角集可能就是 0；
3. 差值图（`fig14_sh_ab_renders.png` 第 4 列）显示暖色全在木柜纹理 / 书架 / 地面，
   **人物与人脸几乎全黑**；人脸区单独量：v0 **+0.00 dB**、v16 +0.09 dB。

代价是多存 757 MB（PLY 体积 3.5×）。**结论：DA3 的 SH rest 学到的是背景硬表面的
视角相关反射，不是人的细节；外观容量不是瓶颈。**

顺带发现一个更重要的口径（`P0_EXPERIMENTS.md` §R-2.5）：

### 5.3-quinquies R-3 已跑完（2026-11-07 03:23），训练分辨率判 B，但挖到"对角线规律"

3 档训练分辨率 × 3 档渲染/评测分辨率，同一 init、同一 2k 步、415 万点固定：

| 训练 \ 评测 | 378×504 | 756×1008 | 1439×1919 |
|---|---|---|---|
| **RES=4**（360×480，181 s / 7.95 GB） | **28.06** | 21.89 | 18.93 |
| **RES=2**（720×960，236 s / 9.53 GB） | 25.21 | **27.12** | 23.32 |
| **RES=1**（1439×1919，745 s / 24.04 GB） | 23.52 | 25.58 | **26.04** |

**对角线规律：PSNR 峰值全部落在"训练 ≈ 评测"的格子；错配代价 4.5~7.1 dB。**

1. **为"救脸"提分辨率：判 B。** 1439 原生口径下 RES=1 比 RES=2 高 +2.73 dB，
   但**收益几乎全在背景**（柜子、地板等大平面）：人脸区只 +0.52，view 0 单帧 **+0.04**；
   误差图（fig19）两行分布几乎相同。代价 3.16× 时间 + 显存打满 24 GB。
2. **反向结论更有用**：交付 378×504 时用 `RES=4`，比 `RES=2` **快 23%、省 17% 显存、高 2.85 dB**。
3. **机制**：决定高斯尺度的是**训练时"点数/像素"比例**（28.0 / 7.0 / 1.8），不是分辨率本身。
   RES=1 时 415 万点摊到 276 万像素，高斯被迫放大填空隙 → 覆盖全但**软**。
4. **人脸是独立瓶颈**：三种分辨率下人脸区 21.6~23.8 dB 且两组几乎相同，全图却能到 26~28。
   → 下一步不再查"采样密度"，该查点数/容量、损失加权、或人脸区域的位姿精度。

**两条口径修正**：① 锐度（Laplacian）跨分辨率不可比（ref 自身 378/756/1439 = 1421/820/417，差 3.4×）；
② PSNR 在自一致性口径下会奖励"点不足导致的平滑"——RES=1 的 26.04 是全表高分，锐度却只有 GT 的 48.5%。
所以选配置必须同时看锐度比 + 分频相关 + 误差图，不能只看 PSNR。

### 5.3-sexies R-4/R-5 全链路审计（2026-11-07）：重影不是代码 bug，也不是"31 层平均"

fig20 里三种训练分辨率的产物都还有糊与淡重影。为了排除"又是 E-01 那类口径 bug"，
从位姿到前馈到高斯头逐段做了数值审计（九个脚本，全部只读，见 `ERRATA.md` 审计基线）。

**六项不变量全部通过**：导出 PLY 与内存高斯逐位一致（5.9e-6）；训练用的 COLMAP 位姿
与 npz 完全相等（ΔR 2.4e-7 / Δt 0）；四元数 wxyz 序正确（薄盘最短轴与视线夹角中位 20.5°）；
opacity/scale 全局增益扫掠峰在 1.0~2.0（不存在 logit↔线性、σ↔3σ 这类成倍口径错）；
fx/fy（1.021）与焦距整体在 0.97~1.03 内扫掠全部平坦（不是内参 bug）；审计渲染器与交付图
逐像素一致（99.0 dB）。

**官方效果复现**（fig22，R-5）：同一份前向结果、同一个 gsplat 1.5.3、同一组相机，只改导出选项：

|  | 全点 610 万 | 裁剪 484 万 |
|---|---|---|
| 全 SH | **22.11 dB（官方等价）** | 19.77 |
| 仅 DC | 20.96 | **18.97（我们的 PLY 口径）** |

`18.97` 与我们历史上报的「DA3 直出」逐位相同 —— 渲染链路一直是对的，**错的是把"PLY
交付口径"当成了"官方口径"**。缺口 3.14 dB = 全 SH（+1.15）+ 不裁剪（+2.34，DC 下 +1.99），
**点集裁剪的代价约是 SH 的两倍**。评测参考图口径已排除（模型内部输入 vs cv2.INTER_AREA
= 54~55 dB）。

> **已归位（I-01/I-02，2026-11-08）**：上面四档已全部落成 PLY 并逐档验证，PLY 侧渲染与内存侧
> 差 ≤0.005 dB（`audit_13`，fig23）。所以 22.11 不只是"内存里能拿到"——**导出成 PLY 之后仍然
> 是 22.11**，可以作为训练与分发的正式基线。分项还发现：**全 SH 买清晰度（人脸锐度 +182），
> 不裁剪买准确度（人脸 PSNR +2.96）**，归位前"既糊又重影"是两个缺失各占一半。

**那重影从哪来**（fig21）：把高斯按"来源视角"切开，在同一像素集上比：

| 组 | 含义 | PSNR |
|---|---|---|
| 全部高斯 | 成品 | 23.87 |
| 仅本视角 | 该视角自己的壳（α 未叠满，画面暗） | 14.44 |
| 仅本视角 ÷ α | 去掉透明度后的单视角 | 19.69 |
| 去掉本视角 | 其余 31 个视角 | 23.34 |

三条读法（**已订正 R-4 的两处过度解读**）：
1. **单层 α 只有 0.036、每视角只有 0.79 个高斯/像素（自带 20.6% 空洞）** → 单看一层必然是
   "稀疏 + 半透明的点画"。成品是 32 视角叠到 α≈1.000 才成形的。
2. **`÷α` 那个 19.69 dB 不能当几何误差读**：α=0.036 时 unpremultiply 把噪声放大约 14 倍。
   直接量到的几何残差是 **~1 px 横向 + 26~42 mm 沿视线**（`audit_8` 的 G0/G1）。
3. **"成品 ≈ 去掉本视角"不能推出"31 层平均抹平细节"**：去掉 1/32 的贡献只动 0.5 dB，
   属 alpha 混合的正常稀释。

**σ 是分辨率的硬上限**：init 的 σ 折算到像素是 `[0, 0.48, 1.28]` px @378；同一批高斯渲染
1439 时变成 `[0, 1.84, 4.86]` px。所以 `RES=1 @1439` 的 26.04 dB 本质是"用 4.9 px 的笔刷
重画 1439 的图"。训练能改，但 2k 步只把 σ 缩了 11%、把 α 提到 0.073 —— 照片损失在
"薄盘 + 多视角叠加"下对 σ 的梯度压力很弱。

**对已有结论的影响**：R-3 的"对角线规律"与"RES=4 交付 378 最优"不受污染——三档在 378
口径下的 σ 同样是 ~1 px，比的是容量而不是口径。RES=1 之所以"重影最少但最糊"，依据应改成
σ 的像素当量（4.9 px 笔刷把重影糊掉了），而不是 R-4 那条推理。**在这个密度下，锐度与
重影可见度是一体两面。**

### 5.4 如果目标只是"做出可用的高保真资产"

P1（前馈 init + 短优化）大概率比训新头更快见效：13.5 s 拿到几何初值，再用 3~5k 步把外观和细节补上，
时间上仍是"分钟级"，而且不用碰 1.4B 骨干的训练。要重新训练前馈头，得先有 P0 的结论撑着。
