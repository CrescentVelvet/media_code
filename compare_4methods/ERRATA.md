## E-01 · DA3 高斯与相机位姿差 1.81 倍尺度（2026-11-06 发现 / 修复）

### 症状

`ppt_assets/fig10_p1_renders.png` 第 2 列「DA3 直出」：视角 0 尚可（略偏白偏软），
视角 16 **整幅融化、人物完全消失**。第一反应怀疑位姿有偏差，**不是**。

### 根因

`Depth-Anything-3/src/depth_anything_3/model/da3.py:400-415` `_apply_depth_alignment()`：

```python
scale_factor = least_squares_scale_scalar(valid_metric_depth, valid_depth)
output.depth      *= scale_factor
output.extrinsics[:, :, :3, 3] *= scale_factor
output.is_metric = 1
output.scale_factor = scale_factor.item()
# ← gaussians.means / gaussians.scales 没有乘
```

即：**depth 与相机被拉到米制，高斯留在对齐前的坐标系**。我们的 `97/98` 把
"官方导出的 PLY（raw 尺度）"与"`cameras.npz`（米制）"混用，于是点云整体只有真实
尺寸的 **1/1.81 ≈ 0.55**。

DA3 自己是知道的——`utils/export/gs.py:91-93` 渲视频时反过来把相机缩回去：

```python
if prediction.is_metric and scale_factor is not None:
    tgt_extrs[:, :, :3, 3] /= scale_factor
```

### 为什么"只有参考视角看着正常"

参考相机在世界原点，缩放是**以原点为中心的径向缩放**。对针孔相机 `u = fx·x/z`，
点沿自身视线滑动不改变投影 → 帧 0 画面几乎不变。其余视角看到的是横向位移，
量级 ≈ `(1−1/1.81)·d ≈ 0.45·d`：2 m 处约 0.9 m，接近半个画面。

### 证据（`99_diag_gs_ply_perview.py` / `99b_diag_umeyama.py`）

| 视角 | 到帧 0 距离 | 高斯回投自身相机误差 | ‖means − 深度抬起点‖ |
|---|---|---|---|
| 0 | 0.00 m | **1.19 px** | 0.85 m |
| 1 | 0.18 | 37 px | 0.83 |
| 4 | 0.81 | 151 px | 0.88 |
| 16 | 1.38 | 200 px | 0.98 |
| 8 | 1.78 | 193 px | 0.91 |

- 纯缩放拟合（只允许 s，不允许 R/t）：**s = 0.552 → 隐含 scale_factor 1.81**，
  逐视角 0.50~0.52 高度一致；
- 3D 距离 **恒定 ~0.9 m**、而像素误差 1→200 px 跨越两个量级 —— 只有"以帧 0 为原点的
  径向缩放"能同时解释这两个数。

### 影响范围（哪些结论要改）

| 对象 | 影响 |
|---|---|
| P0 三项（分辨率 / SH / 视角数） | **全部在错误口径下测**，需重测 |
| P0 结论「质量随到参考视角距离单调衰减，瓶颈是跨视角几何不一致」 | **降级为待重测**：该曲线很可能主要是口径错位，不是模型能力 |
| P1 前馈 init 两组（20.14 / 21.72 dB） | 是在错位 0.9 m 的条件下硬撑出来的，需重测 |
| P1 结论「多壳拓扑是重影主因」 | **降级**：主因是口径，多壳（厘米级）是残余 |
| fig6（DA3 原生高斯头）、fig10 第 2 列 | **图不可用**，必须重出 |
| P1 的「COLMAP init」两组（22.23 / 24.33 dB） | **不受影响**：点云由 depth 反投影而来，与位姿同源同尺度 |

### 修复

- 新增 `da3_frame.py`：`gaussians_to_metric(pred)` —— 导出前把 `means/scales` 乘 `scale_factor`；
- `98_da3_ff_init.py` / `97_da3_gs_export_full_sh.py`：导出前调用，并把
  `scale_factor` / `gs_scale_applied` 写进 `cameras.npz` 与 summary；
- `98b_ply_to_3dgs_ckpt.py`：读 npz 断言 `gs_scale_applied == 1`，否则直接退出
  （宁可报错，不要静默生成错尺度的 ckpt）；
- `94_render_da3_gs.py`：无需改（PLY 为米制后与 npz 自洽）。

### 重测计划

1. 修复后「DA3 直出」32 视角重渲 + PSNR（本次先做，用于出对比图）；
2. P0 三项按新口径重测（**旧数字全部作废**）；
3. P1 前馈 init 两组按新口径重跑（预期重影大幅减轻）。

### 验证结果（2026-11-06 23:5x，已闭环）

修复方式：`98` 导出前对 `means/scales` 乘 `scale_factor`，DA3 自报 **1.9988**（≈2.0，干净的两倍，
与 99b 拟合的 1/0.5516=1.813 同向，差值是拟合吸收了真实不一致）。输出到
`~/output/da3_gs_results/佳佳抱枕_p1m/`；旧目录 `佳佳抱枕_p1` 保留作对照。

**同一 PLY、同一相机、只差"是否乘 2.0"**，32 视角自一致性：

| | 修复前 | 修复后 | Δ |
|---|---|---|---|
| PSNR 均值 | **11.38** | **18.97** | **+7.59 dB** |
| SSIM | 0.2682 | 0.5767 | +0.309 |
| 锐度 | 149.4 | 222.5 | +73 |
| 近（≤1 m，11 视角） | 13.55 | 19.90 | +6.35 |
| 远（>1 m，21 视角） | 10.24 | 18.48 | +8.24 |
| 近远差距 | 3.31 dB | **1.42 dB** | 衰减只剩 43% |
| corr(距离, PSNR) | −0.803 | −0.624 | 仍为负，但弱得多 |

**最强的验证是参考视角**：按机理预测"帧 0 不该变"，实测 **20.80 → 20.87（+0.07 dB）**；
而其余 31 个视角全部 +4.83~9.62 dB。预测与实测在同一点上对齐，说明归因不是巧合。

由此对 P0 结论做定量修正：

- 「质量随到参考视角距离衰减」**仍然存在，但被放大了约 2.3 倍**（3.31 → 1.42 dB）；
- 所以它不是"模型能力只有 11 dB"，而是"我们的导出把它压低了 7.6 dB"；
- 残余的 1.42 dB 与 `99b` 拟合后的 94 mm 中位残差一致 → **真实的跨视角不一致是厘米级**，
  不是米级。P0 的方向判断（加分辨率/SH/视角数无效）需要在**新口径**下重测后才能确认。

⚠️ **但 P1 的 COLMAP init 两组（22.23 / 24.33 dB）也要重新审视**：它们的点云由 depth
反投影而来（米制，本身自洽），所以**不受 E-01 影响**；然而它们与"前馈 init"组的对比
原本隐含"前馈初值把质量拉低"的结论，现在这个对比要改成"前馈直出 18.97 → 前馈 init 5k
20.14"，差距只剩 1.2 dB，**前馈初值的价值被高估/低估的判断全部作废，需重跑**。

### 重测结果（2026-11-07 00:54，P1 三组已闭环）

按 `P1_EXPERIMENTS.md` §5 预注册的判据重跑（同场景、同超参、同 32 视角，唯一差别是初值 PLY
是否乘 1.9988）：

| 组 | 旧 PSNR | **新 PSNR** | Δ | 新 SSIM | 新锐度 | 训练 |
|---|---|---|---|---|---|---|
| 前馈 415 万 + 2k | 19.67 | **25.21** | **+5.54** | 0.859 | 822 | 236 s |
| 前馈 415 万 + 5k | 20.14 | **25.51** | **+5.37** | 0.856 | 901 | 519 s |
| 前馈 57 万 + 5k | 21.72 | **25.17** | **+3.45** | 0.858 | 845 | 205 s |

**三条预注册判据全部命中「推翻」分支**：

1. A1（25.51）比稀疏点云 + 5k（22.23）高 **3.28 dB** → 旧结论「加速来自少跑步数而非前馈初值」
   **不成立**；正确说法是"前馈初值 + 少跑步数"。
2. A1（25.51）> A2（25.17）→「点数越多越差」**不成立**，稠密略优。
3. A1−A2 从 1.58 dB 缩到 0.34 dB →「opacity 分布不匹配导致叠糊」**降级为主因之一而非主因**。

**视觉侧的第二个独立验证**（`fig12_e01_retest_renders.png`）：旧口径的
「前馈 + 5k」在视角 0 人物外面套一层半透明壳、视角 16 人物错位；
米制版重影完全消失。**"重影 = 0.9 m 错位下优化器长出第二套壳"这一归因成立。**

**corr(到参考视角距离, PSNR) 也翻正为 0**（旧 +0.50 → 新 +0.07）：
训练之后，"离参考视角多远"不再是质量因子。P0 的 −0.62（未训练直出）仍存在，但很弱。

**代价**：A1 的 519 s 有 4.2 倍于 A2 的 205 s，换来 +0.34 dB；
甜点因此落在 **415 万 + 2k 步 = 236 s / 25.21 dB**（端到端 4.5 min）。

⚠️ **仍未闭环的部分**：P0 三项里 **SH rest 已于 2026-11-07 02:35 按米制口径重测闭环**，
判定 **B（无效）**：Δ = +0.23 dB（初始 degree=2 时 +0.26，两套时间表几乎相同），
且差值图显示差异全在背景木纹/书架，人脸区 ±0.00~0.09 dB —— 详见
`P0_EXPERIMENTS.md` §R-2。分辨率与视角数两项仍未重测，优先级已被下调
（见 `P1_EXPERIMENTS.md` §5.4）；但重测中顺带发现**训练分辨率 `RES=2`（720×960）
与评测归一化 378×504** 这个一直存在的口径，人脸在评测分辨率下仅 ~40 px，
它比"外观容量"更能解释"背景清楚、人脸糊"——见 §R-2.5。

### A. 尺度 / 坐标系口径（E-01 的直接教训）

- [ ] **A1 每个几何量标注单位域**：变量名或注释里写明 `raw` / `metric` / `normalized`；

- [ ] **A2「点云 + 相机」组合先跑自投影**：判据 = 参考视角中位 reproj **< 5 px**、

      工具：`99_diag_gs_ply_perview.py`。
- [ ] **A3 导出端写、读取端断言**：写方落 `gs_scale_applied`，读方不匹配直接 `SystemExit`。
      **不做静默兼容**——静默兼容正是这次 bug 能活过整轮 P0/P1 的原因。
- [ ] **A4 跨运行对比钉死所有隐式选择**：`ref_view_strategy`、输入顺序、分辨率、

- [ ] **A5 优先「一次前向多出口」**：同一实验的对照组与实验组共享同一次推理的相机与
      世界系（98 新增 `SAVE_FULL_SH` 即此用法），不要靠"两次运行应该一样"去赌。

### B. 训练"跑完了但没学"（本次最贵的弯路）

- [ ] **B1 新增 init 通路必须验字节级变化**：同配置跑 0 步 vs N 步，
      `md5sum point_cloud/iteration_*/point_cloud.ply` 不能相同。不同即通过。
- [ ] **B2 参数一律 `nn.Parameter`**：`torch.from_numpy()` 默认 `requires_grad=False`，
      而 3DGS 的 `restore()` 是直接赋值、不重新包装 → autograd 不追踪、梯度恒 `None`。
- [ ] **B3 验梯度必须走真实 `backward()`**：禁止手动塞 `.grad` 再 `step`
      （我这次正是靠这个假验证得出"绑定正常"，把 bug 多拖了一整轮）。
      正确做法：`loss.backward()` 之后逐个 `print(name, p.grad is None)`。
- [ ] **B4 optimizer state_dict 会覆盖 lr**：`load_state_dict` 用 saved_groups
      **完全重建** param_groups → 必须填真实 lr 并补 `"name"` 键，
      否则除 xyz 外全部不更新。

- [ ] **C1 数字超出预测 > 2 dB 时先看图再上报**：这次的 25.21 比预注册预测高 3.7 dB，

- [ ] **C5 锐度（Laplacian 方差）不可跨分辨率比**：ref 自身在 378/756/1439 下是

## E-02 · 高斯 scale 的数字口径不一致（2026-11-06 订正）

P1 台账里写的「DA3 的 scale 中位数 0.8 mm」是**早期一次性统计**，与最终 PLY 不符。
按 `gs_ply/0000.ply` 实测（4,838,397 点）：

| 轴 | p1 | 中位 | p99 |
|---|---|---|---|
| 0 | 3.2e-9 m | **8.5e-9 m** | 5.0e-3 |
| 1 | 8.2e-5 m | **1.46e-3 m** | 4.7e-2 |
| 2 | 1.0e-4 m | **3.72e-3 m** | 3.3e-2 |

即高斯不是"小椭球"，而是**近乎零厚度的薄盘**（1.5 mm × 3.7 mm × ~1e-8 m），
在自身视角折合 0.3 / 0.8 像素。结论方向不变（远小于像素 → alpha 欠饱和 → 偏白），
但"小椭球"这个描述要换成"薄盘"，且它同时解释了**掠射视角下薄盘退化成线、alpha 归零**
（远端视角"看不到人"的第二重原因）。

opacity 中位 0.036（25% 分位 0.013、90% 分位 0.107）这条是准确的，保留。

**2026-11-07 补充**：上表是 raw 尺度（未乘 1.9988）的 PLY。米制 PLY `佳佳抱枕_p1m/gs_ply/0000.ply`
实测为 **1.7e-8 × 2.9e-3 × 7.4e-3 m**（正好 2 倍），opacity 分布完全不变（中位仍 0.0356）。
"薄盘"的判定与像素足迹（自身视角 0.3 / 0.8 px）**不因折算而改变**——因为相机同步放大 2 倍，
屏幕足迹是尺度不变的。P0/P1 里"薄盘导致 alpha 欠饱和 → 偏白"这条继续成立。
