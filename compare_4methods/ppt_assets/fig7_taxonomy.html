前馈重建的三条技术路线：多快、多好、差在哪

同一数据（佳佳抱枕 · 32 视角 · RTX 3090）同一批帧，端到端实测。 核心差别不在骨干网络，而在「要不要做逐场景优化」。
路线 A
前馈直出高斯
Feed-forward Gaussian Head
DA3 原生高斯头QuerySplat
机制
一次前向，逐像素或逐查询解码 位置 / 尺度 / 旋转 / 不透明度 / SH，直接写出 PLY
耗时
13.5 s（DA3）　38.5 s（QuerySplat）
产物
610 万高斯 · 314 MB　｜　37 万 · 33 MB
实测问题
视角之间质量不稳（视角 8 拖影、视角 16 人物消失）；细节被 504 px 输入与查询预算卡住
速度唯一达标，保真度不达标
路线 B
前馈 + 短精调
Feed-forward then short refine
InfiniSplat v2
机制
前馈定几何 → 3000 步只调 SH / scale / opacity / quat，位置完全冻结
耗时
34 s + 163 s ≈ 3.3 min
产物
594 万高斯 · 386 MB
实测问题
重影：同一空间出现多份几何副本。精调 +7.30 dB 说明几何大体对、外观覆盖不足
性价比最好，但几何错误优化不了
路线 C
前馈几何 + 逐场景优化
Two-stage: predict then optimize
DA3 + 3DGSVGGT-Ω + 3DGS
机制
前馈出深度 / 位姿 / 点云 → 组装 COLMAP 场景 → 30k it 光度优化
耗时
20.4 min　22.9 min（前馈只占 3~10%）
产物
175~189 万高斯 · 414~448 MB
实测问题
漂浮物、转动闪烁；20 分钟的优化把前馈的秒级优势完全抵消
质量最稳，代价 100 倍
1
速度已经分出胜负。 纯前馈 13.5 秒就能出可渲染的 PLY；接上 3DGS 变成 20 分钟以上， 多出来的时间换来的是"能看"，不是"好用"。
2
质量谁都没赢，但失败模式不一样。 视角不稳 / 重影 / 漂浮物分别指向 位姿一致性、几何副本、深度噪声—— 换一个方法解决不了另一个方法的问题。
3
现在还排不了名。 只有定性和耗时，缺同口径 NVS holdout 与 Sim(3) Chamfer。 这个洞不补，启动大规模训练就没有衡量标尺。
下一步（低成本验证先做） ① 输入分辨率 504 → 1008，看细节是否随分辨率走；② 各方法用同一 COLMAP 相机重渲染， 消掉构图差异；③ 前馈 init + 3~5k 步短优化，验证能否用 2~4 分钟换掉 20 分钟； ④ 再谈改结构（换 2DGS 原语 / 加高分辨率外观头）——那是训练项目，不是推理改动。
