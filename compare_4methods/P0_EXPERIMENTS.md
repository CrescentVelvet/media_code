## P0-2 · 保留 SH rest（同一次前向，只改导出）

**背景**：官方 `export_to_gs_ply`（`depth_anything_3/utils/export/gs.py:52`）写死 `save_sh_dc_only=True`，
而权重里 `gs_adapter.sh_degree = 2`，即有 8 个高阶 SH 系数从没被导出过。
我们此前所有"DA3-GS 视角不稳"的结论，都建立在丢掉了视角相关外观的 PLY 上。

**做法**：新增 `97_da3_gs_export_full_sh.py`——不改 DA3 仓、不改权重，
复用官方 `save_gaussian_ply`，其余参数（prune 0.9 / 边框剪枝 / opacity 反 sigmoid / gs_views_interval=1）
逐项对齐官方，保证唯一变量就是 SH rest；同时导出 dc 与 full 两份做 A/B。

**预测（跑之前）**：视角 0 几乎不变；视角 8/16 可能略有改善，但**不期待翻盘**——
理由是那两处是整片拖影/人物消失，不像"少了两阶视角相关颜色"能解释的。

### 实测

**命令**（da3_human env，`97_da3_gs_export_full_sh.py`，同一次前向导出两份）：

| 项 | 数值 |
|---|---|
| 权重 | `/mnt/d/wheel/da3_human_ms`（sh_degree=2 → d_sh=9，即 8 个高阶 SH 从未被导出） |
| 前向 | 6.9 s（加载 19.1 s 不计） |
| 高斯（预测） | 6,096,384 |
| 高斯（PLY 实存，导出剪枝后） | **4,838,527**（prune_by_depth_percent=0.9 + 边框剪枝） |
| DC-only PLY | 313.8 MB，写盘 9.0 s |
| full-SH PLY | **756.8 MB**，写盘 19.4 s |
| 对照组自检 | 我们重导的 DC-only 与旧基线渲染**逐像素 MAE=0.000**（PSNR 77/99/99 dB）→ 导出链完全可复现 |

**逐视角指标**（32 视角全渲染，PSNR/SSIM 对齐各自输入帧；`per_view_metrics.json`）：

| 分区 | DC-only | full-SH | 结论 |
|---|---|---|---|
| 全 32 视角均值 | PSNR 10.60 / SSIM 0.2454 / sharp 119.6 | PSNR 10.41 / SSIM 0.2389 / sharp 191.4 | 整体略降，锐度 +60% |
| **参考视角 19**（DA3 把 ref 相机放在原点，`c19≈(0,0,0)`） | **19.61 / 0.649 / 296** | **20.32 / 0.684 / 530** | **+0.71 dB，唯一变好的视角** |
| 次好视角 3 / 18 / 20 / 21 | 13.16 / 12.00 / 12.88 / 12.45 | 12.60 / 11.47 / 12.40 / 11.95 | 全部 −0.5 dB 左右 |
| 塌掉的视角（sharp<20） | 9/10/11/12/13/24/25/26/27/28 | 同 | 渲染几乎是纯色糊，full-SH 也救不回 |

**读法**：`full-SH` 只在**几何正确**的参考视角兑现收益（+0.71 dB、SSIM +0.035、锐度 +79%），
一旦几何错了（sharp 1.7~16 的那些视角），高阶 SH 反而引入不受约束的视角相关颜色，PSNR 掉 0.2~0.6 dB。

### 对计划的影响（对应判据"若 B 则"）

- **判定为 B（部分）**：外观容量**确实有天花板效应**，但它不是当前主要瓶颈。
  证据：几何塌掉的视角，加上 8 个高阶 SH 系数后锐度仍是 1.7~16（纯糊）——
  **加外观容量无法修复几何错误**。
- 因此：
  1. **纹理头/双头的优先级下调**（原 P2 → 仍然后置），因为它的收益只在"几何已经对"的视角兑现。
  2. **投资方向改为几何**：短精调（P1）、位姿/深度精化（D5）的优先级上调。
  3. 附带一个有价值的副作用：**官方导出的 PLY 只有 484 万高斯（不是 610 万）**，
     之前 fig3/PPT 里写的 "4.8~6.1M" 是对的区间，但报告里应当用 **484 万（PLY 实存）** 更准确——已改。
- **另一个必须记录的发现**：DA3 把参考视角相机放在原点（本场景 = 视角 19），
  质量随"离参考视角的圈数"衰减：参考视角 19.6~20.3 dB，隔 1~2 圈降到 12~13 dB，隔 8 圈以上塌到 8~9 dB 且近乎空白。
  **"视角 0 好 / 8 拖影 / 16 人物消失"的真实机理是"离参考视角越远越烂"，不是随机的视角不稳。**
  这条对 P0-3 的判据要顺势调整（见下）。

> **补跑（同日，为与 P0-1/P0-3 对齐）**：上面是 `saddle_balanced`（参考视角 19）的结果。
> 加上 `REF_STRATEGY=first`（参考视角 0）重跑一遍，结论一致但更干净：
> **参考视角 +1.23 dB、其余 31 视角 −0.25 dB**。下文 §4 统一用 ref=first 这套数字。
> 这也顺带说明"参考视角给多少分"本身受哪一帧被选为参考视角影响（+0.71 vs +1.23），
> 跨运行比较必须钉死 `REF_STRATEGY`。

## P0-1 · 输入分辨率 504 → 1008

**预测（跑之前）**：锐度上升明显，视角 0 的细节（面部/手）变清楚；
但视角 8/16 的拖影**不改善，甚至更差**（宽基线下位姿/深度误差随分辨率一起放大）。

### 实测

**第一次做错了，记下来**：直接 `PROCESS_RES=1008` 重跑，渲染沿用 504 那次的 `results.npz` 相机，
结果画面整体旋转错位、大片纯黑。原因：**DA3 的世界坐标系由参考视角定义**，
`saddle_balanced` 在 504 时选出参考视角 19、在 1008 时选出 31 → 两次运行的相机外参不在同一个世界系里。
→ 已固化为工程约束：`97_da3_gs_export_full_sh.py` 现在**每次运行都自己落一份 `cameras.npz`**，
并加 `REF_STRATEGY` 开关；做跨运行 A/B 必须钉死同一参考视角。

**正式对比（两组都 `REF_STRATEGY=first`，参考视角 = 0，32 视角）**：

| 指标（渲染统一降采样到 378×504 再算，保证可比） | 504 | 1008 | 变化 |
|---|---|---|---|
| 前向耗时 | 7.3 s | **281.7 s** | 38× |
| 高斯数（预测） | 6.10 M | 24.39 M | 4× |
| PLY（DC-only） | 313.8 MB | **1252.5 MB** | 4× |
| 均值 PSNR / SSIM | 11.38 / 0.2682 | 11.04 / 0.2574 | **−0.34 dB / −0.011** |
| **参考视角 0** | **20.80 / 0.6493 / sharp 290** | **17.45 / 0.3790 / sharp 233** | **−3.35 dB，SSIM 近乎减半** |
| 均值锐度（sharp@504） | 149.4 | 106.3 | **−29%** |
| 塌掉的视角（sharp<20） | 8 / 32 | 7 / 32 | 无改善 |

**另外两个工程结论**：
- 1008 下 **full-SH 导出会 OOM**（24.4 M 高斯 × 41 float，`plyfile` 的 `list(map(tuple, ...))`
  要 ~10 GB 内存，整机被杀）。以后千万级高斯只导 DC-only。
- 1008 下渲染 24.4 M 高斯可用（gsplat），显存够；慢但不至于崩。

### 对计划的影响（对应判据"若 B 则"）

- **判定为 B**：把输入分辨率翻倍**不产生更多细节**——参考视角 PSNR 反而掉 3.35 dB、SSIM 减半、锐度 −29%，
  只有"更多、更小、更互相摊平"的高斯。原因也清楚：**DA3 是按 504 训练的**，
  直接喂 1008 属于分布外推；高斯数 ×4 后更容易互相抵消（与 `som_human` E-01/E-07 的"更多高斯更易摊平"同源）。
- 因此：
  1. **"纹理头只做分辨率提升"这条捷径被否掉**——不重训/不微调，提输入分辨率是负收益。
  2. **高分辨率必须随训练一起做**（高分辨率特征支路 + 在该分辨率上训练），回到"训练项目"的定性，
     与 FINDINGS §5.2 第 3 条一致；但这已经是 P2 的事。
  3. 纯前馈路线的算力账更难看：1008 要 282 s（比 3DGS 训练只快 4 倍），"13.5 秒"的优势只在 504 成立。

## P0-3 · 输入视角 32 → 50

**预测（跑之前）**：拖影与"人物消失"都明显缓解——因为 32 视角时相邻相机基线约 0.27 m（轨迹半径 1.17 m），
遮挡关系变化大；加密一倍后覆盖更连续。

### 实测

**计划被迫改口径**：`infinisplat_v2/07_capture_to_npz.py` 硬限制 `n_views ∈ [2, 50]`（82 帧里最多取 50 帧），
所以只能做 **32 → 50（1.56×）**，不是原计划的 2×。已记录为工具约束。

**做法**：两组都 `REF_STRATEGY=first`（参考视角 = 帧 0），只比**共同物理帧**（20 帧，按采集包原始帧号匹配），
确保同相机。

| 指标（共同 20 物理帧） | 32 视角 | 50 视角 | 变化 |
|---|---|---|---|
| 前向耗时 | 7.3 s | 12.1 s | 1.7× |
| 高斯数 / PLY | 6.10 M / 313.8 MB | 9.53 M / 490.4 MB | 1.56× |
| 均值 PSNR / SSIM | 11.67 / 0.2757 | 11.76 / 0.2780 | **+0.09 dB / +0.002** |
| 均值锐度 | 155.3 | 171.1 | +10% |
| 塌掉视角（sharp<20） | 5 / 20 | 4 / 20 | −1 |
| 参考视角 PSNR | 20.80 | 20.94 | +0.14 |

### 对计划的影响（对应判据"若 B 则"）

- **判定为 B**：视角加密 1.56× 几乎无收益（+0.09 dB），"人物消失/拖影"没有缓解。
  **覆盖不足不是主因**，再往采集侧堆帧数也解决不了。
- 保留一点不确定性：2×（64 视角）未测（工具上限 50），但 1.56× 只换来 0.09 dB，
  斜率太小，2× 也不太可能翻盘。

## 4. 结论与计划调整

**三项干预的 ΔPSNR（全部 `REF_STRATEGY=first`，相对各自 baseline）**

| 干预 | ΔPSNR | 判据 | 结论 |
|---|---|---|---|
| 保留 SH rest @参考视角 | **+1.23 dB** | — | 外观容量只在几何正确处兑现 |
| 保留 SH rest @其余 31 视角 | **−0.25 dB** | B | 外观容量不是主因 |
| 输入分辨率 504 → 1008 | **−0.34 dB**（参考视角 −3.35 dB，锐度 −29%） | B | 分辨率不是瓶颈，且不重训就是负收益 |
| 视角数 32 → 50 | **+0.09 dB** | B | 覆盖不足不是主因 |

**统一结论：当前瓶颈是「几何/位姿一致性」，不是外观容量、不是输入分辨率、不是视角密度。**
证据是同一条曲线（`fig8_p0_evidence.png` 左）：质量随"离参考视角的三维距离"单调衰减，
0 m 处 20.8 dB，> 0.5 m 就掉到 10~11 dB，1.8 m 以外 8 个视角整片糊掉（锐度 < 20）。
也就是说——**同一份前馈输出，在参考视角附近就已经能达到 20.8 dB；它不是"不会做"，而是"跨视角不一致"**。
凡是"加容量"的手段（更多 SH 阶数、更多高斯、更多视角）都改变不了这个跨视角不一致。

**因此计划调整如下**

1. **纹理头 / 双头解耦（原 P2）继续后置**。它只在几何已经对的视角有收益（+1.23 dB），
   在错误视角是负收益。要它有意义，前提是先有跨视角一致的几何。
2. **P1 升级为首要动作**：前馈 init + 3~5k 步 **2DGS/3DGS 短精调**。
   理由是短精调正好是"用光度一致性把跨视角不一致压下去"的手段——而跨视角不一致已被确认为主因。
   同时 20.8 dB 的参考视角水平说明初始几何质量够用，精调起点不差。
3. **位姿/深度精化（D5）从"可选项"提到日程**：如果短精调后仍看到"离参考视角远就烂"，
   说明残差来自位姿本身，那就要动位姿（bundle-adjust 式精化），而不是继续加外观容量。
4. **"改 2DGS 原语"（原 P3）维持最后**：它同样不改位姿误差，收益上限受同一条曲线约束。
5. **一个必须写进报告的口径修正**：DA3-GS 的质量主要由参考视角位置决定（`saddle_balanced` 会自动选参考视角）。
   之前 fig1/fig6 展示的视角 0/8/16 在 saddle 运行里离参考视角（19）有 11~19 圈，
   恰好是该方法的**劣势视角**。给领导汇报时应同时给出"参考视角"和"远离参考视角"两类视角，
   否则容易高估或低估这个方法。→ 已加入 FINDINGS.md 的口径说明。

## R. 米制口径重测（2026-11-07）· R-2 保留 SH rest

> 上表三项全部是在 **E-01 的错尺度**下测的（点云 0.55×，与相机错位 0.9 m），结论作废。
> 本节只重测 R-2（SH rest）——分辨率和视角数两项的优先级已被 P1 下调
> （32 视角已拟合到参考锐度的 90%，再加分辨率/视角数边际收益很低），暂不占用机时。

### R-2.0 设计（必须与 P1 甜点严格同超参，唯一变量是初值 PLY 内容）

| 组 | init PLY | f_rest | 训练 | 说明 |
|---|---|---|---|---|
| **S0**（对照） | `gs_ply/0000.ply` | 全 0（官方 DC-only） | 2k / densify 关 | 应复现 P1 的 A0 = 25.21 dB |
| **S1**（实验） | `gs_ply_full/0000.ply` | DA3 sh_degree=2 的 8×3 系数 | 同上 | 唯一差别 |

两个关键约束（对应 `ERRATA.md` 防再犯清单）：

- **A5**：两份 PLY 由**同一次前向**导出（`98` 新增 `SAVE_FULL_SH=1`），相机/世界系完全共享；
- **A2**：两份必须剪出**同一批点**，`98` 内有硬闸门（顶点数不等直接退出）——
  否则"SH 的收益"里混进了"点集不同"这个变量。

⚠️ **一个必须说明的设计边界**：3DGS 的 `active_sh_degree` 从 0 起、每 1000 步升一阶，
所以 2k 步里**只有后 1000 步真正用上 SH rest**。若 S1 判"无效"，不能立刻断言
"SH 无用"，需先用 5k 步（degree 升到 3）或直接把初始 degree 设到 2 复测一次。

### R-2.1 预注册判据（写在结果之前）

| 判据 | 条件 | 处置 |
|---|---|---|
| **A 有效** | `S1 − S0 ≥ +1.0 dB` | SH rest 应设为默认导出项；P2（双头解耦）优先级**上调** |
| **B 无效** | `S1 − S0 < +0.5 dB` | 外观容量在几何对齐后仍不兑现，P2 继续后置 |
| 灰区 | `+0.5 ~ +1.0 dB` | 看锐度 + 人脸局部放大，再决定是否值得多花 1 GB 体积 |

辅证指标（只做解释、不参与判决）：SSIM、Laplacian 锐度、近/远视角分组 PSNR、人脸局部。

### R-2.2 我的预测（用于事后校准判断力，必须写下来）

- **S0 应复现 25.21 ± 0.3 dB**（同场景同超参）；若偏离 > 0.5 dB，说明本次前向本身不稳定，先查再谈结论。
- **Δ = S1 − S0 预测 +0.2 ~ +0.7 dB**，倾向判 **B（无效/弱收益）**。
  三条理由：① 2k 步里 SH 只生效后一半；② 3DGS 自己会把 f_rest 从 0 学起来
  （lr 1.25e-4），2k 步足够学到"大致不差"的视角相关项；③ DA3 的 SH rest 是从
  32 个视角学出来的，与 3DGS 在同样 32 个视角上优化的目标函数高度重叠，不构成新的信息源。
- 若实测 Δ ≥ +1.0 dB，我要回头修正对"前馈外观分量信息量"的判断——
  上次 E-01 我的三条预测全部低估了 2.2~3.7 dB，说明我对"初值的信息量"系统性偏保守。

四点证据（`fig14` / `fig15`）：

1. **排除"SH 没被用够"**：两种 degree 时间表的 Δ 几乎相同（+0.23 vs +0.26）。

2. **均值被视角波动淹没**：逐视角 Δ 从 **+0.84 到 −0.35**，std **0.35**，
   而均值只有 +0.23。也就是说"平均涨 0.23 dB"这个说法本身不稳定 —— 换个视角集就可能是 0。
3. **差值图（fig14 第 4 列）回答了"改了什么"**：暖色集中在**木柜纹理、书架、地面**这类
   硬表面高频区；**人物与人脸几乎全黑**。DA3 的 SH rest 学到的是背景的视角相关反射，
   不是人的细节。
4. **人脸区单独量（清单 C3）**：v0 17.81 → 17.81（**+0.00**），v16 21.21 → 21.30（+0.09）。
   SH rest 对人物区域**零收益**。

**成本**：多存 757 MB 的 PLY（3.5× 体积、9.8× ckpt），换 +0.23 dB 且人脸无改善 → 不划算。

**与 P0 旧结论的关系**：旧口径下"保留 SH rest @参考视角 +1.23 dB"现在只能解释为
错尺度污染（参考视角恰是缩放不改变投影的那个点，误差形态最特殊）。新口径下结论的性质变了：
不是"外观容量不足"，而是"**外观容量只在背景硬表面上兑现**"。

### R-2.5 由此得到的新发现（比 SH 本身重要）

写结论时顺手核了训练/评测分辨率，发现一个一直被忽略的口径：

| 量 | 值 |
|---|---|
| 原图 | 1439 × 1919 |
| 训练分辨率（`03b` 默认 `RES=2`） | 720 × 960 |
| 评测归一化分辨率（`99_eval_render_metrics`） | **378 × 504** |
| 人脸在该分辨率下的高度 | **约 40 px**（GT 原图约 160 px） |

**所以"脸糊"首先要怀疑的是渲染分辨率，而不是外观容量** —— 这也是 SH rest
（最廉价的外观容量：免费多 756 MB 参数、零训练成本）只值 +0.23 dB 的合理解释。

⚠️ 注意区分：P0-1 测的是「**DA3 输入**分辨率 504→1008」，**训练分辨率从未被单独测过**。
两者是不同变量，不能拿 P0-1 的 B 结论否掉训练分辨率。

### R-2.6 对计划的影响

## R-3. 训练分辨率消融（2026-11-07）· RES=2 vs RES=1

### R-3.0 为什么必须同时钉死两个分辨率

R-2.5 发现的"口径"其实有**两个独立变量**，历史实验把它们混在一起了：

| 环节 | 历史取值 | 是否被单独测过 |
|---|---|---|
| DA3 **输入**分辨率（`PROCESS_RES`） | 504 | 是（P0-1，判 B，但那是错尺度下测的） |
| 3DGS **训练**分辨率（`03b` 的 `RES`） | 2 → 720×960 | **从未** |
| 渲染/评测分辨率（`94` 取 npz 的 504） | 378×504 | **从未** |

所以"脸糊"到底是训练没看到那么多像素、还是渲染时根本没那么多像素、还是模型表达不出来，
这三者历史上无法区分。本轮把后两个变量一起拆开：

- **训练**：`RES=2`（720×960，复用 P1 的 A0 产物）vs `RES=1`（1439×1919，新跑）
- **渲染+评测**：每份训练产物都在 `378×504` / `756×1008` / `1439×1919` 三档各渲一次

**为什么渲染要三档而不是只比原生**：`94` 的 `RENDER_SIZE` 是**真的按该分辨率光栅化**
（按比例缩放内参，不是把低分辨率图放大），所以三档各自都是"该方法在这个交付分辨率下的
真实产物"。只比一档会漏掉两条可能相反的趋势：低分辨率口径下 `RES=1` 多学的细节可能被
降采样抹平（看不出优势），高分辨率口径下 `RES=2` 的高斯可能根本撑不起那么多像素。
两档都报、外加中间档，才能看出趋势是否单调。

**评测口径的硬约束（本轮新加的闸门）**：`99_eval_render_metrics.py` 原来的行为是
"按渲染图自身尺寸"归一化 ref —— 跨分辨率比较时这等于**两边在不同的坐标系里算 PSNR**，
不可比。已加 `--eval-size WxH`，本轮所有跨组比较都强制传它。

### R-3.1 预注册判据（写在结果之前）

主指标：`1439×1919` 口径下的全图 PSNR 均值（32 视角自一致性）。

| 判 | 条件 | 含义 |
|---|---|---|
| **A** | `PSNR(RES=1) − PSNR(RES=2) ≥ +1.0 dB` | 训练分辨率是主瓶颈，4× 成本值得付 |
| **B** | `0 ~ +1.0 dB` | 有收益但边际，需按交付目标决定是否付 |
| **C** | `< 0` | 高分辨率训练反而更差（点数不足以支撑更高像素 / 2k 步收敛不足） |

次级指标（不单独定判，但必须报，用于解释主判）：
1. **人脸区 PSNR**：在 1439×1919 口径下裁画面中心偏上 40%×40%，两组同框比。
2. **锐度比** `sharp(render)/sharp(ref)`：同一评测分辨率下算，看"离原图多远"。
3. **降采样鲁棒性**：`RES=1` 渲 1439 再降到 378，是否仍优于 `RES=2` 直接渲 378
   （超采样抗锯齿的收益）。
4. **成本**：训练秒数、显存峰值。

### R-3.2 我的预测（用于事后校准判断力，必须写下来）

1. **主判 A，但幅度保守**：`Δ = +0.8 ~ +2.0 dB`。
   理由：32 视角自一致性下，4× 像素给出 4× 梯度信号，细节能长出来；
   但 **415 万点 / 276 万像素 ≈ 1.5 个高斯每像素**，密度并不充裕，
   高分辨率下会立刻暴露"点不够"，所以不会是 +4 dB 那种量级。
2. **`RES=2` 在 1439×1919 口径下会掉 1.5~3.0 dB**（相对它自己在 378×504 的成绩）。
   机制**不是**上采样插值损失（渲染是真光栅化），而是：720×960 训练下每个高斯只需
   覆盖约 1 个训练像素，学到的尺度/位置精度只到那个量级；换成 276 万像素渲染时，
   同一个高斯被摊到 4× 面积上，边缘与高频就露馅。这能量化"低分辨率训练 + 高分辨率交付"的代价。
3. **人脸区 Δ > 全图 Δ**：分辨率主要买的是局部高频，全图被大色块稀释。
   预测 `Δ_face = +1.5 ~ +3.5 dB`。
4. **降采样鲁棒性：`RES=1` 在 378×504 口径下仍略胜**（+0.1~+0.5 dB），幅度小于原生口径。

**若预测大幅错（|实测−预测| > 2 dB）就先看图再上报**（清单 C1）。

### R-3.3 风险与降级路径（预先声明）

- `RES=1` 训练显存：415 万高斯 + 1439×1919 光栅化，24 GB 可能不够。
  若 OOM → 先降 `MAX_POINTS` 到 200 万重跑，并在台账里注明"点数被降级，主判只能作参考"。
- 2k 步在 RES=1 下训练时间约 4×（≈16 min），仍可接受。
- 若 `RES=1` 的 PLY 与 init 的 md5 相同 → 直接判无效（清单 B1），不解释。

### R-3.4 结果（2026-11-07 03:23，已闭环）

补跑 RES=4（因为前两组跑完后浮现出"对角线"规律，必须再取一个点验证）。3 训练 × 3 评测，
全部 32 视角自一致性，同一 init、同一 2k 步、关 densify：

| 训练 \ 评测 | 378×504 | 756×1008 | 1439×1919 |
|---|---|---|---|
| **RES=4**（360×480） | **28.06** / 0.916 / 914 | 21.89 / 0.715 / 696 | 18.93 / 0.578 / 350 |
| **RES=2**（720×960） | 25.21 / 0.859 / 822 | **27.12** / 0.896 / 544 | 23.32 / 0.774 / 360 |
| **RES=1**（1439×1919） | 23.52 / 0.791 / 826 | 25.58 / 0.859 / 428 | **26.04** / 0.862 / 202 |

（格内 = PSNR / SSIM / 锐度；ref 锐度：378→1421.5，756→820.5，1439→416.8。
 锐度绝对值**跨分辨率不可比**，Laplacian 方差随分辨率变化 3.4×，只能看同档下的"渲染/ref"比。）

| 训练 | 耗时 | 峰值显存 | 点/像素 | 高斯数（不变） |
|---|---|---|---|---|
| RES=4 | **181 s** | **7,954 MiB** | 28.0 | 4,838,397 |
| RES=2 | 236 s | 9,532 MiB | 7.0 | 同上 |
| RES=1 | 745 s | **24,044 MiB**（24 GB 打满） | 1.8 | 同上 |

**对角线规律**：每一档训练的 PSNR 峰值都落在"训练分辨率 ≈ 评测分辨率"的格子上，
且错配代价极大 —— `RES=4` 渲到 1439 只有 18.93（比对角线的 26.04 低 **7.11 dB**），
`RES=1` 渲到 378 只有 23.52（比对角线的 28.06 低 **4.54 dB**）。

### R-3.5 判定：B（无效），但理由与预注册不同

**主判据名义命中 A**：`Δ(RES=1 − RES=2) @1439 = +2.73 dB`，超过 +1.0 的 A 阈值。
但按清单 C1 先看图，**结论被视觉与分频检查推翻**：

| 检查 | 结果 |
|---|---|
| 人脸区 PSNR（1439 口径，4 视角） | RES=1 **23.82** vs RES=2 23.30 → **只 +0.52** |
| 单帧 view 0 人脸区 | **21.61 vs 21.57 → +0.04**（等于没有） |
| 误差图（fig19） | 两行误差分布**几乎相同**，都集中在头发边缘/五官轮廓 |
| 分频带通（A7b） | 各尺度能量比 0.9~1.0、相关 0.88~0.99，**两组几乎重合** |

→ **+2.96 dB 的全图收益几乎全部来自背景**（柜子木纹、地板、墙面这些大平面在
1439 下有更多纹理可学），**不是我们要救的人脸**。而成本是 **3.16× 训练时间 + 显存打满**。
所以判 **B**：这条路线不值得为"脸糊"付。

**同时得到一个反向结论**：在 378×504 这个交付口径下，**降低**训练分辨率反而更好 ——
`RES=4` = **28.06 dB / 181 s / 7.95 GB**，比 `RES=2` 快 23%、省 17% 显存、高 **2.85 dB**，
且肉眼确认最接近 GT（fig20：发丝、眼廓、衣领纹理最清楚）。

**机制（唯一能同时解释 9 个格子的假设）**：决定高斯尺度的是**训练时的"点数/像素"比例**，
不是分辨率本身。415 万点固定：

| 训练 | 点/像素 | 训练出的高斯 | 在自身分辨率渲染 |
|---|---|---|---|
| RES=4 | 28.0 | 很小 | 细节足、无空洞 → 最锐 |
| RES=2 | 7.0 | 适中 | 均衡 |
| RES=1 | 1.8 | 被迫摊大填空隙 | 覆盖完整但**软** |

这解释了为什么 RES=1 在 1439 下全频段 PSNR 更好（低频 +7.53 dB，高频 +1.70，
HF 相关 0.841→0.889）却看着更软：它是"更准但更平滑"的重建，误差被摊到了
0.6–1.2 px 这个最细尺度上（该段能量比 0.68 vs RES=2 的 0.74）。

### R-3.6 预测校准（诚实记录偏差）

| 预注册预测 | 实测 | 判定 |
|---|---|---|
| 主判 A，Δ=+0.8~+2.0 | +2.73 | 超上限 0.73，方向对 |
| RES=2 @1439 掉 1.5~3.0 dB | 掉 1.89（25.21→23.32） | ✅ 最准的一条 |
| **人脸 Δ > 全图 Δ（+1.5~+3.5）** | **人脸 +0.52 < 全图 +2.73** | ❌ **完全错** |
| RES=1 @378 略胜 +0.1~+0.5 | **−1.69** | ❌ 方向错 |

最大的判断错误是第 3 条：我以为"分辨率买的是局部高频，人脸会受益最多"，
实际是"分辨率买的是大面积纹理，背景受益、人脸纹丝不动"。
→ 说明**人脸糊的成因不在采样密度**，往"提高分辨率/加像素"这个方向调参是死路。

### R-3.7 由此得到的两条口径修正（影响之前所有结论的解释）

1. **锐度（Laplacian 方差）不能跨分辨率比**：ref 自身在 378/756/1439 下的锐度是
   1421 / 820 / 417，差 3.4×。之前报告里"锐度 822 vs ref 1421"这类表述只能同档比。
2. **PSNR 在自一致性口径下会奖励"点不足导致的平滑"**：RES=1 @1439 的 26.04 是全表最高之一，
   但它的锐度只有 GT 的 48.5%，肉眼最软。所以**只看 PSNR 会选错配置**，
   必须同时看锐度比 + 分频相关 + 误差图（这正是 R-2 时 `fig14` 差值图起作用的同一教训）。

### R-3.8 对计划的影响

- **默认训练配置改为 `RES=4`**（交付 378×504 时）：更快、更省显存、还高 2.85 dB。
  若交付 720×960 用 `RES=2`，交付 1439×1919 用 `RES=1` —— **按交付尺寸选 RES，不要固定值**。
- **"人脸糊"与分辨率解耦，已排除这条线**：三种训练分辨率下人脸区 PSNR 在 1439 口径下
  是 21.6~23.8，且两组几乎相同；全图却能到 26~28。人脸是**独立的瓶颈**。
  下一个该查的方向不再是"采样密度"，而是：
  ① 点数/容量（该区域的高斯数量是否足够）② 损失加权（是否该对人脸/高梯度区加权）
  ③ 位姿精度（人脸区域的局部几何是否本身就偏）。
- **`RES=1` 不作为任何交付口径的默认**：唯一优势是 1439 原生交付 +2.96 dB，
  而 +2.96 全在背景；显存打满 24 GB 使它在多人场景下不可用。

## R-4. 全链路审计（2026-11-07 18:30）· 排除"重影是口径 bug"

### R-4.0 触发

R-3 交付后目检 fig20：三档都有糊与淡重影，RES=1 重影最少但仍糊。
在把"糊"归给模型能力之前，必须先排除"又是 E-01 那类口径 bug"。

### R-4.3 那糊和重影从哪来：按来源视角切开

把高斯按"来自哪个视角"切开（导出顺序 = view-major，屏蔽规则可精确复刻；
3DGS 在 densify 关闭时不增删点，所以训练产物也能复原），在**同一像素集**
（仅本视角覆盖到的像素，占 43%）上比：

| 组 | 含义 | PSNR（3 视角均值） |
|---|---|---|
| 全部高斯 | 成品（= fig20 那几张） | **23.87** |
| 仅本视角 | 该视角自己的壳，α 未叠满 → 暗 | 14.44 |
| 仅本视角 ÷ α | 去掉透明度后的单视角几何 | 19.69 |
| 去掉本视角 | 其余 31 个视角 | **23.34** |

1. **单视角 α 中位 0.073**（`opacity>0.5` 只占 10.3%）→ 一个像素要 ~25 层才不透光。
2. **单视角几何自己就偏 4.2 dB**（19.69 vs 23.87）；跨视角深度一致性中位 **0.95%**、
   p90 视角对 **37.3%**，"<1% 的像素"逐对中位只 **52.7%** → 每个壳各自偏一点
   （`audit_1_pose_geom.json` 的 `cross_view_geometry`，992 对视角）。
3. **成品 ≈ 去掉本视角**（23.34 vs 23.87）→ 渲染结果本质是"31 个互相错开的壳的加权平均"。
   平均抵消随机误差（PSNR 不低），也抹平细节（模糊 + 淡重影）。

σ 的硬上限（`audit_7_param_drift.py`）：init σ 折合 `[0, 0.48, 1.28]` px @378；
渲染 1439 时同一批高斯变成 `[0, 1.84, 4.86]` px。2k 步只把 σ 缩了 11%、α 提到 0.073。

### R-4.4 判定与影响

- **没有发现新的代码 bug**。E-01 之后的口径链路是干净的，fig16/fig20 的数字可用。
- R-3 的"对角线规律"与"RES=4 交付 378 最优"不受污染：三档在 378 口径下 σ 同为 ~1 px。
- 多一条解释：**RES=1「重影最少但最糊」是因为壳被优化成互相吻合的大笔刷**（重影被糊掉），
  RES=4 的锐笔刷把"31 个壳没对齐"直接显影。该密度下锐度与重影可见度是一体两面。
- 结论落 `FINDINGS.md §5.3-sexies`，检查项落 `ERRATA.md` E1~E4 + 审计基线表。

## R-5. 复现 DA3 官方效果 +「仅本视角」归因（2026-11-07 23:30）

### R-5.0 触发

峰哥看 fig20/fig21 问：「仅本视角为什么会有这么严重的重影？我们要先把 DA3 的官方效果
复现好，再去想着演进优化。」

判断顺序：**先证明"我们渲染的确实是官方那套"，再谈模型能力**。所以本轮先逐项核对官方
渲染路径，再实测五档口径，最后才回答「仅本视角」。

### R-5.1 官方渲染路径逐项核对（读源码 + 数值验证）

| 项 | 官方（`model/utils/gs_renderer.py` + `utils/export/gs.py`） | 我们 | 结论 |
|---|---|---|---|
| 光栅器 | `gsplat.rasterization` | 同（gsplat 1.5.3） | ✅ 一致 |
| opacities 语义 | 传**已激活** α（0~1），kernel 不再 sigmoid | `sigmoid(PLY 的 logit)` 后传入 | ✅ 一致（实测 `alpha≈输入`，只把 >0.99 夹住） |
| 渲染分辨率 | `prediction.depth.shape[-2:]` = 504×378 | 378×504 | ✅ 一致 |
| 相机帧 | `is_metric` 时 `tgt_extrs[:,:,:3,3] /= scale_factor`（除回高斯所在的未缩放帧） | 把高斯 ×scale_factor（等价） | ✅ 一致（全局相似变换，投影不变） |
| PLY 导出 | `gs_views_interval=1`、`prune_by_depth_percent=0.9`、`prune_border_gs=True`、`save_sh_dc_only=True` | 逐参数相同 | ✅ 一致 |
| 颜色 | `use_sh=True`，**内存里的全 SH** | 只有 DC（PLY 交付） | ❌ **不一致** |
| 点集 | **610 万**（32×190,512，全部像素） | **484 万**（裁剪后 79.4%） | ❌ **不一致** |

注：官方 `export_to_gs_ply` 的默认 `gs_views_interval=1` 与我们一致（`export/gs.py:47`）。

### R-5.2 五档实测（32 视角，全部对**模型实际看到的 378×504 输入帧**）

| # | 配置 | 均值 PSNR |
|---|---|---|
| A | 610 万点 + 全 SH + 正确帧（**官方等价**） | **22.11** |
| B | 610 万点 + 仅 DC | 20.96 |
| C | 裁剪 484 万 + 全 SH | 19.77 |
| D | 裁剪 484 万 + 仅 DC（**我们的 PLY 口径**） | **18.97** |
| E | 帧错：缩放相机配未缩放高斯 | 11.27 |

**最关键的一条交叉验证：D = 18.97 dB，与我们历史上报的「DA3 直出」18.97 逐位相同。**
说明我们的渲染链路一直是对的 —— 错的是**把「PLY 交付口径」当成了「官方口径」**。

2×2 分解：

|  | 全点 610 万 | 裁剪 484 万 |
|---|---|---|
| 全 SH | 22.11 | 19.77 |
| 仅 DC | 20.96 | 18.97 |

- 全 SH 的收益：**+1.15 dB**（全点）/ **+0.80 dB**（裁剪）
- 不裁剪的收益：**+2.34 dB**（全 SH）/ **+1.99 dB**（仅 DC）
- ⇒ **点集裁剪的代价约是 SH 的两倍。**

评测参考图的 resize 口径已排除（`audit_10`）：模型内部输入 vs `cv2.INTER_AREA` 缩放
= **54.1~55.3 dB**（INTER_LINEAR 30~34、LANCZOS4 28~32）→ 我们的 `99` 用 INTER_AREA 是对的。

### R-5.3 「仅本视角」为什么像重影（`audit_8_selfview_geom.py`）

| 量 | 实测（view 0 / 8 / 16） | 含义 |
|---|---|---|
| 每视角高斯 / 像素 | 0.79（PLY 只保留 79.4% 的像素） | 单层自带 **20.6% 空洞** |
| 单层 α 中位 | 0.036（`>0.5` 仅占 0.045%） | 单层几乎透明 |
| 成品 α 中位 | **1.000** | 靠 32 视角叠加才不透光 |
| `means` vs 深度抬升点 | 25.6 / 33.5 / 41.7 mm | 高斯头相对深度头的几何偏移（沿视线为主） |
| 自投影横向残差 | 0.44~1.20 px（去逐视角平移后 0.58~0.92） | 亚像素到 1 px，随视角变 |
| 抬升点自投残差 | **0.0000 px** | 我们的像素映射 + 半像素约定正确（`(idx+0.5)/len`） |

结论：**单看一层必然是"稀疏 + 半透明的点画"**。它不是可独立观看的表示，重影感来自
稀疏采样与 α 不足，不是几何错了，更不是导出 bug。

### R-5.4 订正上一轮（R-4）的两处过度解读

① **「单视角几何自己就偏 4.2 dB（19.69 vs 23.87）」不成立**。`÷α` 在 α=0.036 时把噪声
放大 ~14 倍，该数字被噪声主导。真实几何残差是 **~1 px 横向 + 26~42 mm 沿视线**。
② **「成品 ≈ 去掉本视角 ⇒ 31 层平均把细节抹平」推理链不成立**。去掉 1/32 的贡献只动
0.5 dB，是 alpha 混合的正常稀释，不能据此断言"本视角没用"。R-3 的「RES=1 重影最少但最糊」
结论保留，但依据应改为 **σ 的像素当量**（[0, 0.48, 1.28] px @378，渲染 1439 时变 4.86 px），
而不是 R-4 那条。

### R-5.5 判定与影响

- **DA3 官方效果 = 22.11 dB @378×504**（610 万点 + 全 SH）。此前报的 18.97 是"裁剪 + DC"
  的**交付口径**，差 3.14 dB 全部来自导出选项，与模型、渲染器无关。
- 「前馈 init + 2k 步（25.21 dB）相对 DA3 直出」的优势由 +6.2 dB 修正为 **+3.1 dB**，
  方向不变、幅度要改（`FINDINGS.md` 已同步）。
- 「仅本视角」不构成待修问题；**要复现官方，只需按 A 口径渲染**：不裁剪、全 SH、
  相机除回 scale_factor。可用 `audit_9_official_render.sh` 一键复现。
