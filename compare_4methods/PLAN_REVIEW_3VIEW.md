# 三视角对比实验方案评审（GPT 方案 × 本地已有结论核查）

> 建立：2026-11-11。背景：峰哥跑了 3 视角输入的 DA3-GS vs InfiniSplat v2 对比
> （`90a_run_3view_jiajia.sh` 链路），观察：DA3-GS 整体偏灰、模糊、人脸细节丢失、
> 背景大面积白色空洞；InfiniSplat v2 颜色正常、模糊较少，但头脚重影、人脸细节不足、
> 背景仍有部分白洞。用 GPT 生成了一份四主线归因实验方案，本文档是对该方案的评审
> 与修订。**任何后续三视角实验开工前先读本文档。**

## 0. 评审结论（先给判断）

GPT 方案的方法论骨架**可采纳**：先归因再改模块、判据先于实验写死、分四条主线
（颜色/几何/背景/人脸）独立消融、不把 InfiniSplat 输出当 DA3 训练标签。
这与本目录 IMPROVEMENTS.md 的四条规则（R1 参照物先自证 / R2 单变量 / R3 判据先行 /
R4 报告带参照）同构，直接沿用。

但方案有 **4 处会被本地已实测结论证伪或造成重复劳动、2 处关键缺失**，
按"先修哪里"排序见 §2~§5。**修订后的第一轮实验顺序见 §6。**

## 1. 三视角设定的既有事实（方案设计的约束条件）

以下全部是 2026-11 实测值（出处见 FINDINGS.md / P0_EXPERIMENTS.md），不是推断：

| 事实 | 数字 | 出处 |

| 三图下 DA3+3DGS 精化系病灶 | self3 仅 9~10 dB，渲染被 haze 洗白（比 GT 亮 26 灰阶），densify 填出半透雾 | FINDINGS §8 |

GPT 方案以"125 张评估图"为固定条件不适用（采集包共 32 帧 GT）。

## 2. 缺失 1（最关键）：统一"是否做逐场景优化"的口径

峰哥观察到的 DA3-GS"灰、糊、人脸看不清"，**第一怀疑对象不是颜色管线或
Gaussian 属性，而是直出没做场景优化**：

- DA3-GS 直出 = 一次前向，无任何回炉；
- InfiniSplat v2 = 前馈 + 3000 步精调（+7.30 dB 已实测）；
- 当前对比实质是"优化后 vs 未优化"。

**处置**：GPT 方案把 A（颜色管线）和 B（scale 约束）排在 P0，
应在 E0 之后插入 **E0.5：DA3 init + 2k/5k 步**（复用 03b 链路，32v 下已知 +6.2 dB），
一次性分解出"灰+糊"中有多少属于未优化层。这条成本与 A0 相同、信息量更大。

## 3. 缺失 2：白洞的三个已有解释排在"背景独立生成"前面

GPT 直接跳到 C1–C3（背景独立 Gaussian 生成/密度增强），但空洞有三个更靠前、
已实证的候选，先排除再谈结构改动：

1. **观测弧缺口**：空洞方位角若落在 107.3° 无观测段，是 PLY 里没数据而非渲染错。
   3 视角只有 3 层叠加，此问题只会更严重。**先跑 99g 视角覆盖审计。**
2. **DA3 分层叠加机制**：官方导出 opacity 压到 1/32，靠 32 层叠到 α≈1.000；
   **3 视角只有 3 层，α 叠不满 → 大片透明白**，这是机制必然不是 bug。
   判别：渲一张 alpha/accumulation 图，空洞处 α 低 = 覆盖层数不够。
3. **渲染背景色设置**：确认渲染器背景色与 GT 背景色（若 GT 背景接近白，
   "白洞"可能是对的）。

## 4. 冲突核查表：GPT 提案 × 本地已判 B 的结论

| GPT 提案 | 本地已有结论 | 处置 |
|---|---|---|
| G1 全局 4× Appearance（提输入/特征分辨率） | P0-1 实测 504→1008：**−0.34 dB 判 B**（DA3 按 504 训练，直接喂高分辨率是分布外推） | 删；如保留必须"随训练一起提分辨率"，定性为训练项目 |
| "加 SH / 提分辨率救人脸" | R-2：SH rest +0.23 dB 且人脸 **+0.00**；R-3：三档训练分辨率人脸区 21.6~23.8 纹丝不动——**人脸是独立瓶颈，与采样密度解耦** | 人脸实验直接上 G2/G3（Face ROI + 多视角融合），跳过 G1 |
| B1–B3 Gaussian scale 约束 | σ 像素当量已实测（init [0,0.48,1.28]px @378）；2DGS oracle/eps 扫掠已证"不是足迹下限问题"（I-03b，H2 证伪） | 保留但降优先级，作为短精调的辅助而非独立实验 |
| E 系列 multi-view consistency loss | 方向对（跨视角不一致是已确认主因，FINDINGS §5.2），但**短精调本身就在做光度一致性约束**（P1 判 A）；3 图大基线下几何误差大，直接上 mv loss 有固化错误的风险 | 顺序：先 E0.5 短精调 → 若"离参考视角远就烂"仍在，再动位姿（D5）→ mv loss 排最后 |
| "灰色"归因于颜色空间/曝光（A 系列） | 三图下 DA3+3DGS 已有实测病灶：haze 洗白亮 26 灰阶 | **先确认峰哥跑的是 02 直出还是 03 精化**；若是 03，A 系列找错对象 |
| 纹理头/双头解耦（P2 原规划） | 已两次后置：外观容量只在几何正确的视角兑现（+1.23 dB），且瓶颈在分辨率不在表达能力 | 维持后置；人脸走 Face ROI 分支而非全局纹理头 |

## 5. 评测方法论硬约束（花钱买来的教训，方案未写）

1. **ROI 人脸指标必须逐视角定框**。固定人脸框在 view 8 落在书架上，
   把人脸锐度虚高 +142~+180（ERRATA E12）。逐视角窗：v0 (156,70,221,151)、
   v8 (194,73,251,156)、v16 (162,78,226,156)（378×504 口径，仅示例，3v 实验需重新定框）。
2. **主判据不用全图 PSNR**。自一致性口径奖励平滑（RES=1 拿 26.04 但锐度仅 GT 的 48.5%）；
   必须配锐度比 + 误差图 + 分频相关（A7b）。
3. **参考视角依赖**。DA3 质量随"离参考视角三维距离"单调衰减；跨运行比较必须
   钉死 `REF_STRATEGY`（saddle_balanced 会换参考帧 → 坐标系不同，P0-1 踩过）。
4. **渲染分辨率对齐再比**。对角线规律：训练/渲染分辨率错配丢 4.5~7.1 dB；
   锐度跨分辨率不可比（Laplacian 方差随分辨率变 3.4×）。
5. **PSNR/SSIM 指标口径**：三视角下只有"输入视角自一致性"可用；
   任何"提升 X dB"必须写成"相对基线某口径 +X"（R4）。

## 6. 修订后的第一轮实验顺序（替代 GPT 原 E0~E7 矩阵）

| 步 | 实验 | 目的 | 成本 |
|---|---|---|---|
| ① | 确认链路（02 直出 or 03 精化）+ 渲 alpha/accumulation 图 + 99g 覆盖审计 | 定位白洞是观测缺口 / α 叠不满 / 背景色设置 | 分钟级 |
| ② | DA3 init + 2k/5k 步（3v 输入，复用 03b） | 统一优化口径，预计一次性吃掉"灰+糊"的大部分 | 单卡数分钟~十分钟级 |
| ③ | 人脸仍糊 → 直接上 G2/G3 Face ROI 分支（跳过 G1） | 人脸独立瓶颈；UE 数据有人脸 mask/关键点 GT 可监督（借 vggt_human ExpTracker 657 点管线） | 训练项目 |
| ④ | 重影仍在 → 位姿精化（D5，bundle-adjust 式）；mv loss / confidence fusion 后置 | 几何根因 | 视③结果 |

InfiniSplat v2 全程作独立对照基线：统一输入帧、统一渲染/评测分辨率、
统一 opacity 口径（32v 实测其渲染背景 alpha 仅 0.51~0.68 vs 官方 0.95，
比观感前必须口径统一，FINDINGS §8 结论 1）。

## 7. 方案中值得保留的部分

- 先归因再改模块、判据先行（= R1~R4）。
- 背景与人物分开处理——但动机应改为"DA3 分层叠加在稀疏视角下 α 叠不满 +
  观测弧缺口"，不是"深度/纹理尺度不同"。
- G3 多视角人脸融合（正面主纹理 + 侧脸结构 + 可见性加权）——方案里最值得做的部分。
- 不把 InfiniSplat 输出当 DA3 训练标签；统一输入/相机/颜色后再比。
