## 1. 技术领域与背景技术

### 1.1 技术领域

三维重建 / 计算机视觉。具体涉及：多视角图像的三维高斯溅射（3D Gaussian Splatting, 3DGS）重建过程中，对输入图像或渲染图像的人脸区域施加生成式图像复原/增强（如基于扩散先验的单步复原模型）时，**确定增强生效区域及其空间权重**的方法。

### 1.2 现有技术方案

当前主流做法（也是本方案所在项目的既有实现，`vggt_human/face_enhance.py`）为：

1. **逐帧独立的人脸检测**：对每一帧图像用 BlazeFace/MediaPipe 检测人脸框（`face_enhance.py:135-150`），框按 `FACE_PADDING`（默认 0.2）外扩（`face_enhance.py:153-163`）；
2. **裁剪 → 增强**：按框裁剪出区域，送入生成式复原模型（SD2 + LoRA）增强，`upscale=1` 不做超分；
3. **羽化融合回填**：将增强结果与原图按一个**与图像内容、与三维几何均无关**的权重模板融合。既有两种模板：
   - 二次衰减模板 `create_feather_mask`：以**裁切框中心为原点**的径向衰减 `1 − (r/r_max)²`（`face_enhance.py:91-99`）；
   - 边缘带模板 `create_border_mask`：中心恒为 1，仅边缘 `margin_frac`（默认 0.08）× 短边 呈平滑过渡（`face_enhance.py:102-119`）；
4. **（改进路径）叠加渲染 alpha**：引入 3DGS 渲染出的前景 alpha 图做第二轮加权，`final = fused·α + orig·(1−α)`（`face_enhance.py:489-504`，`FUSION_MODE=border_alpha`）。

### 1.3 现有技术的缺陷（→ 技术问题）

**缺陷一：增强区域在视角之间不一致，导致同一三维表面点被差别对待。**

第 1.2 节步骤 1 的检测框是**逐帧独立**产生的。同一个三维人脸表面点，在 A 视角可能落入检测框（被增强），在 B 视角可能落在框外（不被增强）；步骤 3 的权重模板以**裁切框中心**为基准，而各帧的裁切框位置、大小、长宽比随检测结果浮动，因此同一个三维点在各视角拿到的融合权重互不相同。

其直接后果是：多视角重建在后续训练中面对的人脸区域外观**跨视角不自洽**，表现为增强区域边界处的接缝、重影或亮度跳变。

该缺陷在本项目设计文档中已被明确记录（`vggt_human/DESIGN_face_pipeline.md:409`，未决项 5）：

> 「增强区 mask 的 3D 一致性 —— 现为逐帧 2D bbox crop + feather；同一 3D 点在不同帧可能落在增强区内/外」

**缺陷二：逐视角渲染 alpha 不能解决一致性，且不区分人脸与头部其余部位。**

第 1.2 节步骤 4 引入的 alpha 是**该视角下独立渲染**得到的前景可见性，其数值取决于该视角的高斯投影分布与遮挡关系。同一三维点在不同视角下的 alpha 值并不相等（尤其在边界与半透明边缘处），因此它压制的只是"边缘伪影"，并未建立跨视角的一致判据。此外 alpha 给出的是**整个前景（含头发、脖颈、肩部）**的覆盖，无法区分"应当增强的人脸"与"不应当增强的其余部位"。

**缺陷三：依赖在渲染图上做人脸检测，而渲染图恰恰是低质量的。**

在人脸增强的后处理场景（对当前模型**渲染图**做增强）中，检测对象是重建模型输出的渲染图。渲染图在近景/外插视角下本身模糊，检测器常无法检出人脸。既有实现不得不引入**固定中心框兜底**（`face_enhance.py:42-44` 注释、`face_enhance.py:435-437`）：检测失败时用画面中心 50%×60% 的固定矩形代替人脸框。该兜底与真实人脸位置、尺度无关，属降级措施而非解决方案 —— 其根因是"增强区域的确定依赖对低质量图像的二次检测"这一技术路线本身。

**缺陷四：增强强度在整个区域内恒定，无空间调制能力。**

融合权重只由"距框中心的距离"或"距框边缘的距离"决定，与"该处是否确实是稳定可见的人脸几何"无关。在检测框边缘、遮挡交界、多视角证据薄弱的区域，增强强度与区域中心相同，缺乏抑制机制。

## 2. 发明内容：技术方案

### 2.1 核心构思

> 将增强区域的确定，从**二维图像域、逐帧独立**的判定，前移到**三维场景域、多视角联合**的判定：
> 先为三维场景中的每个三维元素计算一个**固有**的增强置信度，再将其投影到各视角、光栅化为该视角的增强权重图。
> 由于置信度是三维元素的属性而非视角的属性，投影后自然获得跨视角一致性。

与现有技术的关键分野：现有技术在问"**这一帧图像的哪些像素**要被增强"；本方案在问"**场景中的哪些三维表面**要被增强"，视角只是它的投影。

### 2.2 技术手段（分步骤）

#### 步骤 S1：构建三维增强置信度场

**S1.1 输入准备**
- 多视角图像集及其相机位姿（可由 COLMAP / SfM 提供）；
- 各视角的人脸语义区域证据，可取自下列任一种或其组合：
  - (a) 语义分割掩码（如对每帧人脸/头部区域的分割结果）；
  - (b) 人脸检测框（现有流程已有）；
  - (c) **几何掩码**：将头部三维表示（如参数化人头模型或其稠密化高斯表示）的颜色置白、其余置黑后渲染，取渲染亮度图作为该视角的头部软掩码。
- 三维元素集合 {P_i}，可取自：重建场景的高斯集合、头部子模型的高斯集合、或参数化人头网格的顶点集合。

**S1.2 多视角投影与命中判定**
对每个三维元素 P_i，投影至各视角 v，得到像素坐标；判定其是否命中该视角的语义区域，并施加**深度带过滤**以排除沿视线方向位于人脸之后、但二维投影恰落在语义区域内的背景元素。

> 既有可复用实现：`vggt_human/face_center_3d.py:191-212`（投影）、`:241-263`（命中计数）、`:276-309`（深度带过滤，以语义区域内命中元素的距离中位数估计该视角目标距离，仅保留 (1±tol) 带内命中）。该实现当前被用于计算人脸三维中心点，**其逐元素命中计数在求质心后被丢弃**。

**S1.3 置信度累计（本方案的关键步骤）**

对每个三维元素 P_i 计算：

```
c_i = Σ_v  ω_v · hit(P_i, v)
      ────────────────────────
      Σ_v  ω_v · visible(P_i, v)
```

其中：
- `hit(P_i, v)` ∈ {0,1}，表示 P_i 在视角 v 是否命中语义区域（且通过深度带过滤）；
- `visible(P_i, v)` ∈ {0,1}，表示 P_i 在视角 v 是否可见（位于相机前方且在画面内）；
- **分母取"可见视角数"而非"全部视角数"** —— 若以全部视角数为分母，背向相机、被自身遮挡的元素会被系统性压低置信度，使头部正面与背面的判定不对称。（同类分母口径的坑在本项目已有记录，见 `vggt_human/EXPERIMENTS.md` 中 dynamic_filter 的 bug 3：有效视角分母只数有掩码的相机导致过度删除。）
- `ω_v` 为该视角的**权重**，用于抑制不可靠证据：
  - 掠射角降权：当该元素表面的法向与视线夹角接近 90° 时，其二维投影位置误差被放大，命中判定的置信度下降；
  - 可选：检测/分割置信度、该视角下目标尺度（近景视角权重更高）等。

由此得到 `c_i ∈ [0,1]`，作为三维元素 P_i 的增强置信度。

**S1.4（可选）置信度的空间正则化**
对 {c_i} 在三维邻域内做平滑（如对三维元素做近邻加权平均、或对网格顶点沿拓扑邻接做若干轮扩散），抑制单点投票的随机波动。

#### 步骤 S2：投影光栅化，生成逐视角增强权重图

- **S2.1** 对目标视角 v，将 {(P_i, c_i)} 投影至图像平面；
- **S2.2** 按相机坐标系深度排序（z-buffer），每个像素取**最近可见元素**的 c_i 作为该像素权重，从而正确处理遮挡关系；
- **S2.3** 归一化，并施加一次形态学/羽化平滑以获得连续的过渡带。此处可保留现有 `create_border_mask`（`face_enhance.py:102-119`）作为最终过渡项与置信度图相乘，二者不冲突；
- **S2.4** 输出：该视角的增强权重图 `w_v(x, y) ∈ [0,1]`。

**关键性质**：同一三维元素 P_i 在任意视角的贡献值恒为 c_i，因此权重场在三维域中定义良好，其跨视角投影是自洽的。

#### 步骤 S3：增强执行与加权融合

- **S3.1** 对目标视角执行生成式人脸增强（可用现有裁剪→增强流程，或不裁剪的整图增强）；
- **S3.2** 融合：`out = enh · w_v + orig · (1 − w_v)`；
- **S3.3（可选，增强强度空间调制）** 以 c_i 同时调制增强强度或增强模型的引导强度，使"多视角一致确认为人脸"的区域获得完整增强强度，"证据薄弱/边界"区域获得较弱增强。

#### 步骤 S4：在三维重建训练流程中的应用

上述权重图可用于以下任一时机（三者可组合）：

| 应用时机 | 用法 |
|---|---|
| (a) 训练前处理 | 以 `w_v` 为权重，按增强结果替换输入图像的人脸区域，形成增强后的真值 |
| (b) 训练中后处理 | 以 `w_v` 为权重，按当前模型渲染图的增强结果替换真值（伪真值/自蒸馏） |
| (c) 外插视角注入 | 渲染输入集中不存在的新视角 → 增强 → 以真实相机位姿注册回场景，作为额外训练视角 |

在 (a)(b)(c) 中，`w_v` 均由同一套三维置信度场投影得到，因此三个入口的增强区域在三维意义上是同一个区域 —— 这是现有逐帧 2D 框方案无法保证的。

## 3. 有益效果

### 3.1 直接技术效果

1. **消除增强区域在视角之间的判定跳变**：同一三维表面点在任何视角下获得一致的增强判定，避免"此视角增强、彼视角不增强"造成的外观不自洽。
2. **消除对低质量图像二次检测的依赖**：三维元素集合在场景构建阶段即已确定，增强区域由投影得到，**不需要在渲染图上重新做人脸检测**，从根本上规避了缺陷三（近景渲染人脸过糊导致检测失败、只能以固定中心框兜底）。
3. **增强强度可空间调制**：以置信度调制强度，在边界与证据薄弱区自动抑制，替代"区域内强度恒定 + 边界羽化"的粗粒度方案。
4. **多视角证据的显式利用**：将"该处是否稳定可见的人脸"这一判据显式化、可量化、可调参（视角权重、深度带容差、置信度阈值），便于针对不同数据分布调优。

### 3.2 预期可量化的技术效果

| 指标 | 测量方式 | 预期方向 |
|---|---|---|
| 跨视角增强权重一致性 | 抽样三维表面点，统计其投影至各视角后的融合权重方差 | 下降 |
| 增强边界带的重建误差 | 在权重图边界带内计算渲染 vs 真值的 PSNR/LPIPS | 改善 |
| 人脸区锐度 | Laplacian 方差 / 梯度能量（既有 `vggt_human/face_metrics.py:69-88`） | 不低于现有方案 |
| 权重图的视角间抖动 | 相邻视角（相机连续绕转）权重图的 IoU、边界像素位移 | 下降 |
| 检测失败帧占比 | MediaPipe 在渲染图上检不出人脸的帧数 | 归零（不再依赖检测） |

> ⚠️ 上表除"检测失败帧占比"外，**均为预期方向，尚未实测**。申请前应以实测数据填充，避免在说明书中写入无依据的数值。

### 4.2 待实现的改动

1. 将 `face_center_3d.py` 的命中计数从"用于阈值筛点求质心"改为"输出逐元素置信度数组"（新增输出，不破坏原用途）；
2. 新增置信度累计（S1.3，含可见性分母与视角权重 ω_v）；
3. 新增投影光栅化模块（S2，z-buffer）；
4. 在 `face_enhance.py` 的融合分支中新增 `FUSION_MODE=confidence` 路径，以 `w_v` 替代 `create_feather_mask` / `create_border_mask`。

### 4.3 实施例 1：头部子模型 + 几何软掩码

- {P_i} = 头部子模型的高斯集合（`head_gs_p{pid}.ply`）；
- 各视角语义区域证据 = 该头部子模型经颜色 hack 渲染得到的软掩码（`render_closeup.py:571-587`）；
- 置信度累计后投影回各视角，得到人脸区权重图。
- **优点**：不依赖任何图像域检测，完全几何自洽；对多人场景天然按 pid 分离。

### 4.4 实施例 2：场景高斯 + 语义分割掩码

- {P_i} = 重建场景的全部高斯；
- 证据 = 逐帧语义分割掩码（如 SAM2/SAM3 的 person/face mask）；
- 复用 `face_center_3d.py` 的深度带过滤剔除人脸后方背景点。
- **优点**：可在没有头部子模型时独立工作；可同时输出"哪些高斯属于人脸"，供其他模块使用。

### 4.5 实施例 3（最简）：参数化人头网格顶点

- {P_i} = 参数化人头模型（如 FLAME）的顶点集；
- 证据 = 顶点在各视角的投影是否落在人脸掩码内；
- 置信度平滑后，用网格三角形插值得到连续权重场。
- **优点**：元素数量最少（数千级），计算量极低；权重场天然连续（无需光栅化平滑）。

### 6.2 区别技术特征（建议写入独立权利要求）

1. **增强区域的判定域**：本方案在**三维场景域**通过多视角投票确定每个三维元素的增强置信度，现有技术均在二维图像域逐帧确定。
2. **一致性来源**：本方案的跨视角一致性来自"置信度是三维元素的固有属性"这一构造；对比文件的多视角一致性优化作用于**损失函数层面**（对已增强结果的约束），而本方案作用于**增强信号产生之前的区域判定层面**。二者解决的问题不同：前者治理"增强结果与观测冲突"，后者治理"增强区域自身不一致"。
3. **深度带过滤**：以语义区域内命中元素的距离中位数估计目标距离并设容差带，剔除沿视线方向的背景元素。
4. **置信度的双用途**：既作为融合权重（S3.2），又作为增强强度的调制量（S3.3）。
5. **对渲染图检测的取代**：由三维投影直接获得区域，取消对低质量渲染图的二次人脸检测及其固定框兜底。

### 6.3 创造性论述要点

- **技术问题**：增强区域跨视角不一致 → 多视角重建的人脸外观不自洽（接缝/重影）。
- **技术手段**：三维域多视角一致性投票 + 投影光栅化（充分利用了三维重建本身提供的多视角观测与几何信息，属该技术领域内的具体技术手段，而非抽象算法）。
- **技术效果**：可量化的跨视角权重一致性提升、边界带误差改善、检测失败率归零。

> 注：国家知识产权局令第 84 号（2025-11-10 公布，2026-01-01 施行）修改了《专利审查指南》第二部分第四章第 6.4 节，明确「使发明产生**预料不到的技术效果**的技术特征，或者体现发明**克服技术偏见**的技术特征，应当写入权利要求中；否则即使说明书中有记载，评价发明的创造性时也不予考虑」。
> 本项目另有一项**反直觉发现**可支撑"克服技术偏见"的论述，建议单独撰写（见 `vggt_human/EXPERIMENTS.md:78-103`：以增强图作局部区域监督目标（masked-L1）对锐度无可测量贡献，而将增强图作为**完整训练视角**注入则实测有效 —— "局部监督无效 ≠ 增强图无用"）。

## 7. 风险与注意事项

### 7.1 权利要求中不得出现特定第三方模型名称

本项目使用的生成式复原模型 **HYPIR**（XPixelGroup）:
- 其开源权重附带的许可协议由 **SupPixel Pty Ltd** 持有，含"开源组件 + 专有组件（神经网络权重）"，**非商业用途**，商用需单独许可；
- 该工作已于 2025-07 开源并于 SIGGRAPH Asia 2025 发表，**属现有技术**，不得作为创新点。

**处置**：权利要求中一律写作"图像复原模型"或"生成式增强模型"，将具体模型仅作为**实施例**记载。否则保护范围被锁定在单一第三方模型上，且商业化实施时另需取得该模型授权。

### 7.2 数据合规（新增硬门槛）

《专利审查指南》第二部分第九章第 6.1.1 节（国家知识产权局令第 84 号新增，2026-01-01 施行）规定：包含算法特征的发明专利申请，若其**数据采集、标签管理**等含有违反法律、社会公德或者妨害公共利益的内容，依专利法第五条第一款**不能被授予专利权**；该节【例1】即以"人脸识别 + 商场精准营销"因违反个人信息保护法而被驳回。

**处置**：说明书须载明训练/测试数据的合法来源与获取方式（自有采集并已获授权 / 已授权的公开数据集 / 合成数据），避免数据来源不明的表述。

### 7.3 公开时点

本项目部分文档（如 `vggt_human/pipeline.html`）如曾对外发布，可能影响新颖性。**建议在申请日之前不再对外披露本方案的技术细节**（含论文投稿、演示视频、对外交流、公开仓库推送）。

### 7.4 权属

若属职务发明，专利申请权及专利权归单位（专利法第六条）。需先确认权属主体与发明人署名。
