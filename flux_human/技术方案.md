# 技术方案：图像生成解决人体微动三维重建模糊

## 1. 问题与目标

**问题**：拍摄视频中人体微动（呼吸、轻微晃动）导致多视角图像间动作不一致，MVS/NeRF 重建出现模糊、浮空 artifacts。

**本阶段目标**：用**图像生成**路线验证可行性——把动态视频转成"动作静止的多视角图像集"，做无模糊三维重建。后续扩展到视频生成。

**重要认知**：图像生成因无跨视角通信，一致性靠"同 seed + 强 condition"硬撑。若图像生成阶段重建质量 < 单图重建基线，说明思路有问题；若 ≥ 单图重建，则扩展到视频生成（temporal attention 解决一致性）有望进一步提升。

## 2. 方案核心思路

```
SAM3D Body 抽 SMPL → 找静止参考帧 T* + 渲染骨骼深度图
                              ↓
Flux1 + ControlNet(depth) + IP-Adapter(T*) → 生成 N 张多视角静止图像
                              ↓
SMPL 投影校验 → 剔除坏视角
                              ↓
NeuS 隐式表面重建 → mesh → 与基线定量对比
```

## 3. 整体流程

```
输入视频
  │
  ├─[A] 抽帧 → SAM3D Body 抽 SMPL 序列 → 找动作速度最小的参考帧 T*
  │
  ├─[B] 用 T* 的 SMPL 渲染 N 个目标视角的骨骼深度图（相机绕主体 orbit）
  │
  ├─[C] Flux1-dev + ControlNet(depth) + IP-Adapter(T*) 生成 N 张多视角图像
  │       （同 seed 锁随机性，IP-Adapter 锁外观，ControlNet 锁几何）
  │
  ├─[D] 一致性校验：SMPL 投影回每帧，剔除投影误差大的视角
  │
  └─[E] NeuS 重建（known pose，不用 colmap）→ mesh → 对比基线
```

## 4. 关键模块与技术选型

| 模块 | 职责 | 选型 | 复用性 |
|---|---|---|---|
| **A. SMPL 提取** | 视频抽帧 → 每帧 SMPL 参数 + 找静止帧 T* | SAM3D Body（已建 `sam_3d_body/`） | 视频阶段复用 |
| **B. 骨骼深度图渲染** | T* 的 SMPL + N 个相机位姿 → N 张深度图 | pyrender + SMPL mesh 渲染 | 视频阶段复用 |
| **C. 多视角生成** | 参考帧 + 深度图 → 多视角静止图像 | Flux1-dev + ControlNet(depth) + IP-Adapter | 视频阶段换 Wan2.2 |
| **D. 一致性校验** | SMPL 2D 投影 vs 生成图关键点，剔除坏视角 | 现有 SMPL + 投影代码 | 视频阶段复用 |
| **E. 三维重建** | N 张图像 + known pose → mesh | NeuS / Instant-NSR（对噪声鲁棒） | 视频阶段复用 |

**关键设计**：A/B/D/E 四个模块做成独立脚本，下沉共享逻辑，视频生成阶段只换 C 模块（Flux → Wan2.2 + 视频 ControlNet），其余不动。

## 5. MVP 分阶段实施

### Round 1：极简跑通（1-2 天）
**跳过 SAM3D Body**，直接验证"生成图像能否做出不输单图重建的 mesh"。

```
单张参考帧（人工挑）→ Flux + 简单 ControlNet（canny/depth）
  → 生成 8-16 张不同视角 → NeuS 重建 → mesh
  → 与 PIFuHD 单图重建对比 Chamfer
```
跑不通先调通，**别加复杂度**。

### Round 2：加核心组件（3-5 天）
接入完整方案，验证核心假设。

```
+ SAM3D Body 抽 SMPL → 自动找静止参考帧 T*
+ 骨骼深度图作 ControlNet（替代 canny，精确锁 pose）
+ IP-Adapter 锁外观
+ 同 seed + SMPL 投影校验剔除坏视角
→ NeuS 重建 → 对比 Round 1 和 PIFuHD
```

## 6. 成功标准与基线对比

**从 day 1 就跑定量指标**，别只看定性效果。

| 指标 | 说明 |
|---|---|
| Chamfer Distance | 与 GT mesh 双向距离 |
| F-score@1cm | 重建点在 GT 1cm 内的比例 |
| Normal consistency | 表面法向一致性 |

| 阶段 | 对照基线 | 判定 |
|---|---|---|
| Round 1 | PIFuHD 单图重建 | ≥ 持平 → pipeline 通 |
| Round 2 | PIFuHD + 真实多视角 MVS | ≥ PIFuHD → 思路对，扩展视频；< PIFuHD → 重新评估 |
| 视频扩展 | Round 2 结果 | 应有显著提升 |

## 7. 关键技术风险与对策

| 风险 | 严重度 | 对策 |
|---|---|---|
| 多视角几何不一致（生成图不满足极几何） | 致命 | 用 NeuS 非 MVS；SMPL 作几何锚点；增视角数（24-36 帧 orbit） |
| 动作不一致（肌肉形变/衣物褶皱跨视角漂移） | 高 | 骨骼深度图精确匹配 SMPL；投影校验剔除 |
| 背面/遮挡区域幻觉 | 中 | 生成视角足够多；重建后 SMPL 几何 refinement |
| Flux ControlNet(depth) 可控性不足 | 中 | Round 1 先验证；备选 InstantX/xlabs ControlNet |
| NeuS 对生成图像噪声仍敏感 | 中 | 调 σ_init；必要时加 SMPL 几何先验正则 |

## 8. 与视频生成扩展的衔接

**共享模块**（图像/视频阶段复用，下沉到独立脚本）：
- `sam_3d_body/`（SMPL 提取）— 已建
- 骨骼深度图渲染脚本
- 参考帧提取逻辑
- NeuS 重建脚本

**扩展时只换生成端**：Flux1 → Wan2.2-I2V + 视频 ControlNet(depth) + MotionCtrl（相机轨迹控制）。视频生成的 temporal attention 提供"免费"跨视角一致性约束。

## 9. 目录结构与脚本规划（按 AGENTS.md 规范）

```
media_code/
├── sam_3d_body/              # 已建：SMPL 提取（共享，两阶段复用）
└── flux_human/               # 新建：图像生成路线
    ├── _env.sh
    ├── 00_setup_env.sh       # clone Flux 官方仓 + 装 ControlNet/IP-Adapter 依赖
    ├── 01_download_models.sh # 下 Flux1-dev + ControlNet(depth) + IP-Adapter 权重
    ├── 02_extract_smpl.sh    # 调 sam_3d_body 抽 SMPL + 找静止参考帧 T*
    ├── 03_render_depth.sh    # 用 T* 的 SMPL 渲染 N 视角骨骼深度图
    ├── 04_generate_views.sh   # Flux + ControlNet + IP-Adapter 生成多视角
    ├── 05_reconstruct.sh     # NeuS 重建 + 导出 mesh
    ├── 06_evaluate.sh        # 与 PIFuHD/GT 对比 Chamfer/F-score
    ├── run_all.sh
    ├── extract_smpl.py       # 读 sam_3d_body npz + 选 T*
    ├── render_depth.py       # pyrender 渲染骨骼深度图
    ├── generate_views.py     # Flux 推理
    ├── reconstruct.py        # NeuS 调用
    └── evaluate.py           # 指标计算
```

**跨 env 衔接**：`sam_3d_body` 是专用 env（detectron2 pin 冲突），`flux_human` 用独立 env。`02_extract_smpl.sh` 用 `conda run -n sam_3d_body` 跨 env 调用 sam_3d_body 推理，输出 npz 到共享目录，后续步骤在 flux_human env 读 npz。

## 10. 待确认问题（影响选型）

1. **Flux1 版本**：dev（高质量、慢）还是 schnell（快）？ControlNet(depth) 用 xlabs 还是 InstantX 实现？
2. **NeuS 实现**：Instant-NSR（快、neurstudio 系）还是 NeuS 官方？
3. **GT mesh**：有没有真实人体 mesh 作 ground truth？没有就只能跟 PIFuHD 比。
4. **测试素材**：用现成视频还是有指定拍摄视频？人体类型（全身/半身）？
5. **PIFuHD 基线**：是否已建？没有的话要不要新建 `pifu_hd/` 算法目录跑基线？
