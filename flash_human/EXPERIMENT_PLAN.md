## 0. 背景与结论先行

**问题**:前馈重建(VGGT-Ω/DA3)快、三维一致,但细节糊;视频生成模型(H3)细节精致,但跨视角不一致。FlashWorld(arXiv 2510.13678)证明了"质量源与一致源分离 + 渲染在环 + 少步蒸馏"配方成立(单场景 4~9s 出 3DGS)。

**核心方法论修正(本路线成立的前提)**:FlashWorld 用 DMD 蒸馏是因为场景级高质量多视角数据稀缺。**本机有几十个高精度人物模型 = 手里有真 GT,可以渲染任意轨迹的监督数据,直接监督训练,跳过蒸馏**(DMD 三网络 + GAN 调参 + 教师上限约束全部绕开)。蒸馏是没数据时的代偿,留作第二阶段以后的备选。

**与台账 HAND_MOTION_LEDGER 的关系(关键,防误判为重复)**:
- 台账 L5 已证伪的是「**per-scene 光度优化**侧提锐度」:改目标函数三路全负、HYPIR 增强图喂训练无效(flame_human 09-11)。
- 本路线打 L5 的**新机制**:不是 per-scene 光度优化,而是「**渲染 GT 监督训练前馈人像 GS 解码器**」。L5 的本质是欠定优化主动选平滑解;监督学习在有真 GT(渲染资产)时不欠定,理论上不受 L5 平滑偏好约束。【推测】此推断未经实测,是阶段 0/2 要验证的核心假设之一。
- 台账"HYPIR 贴输出有效"的经验直接纳入阶段 1 作为对照组(见 §5)。

**结论**:三阶段推进。阶段 0(冒烟+基线校准)零训练、本周可跑;阶段 1(增强策略对比)验证"质量源放哪";阶段 2(前馈监督训练)才是真正的研究工作量。每阶段设决策门,不达标不进入下一阶段。

## 2. 与既有路线的关系(防重复登记)

| 既有路线 | 它做了什么 | 本路线的差异 |
|---|---|---|
| `artifixer/` | per-scene:稀疏重建 → 扩散校正 → 3D 蒸馏 | 本路线是**人像域前馈** + **渲染 GT 直接监督**,不做 per-scene 扩散校正链;artifixer 在阶段 1 当对照组而非被替代 |
| `flux_human/` | SMPL+骨骼深度 → Flux ControlNet 生成多视角静止图 → 无模糊重建 | 本路线用 H3 Ref2VA 参考锁身份 + GS 像素对齐解码器;两路线可在阶段 1 做生成源对比 |
| `da3_human/` | scene_gs 的 DA3+2DGS per-scene 方案 | 直接复用其管线与评测协议;分工:da3_human 管场景,flash_human 管人 |
| 台账 L1(表示容量) | 加高斯点数救细节 ❌ 已证伪 | 本路线不靠加点数,靠监督数据的高频 GT |
| 台账 L3(光度学运动) | 靠光度梯度学运动 ❌ 已证伪 | 本路线不学运动;固定表情/静态假设与之一致 |
| 台账 L5(优化目标平滑) | per-scene 3D 侧提锐 ❌ 已证伪 | 机制差异见 §0:【推测】监督学习不欠定,不受 L5 约束——**这是本路线最核心的待证假设** |

## 4. 阶段 0:冒烟测试与基线校准(零训练,目标 1~2 周)

### 4.1 数据工厂(本阶段唯一新建基础设施)

| 脚本 | 内容 |
|---|---|
| `_env.sh` | 共享环境:路径(资产根/输出根)、conda env、代理 |
| `00_setup_env.sh` / `00a_setup_env.sh` | 服务器 / WSL 建 env |
| `01_render_gt.py` | 高精度人物模型 → 相机轨迹(环绕+微仰俯+半身/特写两档)→ 渲染 RGB+深度+法线+内外参;**域随机化开关**:HDR 环境光/曝光/模糊/噪声(默认开) |
| `01b_make_lowq.py` | GT → 低质化模拟实拍输入(压缩/运动模糊/降采样),制造"前馈输入" |

**资产选择**:从几十个模型选 3~5 个代表性资产(不同发型/是否戴眼镜/毛发材质)。**先确认资产格式**(mesh+纹理 or GS)再写 01 脚本。

### 4.2 三条基线

| 脚本 | 内容 | 回答的问题 |
|---|---|---|
| `02_run_vggt_omega.sh` | 调用 `../vggt-omega/` 对低质输入推理 → 点云+位姿+深度;3090 显存/耗时落盘 | Ω 人脸几何精度?动态(转头/微表情)行为如何【台账 L2 相关】 |
| `03_run_flashworld.sh` | 单图 → 场景 GS(调 media_paper 笔记 §12 推理参数) | 人脸特写 scale 是否崩(笔记标过【待核实】) |
| `04_run_photometric_gs.sh` | 复用 `../vggt_human/` 管线:Ω 位姿 + 光度优化 head_gs | 当前 pipeline 质量上限(台账已有部分数据,补齐渲染 GT 上的口径) |

### 4.3 产出与决策门 G0

- `05_quality_gap_report.py`:人脸区域(检测框 crop)PSNR/LPIPS/**锐度保留率(沿用台账口径)** + 深度 MAE + 位姿误差;误差热力图分区域出图。
- **G0 通过条件**:缺口报告明确指出最大短板环节(位姿漂移 / 几何 / 纹理)。若"纹理糊"占比最大 → 进阶段 1;若位姿/几何是主因 → 回 da3_human/vggt_human 修结构,本路线暂停。

## 5. 阶段 1:增强策略对比(轻训练,目标 2~4 周)

在 G0 确认"纹理糊是主因"后,同一份数据同口径对比四策:

| 脚本 | 策略 | 机制 | 台账依据 |
|---|---|---|---|
| `06_enhance_2d_post.sh` | 渲染输出 → HYPIR/OSEDiff 逐帧增强(**贴输出**) | 2D 后处理,不追求跨视角一致 | L5:贴输出已验证有效 |
| `07_artifixer_baseline.sh` | 调 `../artifixer/` per-scene 扩散校正链 | 现成对照组 | — |
| `08a_h3_enhance_post.sh` | 渲染输出 → H3(Ref2VA 参考锁身份)增强 → 贴输出 | 生成式 2D 后处理 | 新增:验证 H3 教师价值 |
| `08b_h3_enhance_backprop.py` | 渲染 → H3 增强 → **反传 UV 高斯纹理**(冻结几何) | FlashWorld 式闭环 | ⚠️ 台账 L5 证据(HYPIR 喂训练无效)提示成功率低,**预期放低,当负结果预案设计** |

**评测补充**:四策全部加测**跨视角重投影一致性**(视角 A 增强图 warp 到 B 与 B 增强图的结构相似度)——2D 后处理路线的已知短板,这是与台账旧实验相比新增的度量维度。

**决策门 G1**:若 06/08a(贴输出)已满足质量目标且重投影一致性可接受 → **直接采用贴输出路线,跳过阶段 2 的反传方向**,阶段 2 只做前馈化提速;若贴输出跨视角闪烁严重 → 阶段 2 的前馈监督训练成为主路线。

## 6. 阶段 2:前馈人像 GS 监督训练(研究主体,目标 2~3 个月)

前置:G1 判定需要"3D 一致的细节"才进本阶段。

| 脚本 | 内容 |
|---|---|
| `09_scale_data_factory.sh` | 资产工厂放量:域随机化(光照/材质/肤色/发型/姿态)× 轨迹采样 → 渲染 GT 数据集(规模视显存与训练预算定,先 1~2 万序列) |
| `10_train_feedforward_gs.py` | 结构照 FlashWorld 像素对齐 GS 解码器(media_paper 笔记 §12 已源码核实:Wan VAE decoder 深拷贝改造、每像素 2 高斯、SH degree 2);backbone 冻结 VGGT-Ω 特征;**直接监督:GS 参数回归 + 渲染 L2(对渲染 GT)**;无 DMD、无 GAN |
| `11_eval_feedforward.sh` | 渲染测试集 + 实拍测试集(vggt_human 棚拍数据)双口径评测 |

**三个核心待证假设**(逐个出结论,允许负结果入库台账):
1. 【推测→待证】渲染 GT 监督训练的前馈解码器,锐度保留率显著高于 per-scene 光度优化(绕开 L5);
2. 【推测→待证】域随机化 + 实拍混合微调能兜住渲染→实拍域差;
3. 【待核实】冻结 Ω backbone 的特征粒度足以支撑脸部高频(Ω 人脸特写几何精度无专项验证)。

**决策门 G2**:O3 验收通过 → O4 提速(少步蒸馏 / 离线增强造伪 GT 训快速学生 / LoRA 微调路径,三选一按当时生态定)。

## 8. 评测协议(沿用并扩展台账口径)
