## 99e 解封装脚本：MP4 → PLY（单样例，0d0e5a9..）
- 需求: 99b 正向四步的严格镜像，**单样例、不批量、始终走 demux**（用户明确）。
  反向工具链: demuxer.py / build/gltf_unpacker / decode.py（服务器上，本机没有）。
- 分 4 块写 + 逐块 commit: 骨架 → 路径解析+PROBE → unpack_one → main。
- 布局: 输入 <批次>/mp4/<task>.mp4 → 输出 <批次>/unpack_ply/<task>.ply；
  中间产物 <批次>/unpack_work/<task>/（GLB/bin/视频/三件套 json，KEEP_WORK 默认 1）。
  孤立 MP4（别人给的成品）以其所在目录为批次根。
- 三工具 CLI 未读源码 → 设计: 默认镜像参数 + `PROBE=1` 打印 usage +
  DEMUX_ARGS/UNPACK_ARGS/DECODE_ARGS 完整模板覆盖（占位符 {mp4}{glb}{video}/
  {glb}{bin}{init}{camera}{view}{outdir}/{bin}{ply}{outdir}），改参不用改脚本。
- decode 输出 PLY 名未知 → 先记 work 下既有 ply，跑完按 mtime 找**本次新产出**
  并重命名为 <task>.ply（避免捡到上一轮残留）。
- ⚠️ 踩坑: build_args 若「先 format 再 shlex.split」，Windows 路径反斜杠会被当
  转义符吃掉（C://a//b → C:ab）。改为**先 split 模板、再逐 token 代入**，顺带
  支持含空格路径不被二次拆开。服务器 Linux 路径本来不受影响，但是隐患。
- 自测 7 组全过（桩工具链 + monkeypatch run_cmd）: 路径推导(2)/模板覆盖/三步全链/
  skip/FORCE/DRY_RUN/Step1 失败/bin 块大小 glob 兜底/无 PLY 失败。py_compile 通过。
- 待服务器验证: ①三个工具真实参数名（先 PROBE=1）；②反向 view_limits json 必残缺
  （六项白名单，NOTES 第 9 条）；③PLY 是否位级无损（encode 若含量化则有偏差）。
