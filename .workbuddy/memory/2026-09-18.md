## 讨论：环绕视频（含人物微动）→ 高精度无重影 3D 模型的路线选型

**性质**：grill-me 式方案讨论，**未定案**，无正式方案文档（峰哥明确只要日志记录）。
**缘起**：昨天 SHARP 单图复现效果不错但只有单视角可看，峰哥提出两个设想 ——
(1) 用 3 张或更多环绕图跑 SHARP 拼接出完整模型；(2) 或用视频生成模型（本地有 minimax_h3）做"人物静止化"再重建。核心顾虑是人物微动导致多视角不一致。

### 一、查证到的硬事实（都做过实测/读原文，可回溯）

**关于数据**（`/mnt/d/dataset/测试数据sample/3fe0604320a24d66a8bde164edf18c11`）
- **125 张** HEIC（`image/`）+ 对应 JPG（`image_jpg/`，vggt_human 01b 转过），另有 `pcd.ply`、`transforms.json`
- `transforms.json` 是完整 nerfstudio 格式：**125 帧全带 `transform_matrix`**（4×4 c2w）+ 逐帧内参（w/h/cx/cy/fl_x/fl_y）→ **位姿齐全，可直接复用**
- 文件名是纳秒级单调时钟：**总跨度 13.3 秒，相邻间隔中位 ≈100ms** → 判断**像是 10fps 视频抽帧**（待峰哥确认原始视频是否还在）
- ⚠️ **125 张全部无 EXIF 焦距**（连原始 HEIC 也没有，逐张探 FocalLength/41989 均 None）→ SHARP 一律 30mm 兜底

**关于 SHARP**
- `src/sharp/cli/predict.py` 收到目录时是 **`for image_path in image_paths:` 逐图独立前馈**，每张单独 `predict_image()` → 各存 `<stem>.ply`，**无任何跨视角联合约束**
- 输出在**各自相机坐标系**（README 原文 "scene center is roughly at (0, 0, +z)"，OpenCV 约定），**SHARP 不输出位姿**
- 拼接路线的量化障碍：125 × 1,179,648 = **1.47 亿高斯 / ≈8.2 GB**，且重叠区需自写"谁说了算"的裁决机制 —— 而那就是多视角一致性优化本身

**关于 minimax_h3**（`minimax_h3/README_wsl.md`）
- 第 55 行原文：⚠️ **当前 06b/06c/06d 都出噪点（彩色方块，根因待查）…暂无可用生成路径**
- 3090 能跑 06c/06d（int8 + block offload，权重压到 ~62GB + 56GB RAM），但**产不出可用视频**
- 能力是 **T2VA / FL2VA / Ref2VA（生成）**，**不是 vid2vid 视频编辑** → 无法"输入视频 → 改写视频"

**关于已有项目**
- `pdfgs_human`：定位与本次需求**逐字对应**（"真实环绕拍摄的人物图像 → 滤除微动 → 干净的静态人体重建"）。核心=`progressive distractor filtering`（DINOv3 特征 cosine 相似度判 distractor，逐 phase 收紧 0.6/0.7/0.8）。**Step 02 支持视频抽帧**（`FRAME_FPS=10` / `FRAME_MAX=60`）
  - 其 README 第 9 行：核心假设是**干扰像素"稀疏离群"**
  - 其 README 第 13 行已论证：合成视频的不一致是**弥散**的（遍布全身细节），不满足稀疏离群假设
  - 其 README 第 84 行：白底分割会导致"放射状白色翅膀"伪影（另一个已知问题）
- `flux_human/技术方案.md`：**已规划**本条视频扩展路线（第 8 节：Flux1 → Wan2.2-I2V + 视频 ControlNet(depth) + MotionCtrl）
  - 关键设计：**先定静止姿态**（选动作速度最小的参考帧 T\* → 抽 SMPL → 渲染各目标视角骨骼深度图 → ControlNet 逼模型照画），即**显式几何锚定**，而非指望模型自己"变静止"
  - 第 9 行的判定标准：图像版重建质量 < 单图基线 → 思路有问题；≥ → 再扩展视频

### 二、已达成的决策（分支 1：目标与验收）

| 项 | 结论 |
|---|---|
| 覆盖范围 | **不需要 360°**，只需 125 张环绕图覆盖的范围内效果好 |
| 评测相机 | **环绕轨迹上任意连续角度（含插值）+ 一部分外插**（如俯仰 ±5°） |
| hold-out | **每 5 张抽 1 张**（约 25 张完全不参与重建） |
| 根本目的 | 从有微动的环绕视频重建**高精度、无重影**的 3D 模型；"静止化"只是手段 |

### 三、讨论中建立的判断（供下次接续，非定案）

1. **SHARP 不适合当"重建器"**：逐图独立 + 无位姿 + 无融合机制，在你的验收口径（含插值视角）下必然层叠/重影。只适合当**先验**（初始化 或 逐视角监督）。
2. **"静止"是 3D 概念，2D 视频模型无法定义它**：它要求所有视角的人物处于**同一世界姿态**；视频扩散最多做到"相邻帧看起来变化小"，不知道"转过 30° 后同一姿态该长什么样"。让模型自由发挥 → 抖动少了但**跨视角仍各画各的**，且失败原因从"真实微动"变成"生成幻觉"，更难诊断。
3. **三种解法谱系**（微动场景下"去重影 = 高精度"是同一问题的两面）：
   - **A 保留真实 + 滤除运动**（pdfgs_human）— 不引入幻觉，失败模式可诊断，成本最低
   - **B 显式建模运动**（动态高斯 / 4D）— 工程量大，需时间同步
   - **C 生成内容替换观测**（flux_human / SHARP 拼接）— 风险最高，无真值锚点
   - 我的推荐：**先确认 A 的基线**，它的失败模式会指出该往 B 还是 C 走
4. **若走 C，必须显式姿态锚定**（flux_human 第 8 节的 T\* → SMPL → 骨骼深度图 → ControlNet 那条），而不是让生成模型"自己静止化"。锚点可与 SHARP 几何合并成同一先验。

1. **`pdfgs_human` 在这类数据上跑过吗？结果具体差在哪？** 三种可能对应完全不同的分叉：
   - 没跑过 → 先跑基线（已有实现 + 现成 `transforms.json` 位姿，成本最低）
   - 跑过但重影仍在 → 可能微动幅度超出"稀疏离群"假设 → 才轮到 B/C
   - 跑过但有白色翅膀/边缘伪影 → 是白底分割问题，与微动无关
2. **这批数据的微动幅度属于哪一档**：呼吸级微动 / 手臂摆动 / "东张西望"级大幅运动？

3. **125 张是否来自一段原始视频？原始视频是否还在？**（若是视频，pdfgs/A 路线可直接吃视频抽帧）

### 形成的判断（非定案）

1. **能写，但不能按「用了 HYPIR 做人脸增强」写** —— 那属现有技术应用，必被驳。
2. **按可专利性分四层**（模型层 / 集成层 / 一致性机制层 / 调度层），价值集中在后两层：
   - **一致性机制层**（有实现、可立即写）：羽化融合（54px 二次衰减）+ 跨帧噪声对齐（每帧重设 seed，配合 `affine_l2s` scale_exp=1.25 使五官在 crop 内对齐）+ 增强图以真实相机位姿注册为完整训练视角 + 频域去红润（小波高频子带 per-channel DC 校正）。
   - **调度层**（未实现、价值最高）：3D 一致增强掩码（`DESIGN_face_pipeline.md` 第 11 节未决项 5 已识别缺陷：逐帧 2D bbox 导致同一 3D 点跨视角落在增强区内外）+ 自适应触发替代固定 `epoch=48` + 幻觉监控与回滚（第 10 节已指出「后 12 epoch 人脸区全是伪 GT，无回滚」）。
3. **「反直觉发现」是创造性的核心素材**（对应审查指南 6.4 新增的「克服技术偏见」）：`EXPERIMENTS.md` L78-103 的 **masked-L1 无效（+4.04% vs +3.98%，噪声内）vs 整视角注入有效（LPIPS 0.305→0.260 等）** —— 这个对比正好是「克服技术偏见」的形态，应写入权利要求。

### 产出：方向① 技术方案草稿（当日完成）

**文件**：`vggt_human/PATENT_3d_consistent_face_enhance.md`（新建）
**发明名称（建议）**：一种基于多视角一致性投票的三维重建人脸增强区域确定方法

**核心构思**：把增强区域的判定从「二维图像域、逐帧独立」前移到「三维场景域、多视角联合」——
为每个三维元素算一个**固有的**增强置信度 c_i，再投影光栅化为逐视角权重图。因 c_i 是三维元素的
属性而非视角的属性，投影后天然跨视角一致。

**关键代码发现（本次阅读确认，可复用）**：
- `face_center_3d.py:241-263` 已实现**逐元素多视角命中计数**，但求质心后**把计数丢弃了** —— 本方案
  只需保留它即得置信度场（`face_center_3d.py:276-309` 的深度带过滤也可直接复用）。
- `render_closeup.py:571-587` 的 `load_head_gs()` + `:462-472` 已能用 **SH 颜色 hack** 渲染出头部
  **几何软掩码**（`.alpha.png`），可作为「各视角语义区域证据」，完全不依赖图像域检测。
- `face_enhance.py:42-44`/`:435-437` 记录了**现有技术缺陷的直接证据**：后处理时对**渲染图**做
  MediaPipe 检测，渲染图糊时检不出，只能退化为固定中心框兜底。本方案取消该检测 → 缺陷三论证有力。
- `face_metrics.py:69-88`（Laplacian/梯度能量）、`diag_boundary.py:42-62`（腐蚀掩码重算 PSNR）
  是现成的效果验证工具。

**方案的四个技术手段（写入权利要求的候选）**：① 置信度累计分母取**可见视角数**而非全部视角数；
② 视角权重 ω_v 按表面法向与视线夹角降权（掠射角不可靠）；③ z-buffer 深度排序光栅化；
④ 以 c_i 同时调制增强强度（空间非均匀），不止做融合权重。

**对照最接近现有技术 CN122289572A 的区别点**：该文件的多视角一致性优化作用于**损失函数层面**
（约束已增强结果）；本方案作用于**增强信号产生之前的区域判定层面**，解决的是上游的
「增强区域自身不一致」，两者问题不同。

**文档中已标注的诚实边界**：§3.2 五项量化效果除「检测失败帧占比」外**均标注为预期方向、尚未实测**，
明示不得在说明书中写入无依据数值；§6.1 明示是公开库快查、**不构成新颖性检索结论**。

## 代码：vggt_human/99f 批量收集 ply + 相机参数（完成，已提交 90de32c）

**文件**：`vggt_human/99f_collect_ply_and_camera.py`（新建，177 行）
**功能**：按 99a 的预设路径扫批次根目录，把每个 task 子目录下的
`point_cloud_final.ply` + `gs_camera_params_final.json` 成对复制为
`point_cloud.ply` / `gs_camera_params.json`，落到 `<批次>/ply_gs/<task_id>/` 下。

**与 99a 的差别**（有意为之，非疏漏）：
- 99a 输出**压平**成 `<批次>/ply/<task_id>.ply`；99f 保留 task 目录层级、带相机参数（下游按目录整体加载）
- 99f **两个文件要么全复制要么跳过**：缺任一即 skip（避免下游拿到没相机参数的半成品）
- 新增 env 覆盖：`SRC_ROOT` / `RESULTS_ROOT` / `OUT_DIR` / `PLY_NAME` / `GS_NAME` / `PLY_OUT_NAME` / `GS_OUT_NAME` / `ONLY` / `DRY_RUN`

**实测**（TEMP 下造假批次：taskA 齐全、taskB 只有 ply、taskC 齐全）：
三种模式（DRY_RUN / 正常 / ONLY=taskB,taskC）行为均正确 —— taskB 被 skip 且打印缺哪个文件，
输出树为 `out/ply_gs/{taskA,taskC}/{point_cloud.ply, gs_camera_params.json}`，无多余产物。
