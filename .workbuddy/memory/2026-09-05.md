## HYPIR 提速三项（cd1d8ee）—— 优化点 1 的缺口补上
- 实测（3090 / 512²）：base 170ms → +cache_text 161 → +merge_lora 139 → +compile 130 ms/张
- **merge_lora 默认开**：257 层；peft 用 inject_adapter_in_model 无 merge_and_unload，需逐层
  `LoraLayer.merge()`；forward 有 `elif self.merged` 分支不会重复叠加。漂移 0.35/255
- **cache_text 默认开**：monkey patch `prepare_inputs`；text_encoder 确定性不耗 RNG → 逐位不变
- **compile 默认 auto（回本线 2400 张）**：增量仅 12ms/张 vs 一次性编译 28s → ~2300 张回本，
  小批量编译净亏
- **关键坑**：diffusers `Attention.forward` 的 `inspect.signature(self.processor.__call__)` 让
  dynamo 按 block 加 processor id guard，默认 cache_size_limit=8 撑爆后退回 eager+开销 →
  **175ms 变 1687ms（慢 10 倍）**；已把 limit 抬到 64 写进 compile_unet()
- **A/B 方法论坑**：`vae.encode().latent_dist.sample()` 按调用序号取随机样本 → 相邻两次前向
  差 mean|Δ|≈0.011。对比必须**对齐调用序号**（跑两次完整脚本比同名图），同序号逐位可复现
