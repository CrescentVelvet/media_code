### 近景相机废片根因彻底定位（不是 SAM3 检测问题）
**核心发现**：72/72 近景视角几何余量 margin = half_FOV - (|pitch| + face_angular_radius) 全部为负（-3.7°~-8.8°），即每个视角人脸都必然偏出画面。

**根因链（相机几何设计缺陷，非检测问题）**：
1. `compute_closeup_pose` 推进到 MIN_DIST_RATIO=0.3（很近），让人脸角半径 face_ang=atan(r_face/dist) 很大（p00 达 46°）
2. `apply_pitch` 绕右向轴公转位置 ±10°，look-at 重算朝向保证 face_center 在光轴中心——但只保证"点"在中心，不保证"人脸整体"在画面内
3. CLOSEUP_SIZE 模式 fx = FACE_FILL(0.8) × (S/2) × d / r_face：FACE_FILL=0.8 设计上让人脸占半边长 80%，pitch=0 时刚好，pitch ±10° 一加 80% 占比的人脸必然有一部分甩出画面（没给 pitch 留余量）
4. **sanity check 完全失效**：`face_offset_px` 72/72 全是 0.0。因为 look_at_rotmat 的数学性质——forward=(target-C)/|target-C|，target 在相机系下必为 (0,0,dist)，反投影必落 (cx,cy)。这个"sanity check"检查的是 look-at 算法自身的数学性质（target 必在光轴），不是"人脸是否在画面里"，从设计上就是 no-op，永远报 ✅，永远不过滤。

**SAM3 检测本身可信**（不是根因）：
- face_center sanity: p1=93.8%/10.5px（最好）, p2=81.2%/43.5px, p0=55.6%/88.8px, p3=21.2%/44.8px(仅271点)
- 但废片率和 sanity 不相关：p1 sanity 最好但废片率最高(14/18)，p0 sanity 最差但废片率中等(4/18) → 证明根因是相机几何不是检测
- SAM3 mask → face_center_3d 算 3D 中心这一步基本 OK（p1/p2），问题在下游 render_closeup 的近景推进+pitch 外插

**修复方向**：
- 治本：CLOSEUP_SIZE 模式下 FACE_FILL 从 0.8 降到 0.5-0.6（给人脸留 pitch 余量），或 pitch 从 ±10° 降到 ±5°，或 MIN_DIST_RATIO 从 0.3 提到 0.5
- sanity check 要改：不能只查 face_center 点偏移（永远 0），要查人脸边缘（face_center ± r_face 各方向）是否在画面内
- 治标（F0）：inject 阶段 skin_frac<0.10 过滤（之前已定）

### 近景废片终极根因（推翻"外插渲染失败"结论，用户再次纠偏）

**用户质疑**：有些外插视角歪得很离谱根本没对准人脸，不是灰色噪声——是对的。

**真正根因：look_at_rotmat 的 R 约定与 3DGS/COLMAP 相反（+Z forward vs -Z forward）**

**证据链**：
1. `look_at_rotmat` 注释写"COLMAP 相机系: +X右 +Y下 +Z前(朝场景)，R 三行=[right;down;forward]"——这是 +Z forward 约定
2. 但 COLMAP/3DGS 标准是 -Z forward（R[2,:]=-forward，相机看 -Z 方向）
3. `render_closeup.py:421-424` 传 `R=R.T` 给 3DGS Camera，注释说"存的R是COLMAP w2c"——但实际存的是 +Z forward 的 R，不是标准 COLMAP w2c
4. 验证：06c 所有 18 个 closeup 的 `cos(R[2,:], to_face)=1.000`（forward 指向 face_center），但 `cos(-R[2,:], to_face)=-1.000`（COLMAP 标准 forward 远离 face_center）
5. 3DGS 按 -Z forward 解释这个 R → 相机实际朝向 = 设计意图的反方向 → face_center 在相机背后 → 渲染的是相机背后的东西（背景/空高斯）

**为什么有些图好有些图废**：
- 好图：相机背后恰好有其他人脸高斯或身体高斯，渲染出的虽不是目标人脸但看起来像人
- 废片：相机背后是背景/空区域，渲染出灰色噪声或纯背景
- 这解释了"非空像素质心在中心但 skin=0"——相机对准了画面中心（look-at 数学正确），但 3DGS 朝反方向渲染

**修复**：look_at_rotmat 的 R 应改为 COLMAP 标准 -Z forward：`R = np.stack([right, down, -forward], axis=0)`，或在传给 3DGS 前取 R 的第三行取反。改完所有 closeup 会真正朝向 face_center 渲染。

**历史背景**：09-03 曾诊断 face_center 偏离真人（F 在背景墙 z=0.891），09-04 加深度过滤修复部分，但 sanity 仍低（p0=55.6% p3=21.2%）。本次发现的是更底层的 R 约定 bug，与 face_center 精度无关——即便 face_center 完全正确，R 约定反了相机也会朝反方向渲染。

### R 约定 bug 修复 + 测试通过（本轮完成）

**修复**（`render_closeup.py` `look_at_rotmat`）：
- 旧：`R = np.stack([right, down, forward], axis=0)`，`down = cross(forward, right)` —— +Z forward，与 COLMAP 相反
- 新：`R = np.stack([right, down, back], axis=0)`，`back = -forward`，`down = cross(right, forward)` —— COLMAP 标准 -Z forward
- 注：down 的叉积顺序也要改（`cross(forward,right)` → `cross(right,forward)`），否则 +Y down 方向反了；只改 Z 行不够

**sanity check 同步修复**（`run_pipeline` 第 567-588 行）：
- 旧：`if Pc[2] <= 0`（+Z forward 下前方 z>0）—— 但 R 约定反了，这个判断永远误报
- 新：`depth = -Pc[2]; if depth <= 0`（COLMAP -Z forward，前方 z<0，深度=-z）
- 投影公式 `u = fx * Pc[0] / depth`（用 depth 而非 Pc[2]）

**测试**（新增 `vggt_human/test_look_at.py`，纯 numpy，8 个用例全过）：
- T1 标准 look-at `C=(0,0,5)→origin` → R=单位阵（旧代码会得 R[2,2]=-1）
- T2 反向 `C=(0,0,-5)→origin` → R[2,2]=-1
- T3 任意位姿 face_center 反投影 offset≈0（look-at 数学性质）
- T4 COLMAP 一致性：face_center 在相机系 z 恒<0
- T5 右手系：right×down=back，det(R)=+1
- T6 pitch 公转后仍朝 face_center
- T7 `R @ fwd_world = (0,0,-1)`（forward 在相机系是 -Z）
- T8 `R.T` 作为 camera→world，前方点 (0,0,-1) 经 R.T 指向 target（验证 render_views 传 R=R.T 给 3DGS 正确）
