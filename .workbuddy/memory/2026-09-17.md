### CLI 参数（从 `src/sharp/cli/predict.py` 原文读出，非二手）

`sharp predict -i <文件或目录> -o <输出目录> -c <ckpt> [--render] [--device cpu|cuda|mps] [-v]`
- 输入是目录时递归 glob 支持的图像格式
- 输出 `<stem>.ply`；`--render` 时额外 `<stem>.mp4`（**仅 CUDA**，非 CUDA 会 warning 并自动关掉）

## 当日执行记录：00a → 02 全链路跑通（峰哥让跑环境）

### 踩到 3 个坑，全部已修并固化进脚本

**坑 1（阻断性）：`requirements.txt` 里的 `-e .` 按 cwd 解析**
- 现象：`00a` 第 9 步报 `ERROR: file:///mnt/c/code/media_code ... does not appear to be a Python
  project: neither 'setup.py' nor 'pyproject.toml' found` → `❌ requirements 安装失败`
- 根因：`requirements.txt` 第 3 行是 `-e .`（相对路径），pip 按**当前工作目录**解析它。
  脚本在 `/mnt/c/code/media_code` 下执行 `pip install -r $SHARP_DIR/requirements.txt`，
  于是 pip 去找媒体仓的 pyproject.toml。
- 放大效应：pip 是**全量解析通过后才开始安装**，所以这一步一失败 → 前面已解出的
  gsplat/timm/numpy/scipy 等**一个都没装**（torch 是第 6 步单独装的，所以活着）。
- 修：`( cd "$SHARP_DIR" && pip install "${PIP_FLAGS[@]}" -r requirements.txt )`

**坑 2（阻断性）：conda CUDA 头文件布局与 torch JIT 不匹配**
- 现象：`--render` 时 gsplat JIT 编译失败，最终报
  `ninja: build stopped: subcommand failed`，真实错误埋在 427KB 的 glm warning 里：
  `torch/include/c10/cuda/CUDAStream.h:3:10: fatal error: cuda_runtime_api.h: No such file or directory`
- 根因：conda 的 `cuda-toolkit`（label `nvidia/label/cuda-12.8.0`）把头文件放在
  `$CONDA_PREFIX/targets/x86_64-linux/include`；而 torch 的 `cpp_extension` 只加
  `-isystem $CUDA_HOME/include`（= `$CONDA_PREFIX/include`）。两边对不上 → 找不到头。
  证据：全日志 `grep -c "targets/x86_64-linux/include"` = **0**（编译命令里根本没这个路径）。
- 修：`00a` 新增第 7b 步，把 targets include 下**缺失**的条目软链接进 `$CONDA_PREFIX/include`
  （不覆盖已有：实测 linked=189, skipped=1）。修完 JIT 编译成功，输出
  `gsplat: CUDA extension has been set up successfully in 113.29 seconds.`
- ⚠️ 这条对本仓其它要用 torch JIT 扩展的项目同样适用（vggt_human 没踩到是因为它用
  `nvidia/label/cuda-12.1.1` + 自己 setup.py 的 include 处理，且 gcc 编译路径不同）。

**坑 3（非阻断）：`02` 脚本退出码被最后一行带成 1**
- `[ "$RENDER" = "1" ] && echo ...` 在 RENDER!=1 时返回 1 → 整个脚本 exit 1，
  明明成功却让调用方以为失败。改成 `if ... then ... fi`。
