1. 旧 `views/target/geometry` 在赋值瞬间才释放，新 8 视角先建；

## ⚠️ 服务器与本机曾分叉成两条历史线（11-16 已合并）

`git commit` 会把服务器那 4 个提交的成果**全部回滚**——`11_gpu_monitor.py` 从

1. 备份 6 文件到 `/tmp/srv_backup_20261116/`；
2. `git checkout --` 把服务器工作区还原到 HEAD（丢掉被覆盖的假改动）；
3. 本机 `git bundle create 9abca99..HEAD` → scp → `git fetch` 成临时分支；
4. `git merge` 后**仅 `11_gpu_monitor.py` 冲突**（本机只改注释 15 增 21 删、无函数增删，

5. 双向 `git bundle` 同步，本机 `--ff-only` 快进到同一提交。

**结论**：`canada_h100/` 五文件本机与服务器 md5 现完全一致，训练脚本未受影响

## 执行位不随 git 传播（`core.fileMode=false` 的代价）

**现象**：服务器上 `./11_gpu_monitor.py` 报 `bash: ./11_gpu_monitor.py: Permission denied`，
文件是 `-rw-rw----`（644）。本机同文件是 `-rwxr-xr-x`，但 `git ls-files -s` 两边都是
`100644`——因为两边都设了 `core.fileMode=false`（AGENTS.md §11 要求，避免 `chmod` 造
假 mode change 导致 pull 冲突）。**代价就是执行位完全不随 git 走**：新 clone、跨落点
同步后脚本一律没有 `x`。

**修法（已执行）**：
1. 服务器 `chmod +x canada_h100/*.sh *.py` 立即恢复；
2. 装 `.git/hooks/fixperm` + `post-checkout` / `post-merge` / `post-rewrite` 三个触发点，
   pull/checkout/rebase 后自动给带 shebang 的 `.sh`/`.py` 补 `x`，以后不用手工 chmod；
   **`post-rewrite` 的 stdin 必须先 `cat >/dev/null`**，否则子进程写 EPIPE。
   钩子在 `.git/hooks/` 里不入库，换新 clone 要重装（步骤写进 README 坑 4）。
3. README 加「坑 4」记录成因与重装方法（提交 `507227f`）。

**验证**：`chmod -x` 后手工跑一次钩子，两个文件都自动回到 `-rwxrwx--x`；监控 `--once`
正常输出 QUEUE + DCGM；训练作业 `201369781` 未受影响，step 81240、1.2s/step、两 rank loss 均在降。
