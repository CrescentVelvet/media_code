## canada_h100：8 卡 DDP 训练 OOM 崩溃与修复（续训进行中）

**事实**：作业 `201366403` 在 **11-15 18:03:06** 崩于 rank2，`torch.OutOfMemoryError`
（`gsplat/cuda/_wrapper.py:449 isect_tiles` 要申请 2.93 GiB，只剩 2.30 GiB）。
崩前 PyTorch 已分配 **75.55 GiB**（正常训练只占 18.6 GiB），运行 **step 90600/250000（36%）**，
耗时 25h。8 卡空置到 11-16 09:00 才被发现（27 小时空转）。

**根因**：`12_sa_train.py` 换窗段（原 504-513 行）三件事叠在同一个峰值：
1. 旧 `views/target/geometry` 在赋值瞬间才释放，新 8 视角先建；
2. `geometry = teacher(views, ...)` 的 teacher 前向中间激活；
3. 该步 `forward_train` 全参反传。
`metrics` 里 `mem_reserved_GB` 从 65.9 单调爬到 **73.3**（rank5），碎片累积到窗口 #181 顶穿。

**修复（`12_sa_train.py`）**：
- 换窗前 `views = target = geometry = None` + `torch.cuda.empty_cache()`，teacher 前向后
  再 `empty_cache()` 一次，把峰值压回 baseline。
- 训练步包 `try/except torch.OutOfMemoryError`，**跨 rank 用 `all_reduce(MAX)` 同步跳过决定**。
  这一点是硬要求：各 rank 各自 skip 会让 step 走岔，下一次 all_reduce 集合点对不上，
  NCCL 会挂到作业超时。连续 4 个窗口 OOM 才放弃（`SystemExit`）。

**`12_sa_train.sh`**：`cmd_start` 补 `SA_ROTATE` / `SA_CKPT_EVERY` / `SA_RUNDIR` / `SA_RESUME`
透传（原来只透传 SCENE/SCOPE/ITERS/SEED，`SA_RESUME=1` 在 shell 层会被吞掉）。

**续训**：`SA_RUNDIR=/data/00950754/runs/sa_train/job_201366403 SA_RESUME=1 start 8 168h`
→ 作业 `201369781`，从 step 80000 快照接上，跑 `80020/250000` 时 loss 正常
（rank3 0.000142、rank1 0.000207）。显存 73.4/81.5 GiB（90%）、util 94-100%、
270~283W、54-60C。步速 1223 ms（比之前 1185 略慢，empty_cache 与续训 warmup 的开销）。

`git commit` 会把服务器那 4 个提交的成果**全部回滚**——`11_gpu_monitor.py` 从
955 行掉到 757 行，`fetch_dcgm()` / `render_queue()` / `fit()` / `heat_color()`

**正确解法（已执行，提交 `2c4094a`）**：
1. 备份 6 文件到 `/tmp/srv_backup_20261116/`；
2. `git checkout --` 把服务器工作区还原到 HEAD（丢掉被覆盖的假改动）；
3. 本机 `git bundle create 9abca99..HEAD` → scp → `git fetch` 成临时分支；
4. `git merge` 后**仅 `11_gpu_monitor.py` 冲突**（本机只改注释 15 增 21 删、无函数增删，
   服务器是大功能新增）→ 保留服务器功能 + 叠加本机注释清理，顺手删掉被内联取代的
   `scan_jobs()`；
5. 双向 `git bundle` 同步，本机 `--ff-only` 快进到同一提交。

**结论**：`canada_h100/` 五文件本机与服务器 md5 现完全一致，训练脚本未受影响
（md5 与作业提交时相同，作业 `201369781` 继续跑）。以后**改 canada_h100 前先 `git log`
查两边 HEAD 是否一致**，别单侧覆盖。同仓多落点规范见 AGENTS.md §11。

## 执行位不随 git 传播（`core.fileMode=false` 的代价）

**现象**：服务器上 `./11_gpu_monitor.py` 报 `bash: ./11_gpu_monitor.py: Permission denied`，
文件是 `-rw-rw----`（644）。本机同文件是 `-rwxr-xr-x`，但 `git ls-files -s` 两边都是
`100644`——因为两边都设了 `core.fileMode=false`（AGENTS.md §11 要求，避免 `chmod` 造
假 mode change 导致 pull 冲突）。**代价就是执行位完全不随 git 走**：新 clone、跨落点
同步后脚本一律没有 `x`。

**修法（已执行）**：
1. 服务器 `chmod +x canada_h100/*.sh *.py` 立即恢复；
2. 装 `.git/hooks/fixperm` + `post-checkout` / `post-merge` / `post-rewrite` 三个触发点，
   pull/checkout/rebase 后自动给带 shebang 的 `.sh`/`.py` 补 `x`，以后不用手工 chmod；
   **`post-rewrite` 的 stdin 必须先 `cat >/dev/null`**，否则子进程写 EPIPE。
   钩子在 `.git/hooks/` 里不入库，换新 clone 要重装（步骤写进 README 坑 4）。
3. README 加「坑 4」记录成因与重装方法（提交 `507227f`）。

**验证**：`chmod -x` 后手工跑一次钩子，两个文件都自动回到 `-rwxrwx--x`；监控 `--once`
正常输出 QUEUE + DCGM；训练作业 `201369781` 未受影响，step 81240、1.2s/step、两 rank loss 均在降。

## SplatAnything + QuerySplat 解耦 + textured 2DGS 架构评审（Codex）

- 用户提出冻结几何骨干、低分辨率2DGS几何头、高分辨率纹理头，每primitive内部表达不同
  RGB/alpha。判断为**可行候选，未实现/未实测**，细节沉淀 `splatanything/NOTES.md` §0；
  主计划只加入口/状态修正，不启动训练、不改变现有服务器作业。
- 核查本机 QuerySplat `9703d6f` 与 SA `b518996` 源码及论文/作者项目：QuerySplat 是
  冻结VGM+双查询解耦的普通3DGS，不输出RGBA贴图。局部RGB/alpha对应Textured Gaussians，
  作者公开重实现支持精确2DGS与UV采样；不能把逐场景结果当三图前馈泛化证据。
- 建议先借鉴解耦、保留depth锚定格点与轻量头，不搬整个大query decoder。教师及学生encoder
  独立权重，冻结范围必须写清。低分辨率先降低surfel格点，保留教师输入分辨率作控制。
- 2DGS是三维空间中的盘面，必须定义切平面UV；“四块”先明确为2×2 texels，与四子高斯不同。
  先固定几何/opacity学RGB，再单项开放纹理alpha，最后受约束几何残差。冻结骨干不保证深度正确，
  alpha可能遮掉错误层，不能当鼻部重影已修复。R2-N仍是归因入口。
- SA旧合并只处理DC等属性，不能直接平均不同局部坐标的纹理；优先先定surfel再预测纹理，
  新增可导UV渲染、抗锯齿、稳定ID与atlas导出。普通PLY查看器不支持新纹理表示。
- Q0官方SA→Q1适配普通2DGS→Q2 RGB纹理→Q3 alpha→Q4分辨率→Q5几何残差，使用同三图、
  独立身份/target、几何与覆盖守门。旧DA3换2DGS负结果保留，但不直接否定不同表示的新方案。
- 读最新代码确认 `canada_h100/12_sa_train.py` 已有可导3DGS训练；监督为输入重渲染MSE。
  本次未远程核实作业/成本，不能沿用“只有推理”，也不宣称textured2DGS训练或泛化已验证。
