## LoRA 人像微调的数据采购量（采购决策）

- 用户要买 UE 渲染数据做 LoRA（100+ 张/组），问买多少。结论：**400 组甜点区**，100 组验方向 + 补 300；1,000 组逼近 LoRA 容量上限；5,000 组边际收益趋零。
- 推导：身份 60–80 × 每身份 5 变体；单组张数不是瓶颈（一条样本只需 28 张，单组可切 3–5 条）。LoRA 容量 r=16≈1–3 万样本偏移、r=32≈3–10 万（经验值，非论文）。

## ZipSplat 自训手册：实跑验证（799 行定稿）

- `compare_4methods/ZIPSPLAT_DATA_PREP.md` 从 618 → **799 行**。前半自造数据（§1–7），后半官方数据复现（§8–13）。
- **本轮首次做了运行时验证**（此前全是静态读码）：在 WSL `zipsplat` env 用 importlib 桩化 `splatfactory.get_logger` 单独加载 `io.py`，跑通 `write_scene_to_tar` → `iter_scenes_from_tar` 往返。3 场景 × 5 视角、`per_shard=2` 切出 2 个 tar，`index.json` 映射正确。
- **深度编码实测**：形状不转置；范围内相对误差 mean 0.27% / p99 0.53%；`-1` 无效像素正确保留；但 **p0.1/p99.9 端点外的有效像素会被写成 0**（6/2240）。全无效深度写 `d_min=d_max=0.0` → mask 全 False → `compute_scene_scale` raise → 场景静默跳过（即 §2.2 的底层机制）。
- **`{key}` 三条命名硬约束（新发现，源码读取端决定）**：① 不能含 `.`——`member.name.split(".")[0]` 反推 key，`scene.001` 会把整 shard 场景并成一个；② 不能含 `.img/.dep/.cov/.seg/.dyn` 子串——`elif` 子串判定 + `int(n.split(".img")[1].split(".")[0])`，已实测抛 `ValueError: invalid literal for int() with base 10: ''`；③ 同 scene 成员必须连续写入（`iter_scenes_from_tar` 遇 key 变化就 yield），故**不能对同一 tar 以 `"a"` 追加**。
- **`index.json` 只用于计数**：`_count_scenes` 就是 `len(json.load(...))`，值（tar 名）没被读，找场景靠扫 tar；缺失只 warning。
- **`c2w` 存 4×4 时 `.reshape(12)` 必崩**（`cannot reshape size 16 into (12,)`），必须先 `[:3,:4]`。示例代码已改。
- **`get_loader` 是 `DataLoader(self, batch_size=None)`，不 collate** → `next(iter(...))` 拿到单个 sample 的原始 dict，`b["context"]["image"].shape` 是 `[V, 3, H, W]`（`ImagePreprocessor` 返回 CHW），没有 batch 维，别误判配置错。
- 环境事实：本机 **无 `splatfactory` conda env**，实际名是 `zipsplat`（py3.11.17 + torch 2.8.0+cu128），且**缺 `omegaconf`** → 无法直接 import 数据集包，只能桩化后单文件加载。
