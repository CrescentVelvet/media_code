## 修复 99g 在服务器 Python 3.10 下的 SyntaxError + 新增 99h 语法兼容检查

峰哥反馈 `99g_plot_capture_trajectory.py` 第 434 行报错。

**根因**：`f" · 距锚点 {math.dist((0,0,0), ctx["anchor"]):.2f} m"` —— f-string 表达式段里
复用了与定界符相同的双引号。这是 **Python 3.12 才允许的（PEP 701）**，而 `vggt_human` env 是
**3.10.20**（本机 WorkBuddy 内置 3.13，所以本机一路通过，掩盖了问题）。

**修复**：把距离先取到局部变量 `d_origin` 再拼字符串（不改语义，且两种版本都合法）。
另外 99g 顶部加了 `sys.version_info < (3,8)` 的兜底提示（用到 `math.dist`），docstring 注明
「别用 3.12+ 语法」。

**全部实测结论（3.10.20 上逐条跑过，不是猜的）**：
- ❌ `f"{d["k"]}"`、`f'{d['k']}'`（内层引号与外层定界符同类）
- ❌ 表达式段里出现反斜杠
- ✅ `f'''{d["k"]}'''`（三引号外层）、`f"{d['k']}"`（内外类型不同）、`f"{f'{x}'}"`（嵌套但类型不同）
- ⚠️ `ast.parse(src, feature_version=(3,10))` **查不出这一类**：PEG 解析器不再按旧规则限制
  f-string，实测 3.10/3.11/3.12 三种 feature_version 全部通过 → 不能靠它兜底

**新增 `vggt_human/99h_check_py_syntax.py`**：用 tokenize 精确判定（注释与普通字符串天然排除，
不像手写字符扫描会误报）。与真 3.10 交叉验证过：bad1/bad2 命中、ok1 干净，判定完全一致；
对 vggt_human 全部 58 个 .py 报干净。需 Python ≥ 3.12 运行（低版本不产出 FSTRING_* token，
但低版本本身就会报错，不存在反向风险）。

**验证方式（可复用）**：WSL 里有真 3.10 ——
`wsl -d Ubuntu2404 -- bash -lc 'PYTHONIOENCODING=utf-8 ~/miniconda3/envs/vggt_human/bin/python <脚本>'`。
本次用它跑了 99g 的完整渲染（单 ID combo），EXIT=0、产出 4.1 MB HTML + SVG → 运行期也没有
高版本依赖。注意 wsl.exe 输出是 UTF-16，PowerShell 里要 `-replace "`0",""` 去掉空字符再落盘。

**又踩的一个小坑**：99h 自己的 docstring 里写了 `f"""{d["k"]}"""` 这个示例，导致 docstring 被
提前闭合 → 它自己 SyntaxError。写这类示例要用三引号单引号或全角引号。
