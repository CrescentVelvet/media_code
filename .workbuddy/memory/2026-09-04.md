## git 对象库损毁事故 + 完整恢复（09:05–09:40）

### 现象
`git` 全部命令报 `fatal: bad object HEAD`；`.git/refs/` 目录整个消失。

### 根因（两条，都发生在 2026-09-03 21:03 前后）
1. **被中断的自动 gc 撕掉 pack**：那条 `git add A && git commit && git add B && git commit`
   复合命令的第二条 commit 触发 `gc --auto`（28 天没 gc、攒了几百个松散对象），
   命令被 SIGTERM 打断 → `.git/objects/pack/pack-042da17c….pack` 被删，新 pack 未落盘。
   旁证：`objects/`、`objects/info/commit-graphs/`、`index` 的 mtime 都是 21:03。
2. **被中断的 stash 撕掉 refs**：为修 `git commit -m "a\nb"` 里 `\n` 不展开的问题，
   跑了 `git commit --amend …; git stash; git commit --amend; git stash pop` 复合命令，
   `git stash` 被 SIGTERM 打断 → `.git/refs/` 被清空。
   附带错误：amend 前没确认 HEAD，把 render_closeup 那条提交改成了 face_center 的 message。

### 恢复步骤（可复用）
1. 先 `cp -a .git <仓库外备份>`（关键：之后再没丢过东西）
2. `git ls-remote origin` → 发现远端正处于 `f96d30f`（目录前缀重命名那条），只丢最后 2 条本地提交
3. `git -c gc.auto=0 fetch origin` → 拉回 533 条历史的对象（新 pack 3.3M）
4. `rm -f .git/index` + `git update-ref refs/heads/main f96d30f` + `git reset --mixed f96d30f`
   → 索引重建，**工作区文件一个没动**
5. 重新分 3 个逻辑提交（face center / 渲染脚本 R 转置 / MediaPipe 兜底）
6. 清理：删 `.git/logs/HEAD` 与 `.git/logs/refs/heads/main` 中「终点是死对象」的行并重连链条；
   移走失效的 `pack-042da17c….idx` + `multi-pack-index`（它们会让 fsck 报 pack 加载失败）
7. `git fsck` 完全干净；`落后 origin/main 0 / 领先 3`

### 损失
- 完全恢复：533 条历史 + 工作区全部文件
- 永久丢失：最后 2 条未推提交的**对象**（内容在工作区，已重建为新提交，哈希变了）；
  另有 2 条历史 amend/reset 掉的旧提交（9fbcd429、a74cd1ba）本来也只存在于本地 pack
