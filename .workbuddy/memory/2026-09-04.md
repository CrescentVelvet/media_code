   - 另：130 张里只有约 82 张有 mask 文件（misses=48）。
2. **HYPIR 已经是单次前向，不是多步扩散**：
   - `HYPIR/enhancer/sd2.py::forward_generator` = 固定 timestep `model_t=200` 的一次 UNet forward + 一次解析式 `scheduler.step`（无迭代去噪循环）。
   - `base.enhance()` 的真实开销是 **tiling**：`patch_size=512 / stride=256`（50% 重叠）→ VAE encode、UNet、VAE decode 各跑一遍分块。512×512 输入约 4 块；1440×1920 全图约 (1440/256)×(1920/256)≈6×8 块。
   - 已确认 `weight_dtype=torch.bfloat16`，且 diffusers 0.32.2 默认走 `AttnProcessor2_0`(sdpa) → **dtype 与注意力这两条常规加速路已经没有余量**。
   - 结论：TorchScript JIT 不会带来「数十倍」，它不减少 FLOPs，只省 Python 派发；预期 1.0~1.3x，且有控制流/静默写错 shape 的风险。**真正的 5~10x 在：取消 tiling（512 输入单块）、分块 batch 化、torch.compile、merge LoRA、缓存空 prompt 的 text embedding。**
3. `render_closeup.py` 的 alpha 已经是"黑白双背景差分"内联算出（`alpha = 1-(white-rgb).mean(dim=0)`），不是独立一步；真独立的两步是「双背景 alpha」+「SAM2 人脸 mask」。
   - 该公式对高亮物体有 clamp 偏差（白衬衫处 `white` 溢出被截到 1 → alpha 被高估），但同处理论上三通道差值相同，不是致命问题。

- 权重：本地 sam3.pt（3.45GB，key 前缀 detector.* 1156 + tracker.* 309）直接 `build_sam3_image_model(checkpoint_path=..., load_from_HF=False)` 加载。显存 3.33GB。
