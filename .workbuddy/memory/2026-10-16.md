# 2026-10-16 工作日志

## 主题：D 案（稠密化自动调度器）冒烟 + 窗口后 prune 死亡螺旋的根因定位与修复

### 1. 症状

调度器 A 冒烟（double_wave，`USE_DENSIFY_SCHED=1`，激进参数 thr 0.0002/until 10000，
cap 600k，20k 迭代）**在 densify 窗口关闭瞬间崩溃**：
- iter 10000 首个「window closed prune-only」一步删 136k 点（599k → 463k）；
- 之后每千步 ×0.685 指数衰减 463k→286k→196k→135k→…→9.6k；
- PSNR 从 best 20.52@10k 崩到 @20k 5.34。
- **三次独立重跑完全一致**（20.472/20.504/20.517@10k 后同型崩溃）→ 可复现。

### 2. 诊断过程（带分量埋点，一次重跑拿全证据）

在 `_prune_mask` 里把三路判据拆开计数（opa / vs / ws）并重跑，关键数据：

| iter | opa(<0.005) | vs(max_radii2D>20) | ws(scaling>0.1·extent) | applied |
|---|---|---|---|---|
| 1000（窗口，size off） | 1668 | 0 | 12960 | 1668 |
| 4000（窗口，size on） | 439 | 994 | 994 | 1433 |
| 6000（窗口） | 447 | 447 | 447 | 894 |
| 9000（窗口） | 311 | 0 | 343 | 654 |
| 10000（**窗口关，第一次**） | 195 | **137080** | 353 | （旧代码删 136423） |
| 11000+（窗口关） | ~220 | 151886↑ | 1501↑ | — |

### 3. 根因（两条链都实锤）

**机制**：`densification_postfix`（fork `scene/gaussian_model.py:319`）在每次
densify（clone/split 加点）后把 `max_radii2D` **整体清零**。所以窗口内
`vs = max_radii2D > 20` 判据形同虚设（永远只看最近 100 步的新增量，≈0）；
**窗口关闭后不再 densify → max_radii2D 不再清零 → 单调累积成「历史最大屏幕半径」**，
第一个窗口后 prune 就把 ~137k「曾以 >20px 出现过」的点全删。

- 训练渲染用 `-r 2`（~960×720），单手近景时屏幕半径 >20px 的点占 ~23% 很正常，
  它们不是无效点，删掉必然塌模型。
- **正反馈（死亡螺旋）**：窗口后只剪不增 → 删点没有补充来源 → 剩余点被迫长大补偿
  覆盖面积 → 屏幕半径进一步超标 → 下轮再删。日志里 463k→286k→196k 的 ×0.685
  指数衰减就是签名。
- 对照组 `model_colmap_cap600k`（官方代码，硬护栏撞帽后整块跳过 = 窗口后完全不
  prune）@20k = 21.81 正常 → 证实问题就在窗口后 prune。

### 4. 修复

`sched_prune_only` 在窗口后调用处传 `max_screen_size=None`（**只按 opacity<0.005 剪**）：
- som_human/train_som.py 窗口后分支；
- deformable_human/train_mask.py 窗口后分支（同款）；
- `densify_sched.py` 加 `_prune_components`（三路判据分量诊断，恒算计数、
  剪枝按 `max_screen_size` 决定是否并入尺寸判据）+ 自测第 11 组。

### 7. C3 隔离实验（窗口后 prune 是否该关）：**结论 = 维持默认 1**

C3 = `model_dsche_noprune`，与 C2 逐字同参（thr 默认 0.0007 / until 15000 / 调度器开 /
cap 600k / 20k / -r 2），**唯一差异 `DENSIFY_PRUNE_AFTER=0`**（窗口后完全不剪）。
目的：隔离「窗口后只剪不增」语义本身的代价（参考组同样不 prune，最可比）。

| 迭代 | C2（剪，prune_after=1） | C3（不剪，prune_after=0） |
|---|---|---|
| 18000 | 21.303 | 21.290 |
| 19000 | **21.549** | **21.557** |
| 20000 | 21.465 | 21.306 |
| 末三点均 | **21.439** | 21.384 |
| 点数@20k | 580,267 | 599,319 |

- Δ(末三点均) = **−0.055 dB**，@19k +0.008、@20k −0.159 → 全部落在三次重跑噪声
  ±0.045 量级内（@20k 的 −0.159 单点偏大但方向与 @19k 相反，判为噪声+次优快照）。
- 结论：**窗口后 opacity-only prune 对质量中性**，而 C2 少 19,052 点（−3.2%，
  N 减 → 步时随 N 线性下降）→ **维持 `DENSIFY_PRUNE_AFTER=1`**。
- 于是 −0.26~−0.34 dB 的代价**全部归因于「严格 cap 600k + absgrad 均值 topk 截断」
  策略本身**：参考组撞帽后整块跳过 prune、点数冻结在 629,715（超帽 4.95%），
  等于白拿 5% 容量且无 topk 排序偏置。→ 调度器默认仍关（保险丝按需开）。

**分量埋点全程取证（口径自洽，顺手关掉上一轮的「vs 未解之谜」）**：

| 阶段 | vs | applied |
|---|---|---|
| C2 窗口内 iter 1000–14000（`max_screen_size=20`） | **恒 0** | ≈opa（数百） |
| C2 窗口关闭 iter 15000 / 20000 | 113,867 → 139,584（单调累积） | **294 / 396**（仅 opa） |
| A2（until=10000）窗口关闭 iter 13000–20000 | 162,446 → 178,335（单调累积） | **319–393**（仅 opa） |

- 窗口内 vs≡0 直接印证 `densification_postfix` 每轮加点清零 `max_radii2D`
  （上一轮在旧日志里看到的「窗口内 vs=994/588/447」属修复前/口径不同，现口径
  干净复现为 0）。
- 窗口后 vs 单调累积 = 修复前会被一次性删掉的那 11–17 万点；`applied` 只剩
  opa 单路（294~422）→ **修复生效的直接证据**（修复前该位是 137,080）。
- 附：`vs` 与 `ws` 在窗口内虽被计数但不并入 `applied`（`prune_mask` 由
  `max_screen_size` 是否为 None 决定）→ 埋点恒算计数是为了归因，不影响剪枝语义。

### 9. ⚠️ 同族地雷二次发现：硬护栏路径也带尺寸判据（默认开启！）

**发现契机**：准备 E 案冒烟时复核「默认路径到底走哪条分支」——`MAX_GAUSSIANS`
默认 600000 是**开的**，撞帽后走 `n_before >= SOM_MAX_GAUSSIANS` 分支。该分支
是 2026-10-16 我自己改的（旧版撞帽跳过整个调用 = 完全不 prune，与注释不符），
改成了 `sched_prune_only(..., size_threshold)`——**与刚修的死亡螺旋同构**：
只剪不增 + 尺寸判据 → `max_radii2D` 无 densify 补点清零 → 累积成历史最大屏幕半径。

**风险面**：当天 D 案四组冒烟全走调度器分支，护栏分支**零覆盖**；而它是默认路径，
所有后续训练（含 E 案对照）都会踩。

**低 cap A/B 实锤**（double_wave/colmap_refined，`MAX_GAUSSIANS=120000`、
`USE_DENSIFY_SCHED=0`、5000 步、`-r 2`；cap 在 iter 900 触发，但
`size_threshold = 20 if iteration > opacity_reset_interval(3000) else None`，
所以危险区从 iter>3000 才开始）：

| | 组 1 带尺寸判据（修复前） | 组 2 去尺寸判据（修复后） |
|---|---|---|
| iter ≤3000（`max_screen_size=None`） | applied = opa 69~353，点数稳 ~120k | applied = opa 56~99，点数 ~120k |
| iter 3100 首个带判据周期 | **`vs=76,617` → `applied=86,738`**，162,115→75,377（**−54%**） | `vs=57,776` 被忽略，`applied=994`（=opa） |
| iter 3100–5000 | 震荡 110k↔150k，每 100~200 步删 6k~26k | 单调缓降 135,789→133,747，无震荡 |
| **@5000 test PSNR** | **8.85（崩）** | **19.73（正常）** |

**修复**：
- `som_human/train_som.py` 护栏分支：`sched_prune_only(..., None, report=True)`
  + `[DENSIFY-PRUNE] iter N (cap) opa/vs/ws/applied` 埋点 + 点数前后打印
  （此前这条路径是哑的，只在每 1000 步打一句 CAP reached）。
- `deformable_human/train_mask.py` 护栏分支：同款。
- docstring 第 10 条补「只剪不增一律不得带尺寸判据」及事故数据。

**沉淀的判定纪律**（已写进 README「死亡螺旋」节末）：
> 任何「只剪不增」的 prune 调用一律不得带尺寸判据。判定方法：这段代码附近
> 没有 `densify_*` / `clone` / `split` / `postfix` 调用，就不该传 `max_screen_size`。
> 合法使用尺寸判据的**只有窗口内那一处**（每轮 prune 后紧跟 clone/split 补点，自纠）。
