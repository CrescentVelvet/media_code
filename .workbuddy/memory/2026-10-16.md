# 2026-10-16 工作日志

## 主题：D 案（稠密化自动调度器）冒烟 + 窗口后 prune 死亡螺旋的根因定位与修复

### 1. 症状

调度器 A 冒烟（double_wave，`USE_DENSIFY_SCHED=1`，激进参数 thr 0.0002/until 10000，
cap 600k，20k 迭代）**在 densify 窗口关闭瞬间崩溃**：
- iter 10000 首个「window closed prune-only」一步删 136k 点（599k → 463k）；
- 之后每千步 ×0.685 指数衰减 463k→286k→196k→135k→…→9.6k；
- PSNR 从 best 20.52@10k 崩到 @20k 5.34。
- **三次独立重跑完全一致**（20.472/20.504/20.517@10k 后同型崩溃）→ 可复现。

### 2. 诊断过程（带分量埋点，一次重跑拿全证据）

在 `_prune_mask` 里把三路判据拆开计数（opa / vs / ws）并重跑，关键数据：

| iter | opa(<0.005) | vs(max_radii2D>20) | ws(scaling>0.1·extent) | applied |
|---|---|---|---|---|
| 1000（窗口，size off） | 1668 | 0 | 12960 | 1668 |
| 4000（窗口，size on） | 439 | 994 | 994 | 1433 |

| 11000+（窗口关） | ~220 | 151886↑ | 1501↑ | — |

### 3. 根因（两条链都实锤）

**机制**：`densification_postfix`（fork `scene/gaussian_model.py:319`）在每次
densify（clone/split 加点）后把 `max_radii2D` **整体清零**。所以窗口内
`vs = max_radii2D > 20` 判据形同虚设（永远只看最近 100 步的新增量，≈0）；
**窗口关闭后不再 densify → max_radii2D 不再清零 → 单调累积成「历史最大屏幕半径」**，
第一个窗口后 prune 就把 ~137k「曾以 >20px 出现过」的点全删。

- 训练渲染用 `-r 2`（~960×720），单手近景时屏幕半径 >20px 的点占 ~23% 很正常，
  它们不是无效点，删掉必然塌模型。
- **正反馈（死亡螺旋）**：窗口后只剪不增 → 删点没有补充来源 → 剩余点被迫长大补偿
  覆盖面积 → 屏幕半径进一步超标 → 下轮再删。日志里 463k→286k→196k 的 ×0.685
  指数衰减就是签名。
- 对照组 `model_colmap_cap600k`（官方代码，硬护栏撞帽后整块跳过 = 窗口后完全不
  prune）@20k = 21.81 正常 → 证实问题就在窗口后 prune。

### 7. C3 隔离实验（窗口后 prune 是否该关）：**结论 = 维持默认 1**

C3 = `model_dsche_noprune`，与 C2 逐字同参（thr 默认 0.0007 / until 15000 / 调度器开 /
cap 600k / 20k / -r 2），**唯一差异 `DENSIFY_PRUNE_AFTER=0`**（窗口后完全不剪）。
目的：隔离「窗口后只剪不增」语义本身的代价（参考组同样不 prune，最可比）。

| 迭代 | C2（剪，prune_after=1） | C3（不剪，prune_after=0） |
|---|---|---|
| 18000 | 21.303 | 21.290 |
| 19000 | **21.549** | **21.557** |
| 20000 | 21.465 | 21.306 |
| 末三点均 | **21.439** | 21.384 |
| 点数@20k | 580,267 | 599,319 |

- Δ(末三点均) = **−0.055 dB**，@19k +0.008、@20k −0.159 → 全部落在三次重跑噪声
  ±0.045 量级内（@20k 的 −0.159 单点偏大但方向与 @19k 相反，判为噪声+次优快照）。
- 结论：**窗口后 opacity-only prune 对质量中性**，而 C2 少 19,052 点（−3.2%，
  N 减 → 步时随 N 线性下降）→ **维持 `DENSIFY_PRUNE_AFTER=1`**。
- 于是 −0.26~−0.34 dB 的代价**全部归因于「严格 cap 600k + absgrad 均值 topk 截断」
  策略本身**：参考组撞帽后整块跳过 prune、点数冻结在 629,715（超帽 4.95%），
  等于白拿 5% 容量且无 topk 排序偏置。→ 调度器默认仍关（保险丝按需开）。

**分量埋点全程取证（口径自洽，顺手关掉上一轮的「vs 未解之谜」）**：

| 阶段 | vs | applied |

### 9. ⚠️ 同族地雷二次发现：硬护栏路径也带尺寸判据（默认开启！）

**发现契机**：准备 E 案冒烟时复核「默认路径到底走哪条分支」——`MAX_GAUSSIANS`

只剪不增 + 尺寸判据 → `max_radii2D` 无 densify 补点清零 → 累积成历史最大屏幕半径。

**风险面**：当天 D 案四组冒烟全走调度器分支，护栏分支**零覆盖**；而它是默认路径，

**低 cap A/B 实锤**（double_wave/colmap_refined，`MAX_GAUSSIANS=120000`、
`USE_DENSIFY_SCHED=0`、5000 步、`-r 2`；cap 在 iter 900 触发，但

### 9.5 ⚠️ E 案首跑踩雷：gy 镜像 bug 让深度损失全程静默失效（已修复）

**现象**：λ=0.05 那轮跑了 10k 步，`[DEPTH] enabled` 打了，但**没有一条**
`[DEPTH] iter N a=.. loss=..` per-step 日志 → 损失每步都返回 `None`，从没进梯度。

**定位链**（全离线，CPU）：
1. `DepthPrior.loss()` 只在成功时打印，失败原因被吞 → 先复现 None。
2. numpy 逐门限复现（run1 ckpt + train 相机 00001）：`in_frame` 22.4万点 ✅、
   `w_sum` 30142 ✅，**卡在 `gate align: a=-1.76 < 0`** → 每步被 `a<=0` 门限拦。
3. a<0 = 深度图值与 z_view 反相关。逐个变体测相关（`tmp_depth_corr.py`）：
   `gy=-ndc_y`（现码）corr(mono,z)=**−0.475**；`gy=+ndc_y` → **+0.677**。
4. **铁证裁决**（`tmp_gy_verdict.py`）：拿光栅化器自己渲染的深度图（投影真理，
   不依赖我手写投影对错），逐点算 corr(z_view, rendered_depth)：
   `gy=+ndc_y` = **+0.62~+0.88**（4 个测试视角），`gy=−ndc_y` = **−0.48~−0.50**。

**根因**：`depth_prior.py` 的 `gy = -ndc[:,1]` 照抄自 `deformable_human/train_mask.py`
的 `sample_fg_prob`（注释自称「qc_proj_fg.py 验证过」）。但本 fork 视图矩阵 y 轴
朝下（COLMAP）+ 投影矩阵 `P[1][1]=+1/tanfovy` 不翻转 → `ndc_y>0` 就是画面下半部；
grid_sample 的 `y=+1` 也是底部 → **正确约定是 `gy=+ndc_y`，不用取负**。

**当年为什么"验证通过"**：`qc_proj_fg.py:101-107` 把叠加点画在**与采样同一个
（可能翻转的）坐标系**里，点色=落点处 mask 值 → 任何 gy 符号下都「红点落在 fg
上」，对符号天然不敏感，**是无效验证**。

**修复**：
- `depth_prior.py`：`gy = ndc[:, 1]`（去负）+ 注释/docstring 更正。
- `train_mask.py sample_fg_prob`：同款修正（该函数只在 `bg_deform_lambda>0` 时
  调用，默认关 → **沉睡 bug，未影响既有实验**；被照抄到 E 案才真正发作）。
- `train_som.py`：深度块加「失败也可见」节流打印（`[DEPTH] iter N SKIP (原因)`），
  杜绝下次静默跳过。
- 留档：带 bug 的 run2 → `model_depth005_gybug`；重跑 `model_depth005`。

**教训**：投影/坐标变换类代码，「叠点看图」式 QC 若把点画在与采样同一坐标系里
是自证循环；要拿**另一个独立来源**（光栅化器渲染深度、或已知正确的 mask 对齐）
做交叉核对。
