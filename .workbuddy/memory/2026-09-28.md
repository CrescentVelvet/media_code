## vggt_human 99g 增加「视角约束范围」可视化（六种画法）

**需求**：峰哥给了一段相机视角约束的 C++ 移植代码（`compute_sight_center` +
`calc_view_limitations` + 球面绘制），说算得不对，要求**不要照抄**，而是提炼出「视角约束
范围」的本质，画进 99g 的相机轨迹图，并且给几种画法让他挑最不影响原有轨迹的一种。

**结论**：本质 = 以 target 为心的球壳扇块（方位角 az × 仰角 el × 距离 r 三区间），
换成 UWA `view_limits` 就是 Phi/Theta/Radius。已实现 6 种画法 + 叠进 combo 的开关。

### 原代码的 4 个问题（已写进 NOTES.md，都是方法论错，不是精度差）
1. 把相机中心当未知数做最小二乘射线交汇 —— 但 transforms.json 本来就有 `anchor_point`
   （实测视线与 `anchor−C` 夹角余弦均值 0.9926），直接取用更准；估法只留作缺 anchor 的回退。
2. `vulkan_to_webgl` / `webgl_to_vulkan` 是同一个函数 `[x,−y,−z]`，且只对 camera 与 target
   同时施加 → 刚体变换，角度结果不变，纯死代码。
3. 半径区间用 `0.9×avg / 1.2×avg` 拍脑袋常数：实测 `view_limits.json` 是 R[0.432, 2.159]
   而 init 半径 1.909，按固定比例只会给 [1.72, 2.29]，量级都不对。
4. 极角区间带「跨度>10° 才并入 init 值」的条件（不自洽）；az 解缠只在 |az|>0.8π 时补偿；
   绘图用 `cos(phi)` 从 +Y 量起而极角从 −Y 量起 → 球壳纵向画反。

### 实现要点
- 区间 = 各帧实测 min/max ± 显式余量（`VL_AZ_PAD`/`VL_EL_PAD`/`VL_R_PAD`，默认 3°/3°/8%），
  这样能直接和 99e 解出的 `view_limits.json` 对照。az 解缠改成「每步增量归一 (−180,180] 后累加」。
- 6 种画法：`lim_band` / `lim_edges` / `lim_angle` / `lim_rings` / `lim_hull` / `lim_shell`；
  `STYLE=vlimit` 把 6 张内联进同一页 HTML 供选型；`VLIMIT_MODE=<mode>` 可把约束叠进 combo。
- 约束层永远画在轨迹**下层** → `lim_edges`（四条细虚线）对轨迹观感影响最小。
- 实测 10 个样本：az 跨度 171°–270°、el 跨度 8.6°–33.2°、ρ 0.54–1.92 m，无一触发整圈阈值。

### 踩过的 3 个坑（都已修，NOTES.md 有记）
1. `clip_rect` 的契约是 **`(x, y, w, h)`**，不是 `(x0, y0, x1, y1)` —— 传错导致等轴测轴三叉
   按 w=840/h=528 算，画到画布外。
2. `view.rect()` 返回的是**数据框**（View 等比例尺+居中），不是预留框 —— 拿它当面板会把
   甩到外弧外的数值标注裁掉（「张角 269.5°」被切）。新增 `_fit_view()` 按面板长宽比扩张短边。
3. `vlimit` 总览内联 6 张图到同一文档，`clipPath` 的 id 必须带 mode —— 重复 id 时
   `url(#id)` 只解析到第一个，第 2~6 张会被第一张的裁剪框裁掉（单张看正常，拼起来才暴露）。

### 顺手修的两个既有缺陷
- `draw_top_geometry`：frame 0 / 末帧标签会压住 `anchor_point` 标签（印成
  「anchor_poinrame 0」）。改成四个方位里挑一个不撞的，影响所有风格。
- `99h_check_py_syntax.py`：**只做词法检查，漏报纯语法错误**。实测 `f()    f()`（两条语句
  撞一行）它能一路通过 —— 本机 3.13 也不报，服务器才炸。已加 `ast.parse` 前置一道。

## vggt_human 99g 新增 quad 四联对照图（峰哥定稿，已成默认风格）

**需求**：峰哥定了「角度标注 + 等轴测球壳」两种画法，并要求**保留原来的采集轨迹俯视图 +
等轴测图**，在右侧从上往下再画这两张约束图 —— 一共 2×2 四张图。

**实现**：新增 `STYLE=quad`（已设为默认），一张 SVG 1752×1328：左列＝原始采集轨迹
（① 俯视 / ③ 等轴测），右列＝同取景下的约束图（② `lim_angle` 角度标注 / ④ `lim_shell` 球壳）。
画面下方各自的图例带：左列沿用 combo 原排法，右列给出 az/el/ρ/R 数值行 + UWA 对照。

### 三条设计决定
1. **四张图共用同一取景与比例尺**（= 相机范围 ∪ 锚点±均值半径 ∪ 约束范围）。对照才有意义；
   各自取景会让同一段轨迹在两图里大小不同。代价：左列比 combo 单看小一圈（实测约束范围是
   相机范围的 1.2–1.9 倍俯视、1.06–1.26 倍等轴测）。
2. **右列约束层换青绿**（`QUAD_INK`/`QUAD_FILL`），不用 vlimit 的紫 —— 左列轨迹是蓝→紫→玫红
   渐变，中段正是紫，紫约束压上去和轨迹糊在一起分不清。vlimit 系列保持原紫。
3. **右列省两样**：均值半径环（与约束区间圈冗余）、ρ 的图内数值文字（该位置被
   anchor_point / frame 0 / 世界原点 三个底图标签占着；面板下方数值行已有）。

### 新踩的两个坑
1. **`_fit_view` 的 panel 是 `(x, y, w, h)`**，不是 `(x0, y0, x1, y1)` —— 与 `clip_rect` 同构，
   但和 `View(...)` 的后四个参数（x0,y0,x1,y1）不同。第一版按后者传，两个调用点算出的长宽比
   不同（840/570 vs 1712/570）→ 右列被扩张成两倍比例尺且内容偏位。已把参数改名 `panel_xywh`
   并在 docstring 加 ⚠️。**同一份代码里两套像素框约定并存，接错不会报错，只会画出怪图。**
2. `clipPath` id 在同一 SVG 内必须唯一（带面板后缀），否则 `url(#id)` 只解析到第一个。

### 顺手改进
- `_lim_shell` 的分片填充补同色细描边（`fill-opacity`/`stroke-opacity` 各 0.07），消除相邻片
  抗锯齿缝造成的「扇骨」感 —— vlimit 的 lim_shell 单图也一并变好。
- `_lim_angle` 整圈时不再打印 az 边界值（原先会印出 `447.3°` 这种解缠后的原始值，误导）。
- `axis_hints(flip=True)`：右列框外没有空间，+X 标签改画在框内右下角。
- HTML 容器 `.wrap.wide` 从 1240 放宽到 1820（quad 宽 1752，否则被缩放、字变小）。
