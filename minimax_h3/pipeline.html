MiniMax-H3 Pipeline 与优化措施

本仓 minimax_h3/ 用 diffusers 直接跑 MiniMax-H3（不起 SGLang 服务），针对单机 8×A100 80GB 做了一系列显存/速度优化。本文汇总优化措施 + FL2VA/Ref2VA 两个变体的区别。

一、优化措施总览

1. 推理路径：diffusers 直接跑，不起服务

脚本方式显存速度适合
06（bf16）两卡分拆 + auto offloadtransformer 61.7GB + text_encoder 62.1GB，两卡各满offload 有搬运开销无量化、多卡
06a（int8 量化）单卡常驻 + group_offload各组件 ~31GB，单卡去噪只占当前 block同步搬运稍慢，但无服务开销单卡、要省显存

不走 SGLang serve（02+03）那条路——那是 serving 框架，要起长驻 HTTP 进程。diffusers 直接 pipe(...) 跑，简单，适合单次生成。

2. int8 weight-only 量化（06a）

项说明
量化方式torchao Int8WeightOnlyConfig(version=2)——只量化权重，激活全程 bf16，精度损失小
显存transformer 61.7→~31GB，text_encoder 62.1→~31GB，单卡 80GB 可放
关键模块不量化transformer 的 proj_in/audio_proj_in/context_embedder/time_embedder/time_proj/token_refiner/norm_out/proj_out/audio_proj_out + text_encoder 的 model.visual/embed_tokens/norm/lm_head 保留 bf16（输入输出投影 + AdaLN + 时间嵌入，对生成质量影响最大）
CFG-distilledMiniMax-H3 guidance 已 baked in，对权重扰动更鲁棒（不像需 CFG 的模型那样敏感）
torchao 版本需 torchao==0.15.0（TorchAoConfig 要求 ≥0.15.0）

3. group_offload（06a，单卡放不下的关键）

项说明
transformerenable_group_offload(offload_type="block_level", num_blocks_per_group=1)——按 block offload 到 CPU，去噪时只加载当前 block 到 GPU
text_encoderapply_group_offloading(model, offload_type="leaf_level")——按叶子模块 offload
VAE常驻 GPU（pipe.vae.to(DEVICE) + pipe.audio_vae.to(DEVICE)），只在解码阶段用
显存去噪时只占当前 transformer block（~2-3GB）+ 激活 + VAE（~3GB）≈ 10-15GB，单卡 80GB 绰绰有余
Int8Tensor 兼容性踩坑（两个必须改的参数）：
  • low_cpu_mem_usage=True（enable_group_offload 和 apply_group_offloading 都要传）——跳过 pin_memory()，Int8Tensor 不支持 pinned memory
  • 去掉 use_stream=True——use_stream 会走 _pinned_memory_tensors() 调 is_pinned()/pin_memory()，Int8Tensor 报错；改成普通同步搬运，稍慢但稳

4. 分辨率与帧数（省显存）

参数默认说明
NUM_FRAMES73需满足 17*n+5（73=17×4+5，~3s@24fps）。常见：90/107/124（~5s）/175（~7s）
MAX_PIXELS393216（512×768）不传 WIDTH/HEIGHT 时，按首帧图比例（无图默认 16:9）自动算分辨率，总像素 ≤ 此阈值，32 倍数对齐
WIDTH/HEIGHT0（auto）显式传则直接用（必须 32 倍数）
FPS24模型固定 24fps，改只影响 mp4 容器

降分辨率是最有效的省显存手段——文档说 960×544 比 1344×768 快 2.3x、显存也更少。

5. 本地加载（不走代理）

问题修法
modular_model_index.json 里组件 pretrained_model_name_or_path 写的是 "MiniMaxAI/MiniMax-H3"（HF Hub ID），load_components 会从 HF 下载撞代理 SSLload_components(..., pretrained_model_name_or_path=MODEL_PATH) 覆盖，强制本地加载
MiniMax-H3 有两套 transformer：FL2VA/transformer/（原始 MiniMax 格式 blocks.*/model-*.safetensors）和顶层 transformer/（diffusers 格式 transformer_blocks.*/diffusion_pytorch_model-*.safetensors）MiniMaxH3Transformer3DModel.from_pretrained(MODEL_PATH, subfolder="transformer") 用顶层（diffusers 格式），不用 FL2VA_DIR

6. diffusers 安装（PyPI 没有 ModularPipeline）

步骤说明
检测from diffusers.modular_pipelines.minimax_h3 import MiniMaxH3ModularPipeline（不是通用 ModularPipeline，PyPI 有通用类但无 minimax_h3 模块）
PyPI 先试pip install -U diffusers
git fallbackPyPI 还没有 → git clone diffusers main + pip install -e --no-deps --config-settings editable_mode=compat（跳过依赖 pin，用 env 现有 torch/transformers）
editable_mode=compatPEP 660 默认 strict 模式漏 multimodal_gen 子包（KeyError: 'sglang.multimodal_gen'），compat 模式加源码目录到 sys.path，所有子包能 import

7. H3-Context-IR prompt 优化（08）

短 prompt 效果不如 H3-Context-IR 格式长描述（官方推荐）。08_context_ir.sh 调 MiniMax hosted API（POST /v2/h3_context_ir）把短 prompt + 可选首帧图转成结构化长描述（integrated_multimodal_description / overall_soundscape / non_diegetic_music），再传给 06/06a 生成。需要 MiniMax API token。

二、FL2VA 与 Ref2VA 的区别与联系

共同点（共享组件）

组件说明
text_encoderQwen3-VL-32B（H3-Encoder），取第 50 层 hidden state；文本和图像都经它编码（音频不经）
visual_vaeH3-VisualVAE，时间因果视频自编码器，空间压缩 16×、时间 4×、24 通道（f16t4d24），patchify 后有效空间下采样 32×
audio_vaeH3-AudioVAE，左右声道各自编/解码，32kHz → 40Hz 潜序列（立体声）
tokenizer / processor共享
scheduler / audio_scheduler两个调度器：视频 shift=12.0，音频 shift=3.0
Omni-Transformer33B 单流 dense Transformer（~13B 在 AdaLN 分支，推理可预计算缓存故不加载）；3D MM-RoPE 表示 (t,h,w)
CFG-distilledguidance baked in，无 negative_prompt / guidance_scale，每步一次前向
输出768p / 24fps / 32kHz stereo / 4–15s

差异

项FL2VARef2VA
全称First-and-Last-Frame-to-Video-and-AudioReference-to-Video-and-Audio
checkpoint 子目录transformer/（diffusers 格式 transformer_blocks.*）transformer_ref/（diffusers 格式，权重不同）
输入文本 + 可选首帧/末帧/首末帧（0/1/2 张图）文本 + 参考素材（≤9 图 + ≤3 视频 + ≤3 音频，共 ≤12）
支持的 taskt2va（纯文）/ i2va（首帧）/ l2va（末帧）/ fl2va（首末帧）ref2va（参考生成）
condition 角色role=keyframe（frame_index=0 首帧 / -1 末帧）role=reference（按模态独立编号 <Picture N> / <Audio N> / <Video N>）
aspect_ratio默认 auto（跟随首帧比例）默认 auto（参考不绑几何，画布默认 16:9）
顺序敏感性首末帧顺序固定（首帧在前）参考顺序影响语义（重排 = 不同请求，编号 + 共享音视频时钟都跟着变）
视频参考的音轨无视频自带音轨算 <Audio 1>，独立音频文件算 <Audio 2>（以此类推）
精度BF16BF16

联系（为什么共享除了 transformer 之外的所有组件）

MiniMax-H3 把两个变体放在同一个 HF 仓库里，除了 transformer 权重不同，其余全共享（text_encoder / visual_vae / audio_vae / tokenizer / processor / scheduler 都只存一份）。modular_model_index.json 是仓库级公共入口，FL2VA/model_index.json 和 Ref2VA/model_index.json 是任务族各自的 diffusers 索引。
  • FL2VA 的 transformer/ 学的是"首末帧条件下的视频+音频生成"——吃文本 + keyframe（首/末/首末），吐延续的视频+音频。
  • Ref2VA 的 transformer_ref/ 学的是"多模态参考条件下的生成"——吃文本 + 参考图/视频/音频，吐参考驱动的视频+音频（如人物+声音→说话视频）。
  • 两者都是 CFG-distilled（无 CFG guider，每步一次前向），共用 H3-Encoder（Qwen3-VL-32B）编码文本+图像，共用两个 VAE 解码视频/音频。
本仓当前只跑 FL2VA（06/06a 用 workflow="fl2va"）。Ref2VA 需要 workflow="ref2va" + 加载 transformer_ref/，且 diffusers API 要传 references=[MiniMaxH3ImageReference, MiniMaxH3VideoReference, MiniMaxH3AudioReference]（顺序敏感）。要跑 Ref2VA 得下 DOWNLOAD_REF2VA=1 权重 + 改 06/06a 的 workflow + references 传参。

三、脚本一览

脚本作用
00_setup_env.sh装 sglang + g++ 12 + diffusers git main + 依赖对齐（transformers==5.12.1 / huggingface_hub / xgrammar）+ qwen3_asr.py 热修 + flash_attention_v3.py 热修
01_download_models.sh下 MiniMaxAI/MiniMax-H3 权重快照（默认 FL2VA/，DOWNLOAD_REF2VA=1 加 Ref2VA/）
02_serve.shSGLang serve（多卡 Ulysses/TP，要起服务，本仓主推 06 不用这个）
03_generate.sh发 HTTP 请求到 02 的服务（配合 02 用）
06_diffusers_inference.shdiffusers 直接跑（bf16 两卡分拆 + auto offload，不起服务）
06a_diffusers_inference.shint8 量化 + group_offload（单卡，省显存，效果基本无损）
08_context_ir.sh调 MiniMax H3-Context-IR API 把短 prompt 转长描述（打印 + 写文件，不自动跑 06）
