# InfiniSplat v2 — 手机人像落地与传统 3DGS 优化迁移

> 2026-11-02，基于本仓脚本、实验归档、现存结果文件和本机官方源码的评审。
> 本文是机制分析与待验证方案，不代表这些迁移已实现或已跑出收益。
> 运行入口见 [README_wsl.md](README_wsl.md)，已有实测见 [EXPERIMENTS.md](EXPERIMENTS.md)。
> 本机 InfiniSplat 源码 HEAD：`be49948`；历史实验不保证全部由同一源码版本运行。

## 1. 结论：前馈初始化可以继承优化资产，但运动要单独建模

InfiniSplat 前馈输出的仍是显式 3DGS。它改变了高斯的初始化方式，没有取消后续可微渲染、
裁剪、精调、压缩的可能性。最实际的路线是：**前馈提供快速初值，既有模块负责修整，
脸/手的外部运动先验负责把不同状态的观测变成可共同解释的数据。**

“人像糊”至少包含四类问题：输入模糊、低分辨率/合成模糊、深度或相机误差、表情/手势冲突。
增强图与更长精调可能改善前两类，但不能让一份静态几何同时解释张嘴/闭嘴、垂手/抬手。
仅看到重影也不能直接判成运动问题：静态多视角深度不一致、标定错误同样会重影。

参数化先验是持续表情/手部运动下值得优先验证的路线，并非所有人像都必须先上完整头像系统。
若产品只保存一个静态瞬间，可先选表情/姿态一致且有足够视角覆盖的片段；若必须利用持续变化
的完整绕拍序列，需拟合逐帧状态，再统一到选定的目标状态。先验也不能凭空恢复遮挡指尖、牙齿等真值。

| 既有资产 | 在 InfiniSplat 上的接入位置 | 可迁移程度与证据 |
|---|---|---|
| 人脸/手/人物检测、跟踪、mask、关键点 | 采集筛选、区域监督、点归属 | 工具与数据约定可复用；尚未接入本项目完整训练链 |
| 原图人脸高分辨率裁剪监督 | `14_finetune_gs.py` 后处理 | 优先做小实验；不同于 E-25~28 的“裁剪后重跑前馈” |
| HYPIR 增强近景整视角注入 | 前馈后生成辅助监督，再精调 | vggt_human 有正结果；本项目需改相机/图像加载，收益未测 |
| 外插视角增强 | 覆盖内/小范围外插的伪监督 | 可试，不能当成新增真实观测或补全正确背面的证据 |
| 矩阵曝光补偿 | 精调渲染后的逐帧颜色变换 | 实现可借；SOM 严格 A/B 为负，不能默认开 |
| 高斯点裁剪、按人拆分、压缩 | 融合前筛选或导出后处理 | 最值得优先移植的工程资产之一；收益需按阶段计量 |
| FLAME/MHR/MANO 绑定与运动统一 | 前馈周边新增动态分支 | 架构改造；不是给现有 PLY 加一个开关 |
| 传统 densify/位置优化/运动场 | 后处理或新增训练链 | 当前 `14` 未实现；不能照搬旧参数和旧收益 |

## 2. 当前实现接口与性能边界

链路为 RGB + 可选相机 → DA3 几何/外观特征 → 深度反投影中心 + 高斯属性 → 体素均值合并
→ opacity 剪枝 → SH0 PLY。`02` 默认再调 `02b` / `14`：固定中心和位姿，仅优化
`sh, scale, opacity, quat`，无 densify、无 prune、无逐帧形变、无曝光模型。

当前 `14` 按 `result.json` 的输入记录匹配原图，再降采样到 `processed_wh`，要求所有视角
同尺寸，使用已有 `cameras.npz`。因此“目录里追加几张增强脸图”不会自动变成新增监督；必须
显式增加辅助视角记录、K、c2w、尺寸、类型、权重和来源映射，避免哈希不匹配后排序回退配错图。
前馈原始记录应保持可追溯，辅助监督另建清单。

| 历史实测/文件核对 | 数值 | 正确解释 |
|---|---|---|
| 32v / 518，佳佳场景，3090 | 冷启动约 35.5 s；显存观测峰值约 18.3 GB | 不是手机性能；与 torch allocated 口径不同 |
| 模型常驻 | `reconstruct()` 约 8.35 s | `bench_stages.py` warm 循环不含导出、网络、排队、精调 |
| 固定中心精调 3000 步 | 约 161 s，torch 峰值约 6.28 GB | 不是完整产品端到端时间 |
| 32v 导出 | 5,940,842 高斯，PLY 403,977,673 bytes | 17 个 float32/点，约 68 bytes；精调没有减少点数 |
| 25 输入 + 7 严格留出 | 留出 PSNR 19.046 → 21.154 | 一个场景、局部插值收益；不是大角度外推保证 |

原始 6.6 GB 权重与 NVIDIA CUDA 依赖不适合直接塞进相机 App。首版建议手机采集/VIO/质检，
云端常驻推理与可选后台精调，手机接收压缩模型。纯端侧要另做主干蒸馏、算子适配和峰值内存设计。

## 3. 人脸裁剪增强：分清三个不同实验

### 3.1 裁剪图重新送进前馈网络

E-25~28 测的是这种路径：改变输入视场，再让 DA3 预测深度/属性。固定手部 ROI 放大后没有改善
该样本的细节，跟踪窗口更差。它支持“不直接把该方案当作默认提质手段”，不支持“所有 ROI 都无用”。
裁剪会改变场景上下文、跨视角对应和模型输入分布；只修 K 不能保证网络效果与全图相同。

### 3.2 用原始图的高分辨率裁剪，监督已经生成的高斯

这是优先推荐的待测方案：全图做一次前馈，保留相机和场景几何；精调时增加脸/手局部渲染，
与真实原图裁剪比较。每个区域单独按有效像素归一化损失，避免面积很小而被整图平均稀释。

若原图裁剪左上角 `(x0,y0)`、输出缩放 `(sx,sy)`，对应像素内参应为：

```text
A = [[sx, 0, -sx*x0], [0, sy, -sy*y0], [0, 0, 1]]
K_crop = A @ K_original
c2w_crop = c2w_original
```

这里不移动相机、不重新估深度；若起点是已处理图的 K，必须先通过完整预处理变换还原到原图
标定，不能混用尺度。resize 像素中心约定也需与渲染器对拍。以原图采样的纯平移/缩放裁剪为首版，
不默认接入含旋转/镜像的“对齐脸图”。框可以逐帧变化，几何上并不要求固定中心；若人物本身在动，
仍须选一致状态或接入形变，裁剪无法代替运动对齐。

它增加的是原本被 518 长边处理丢掉的真实监督。固定中心的 `14` 可能仍受错误深度、点分布和
SH0 表达限制，因此先验证现有参数能否改善；只有确认残余属于几何/容量问题，才逐步增加
局部受约束中心偏移或有限增点，不能一开始放开全场景位置。

### 3.3 HYPIR 增强后作为辅助监督

vggt_human 的证据不能简单概括成“人脸增强都有效”：

- 2026-09-04 的 masked-L1 对照，人脸锐度 +4.04% vs +3.98%，未测到额外收益。
- 09-05 修复了 L1 与 SSIM 监督目标不一致，但修复后的 masked-L1 未重新跑完整效果对照。
- `06e` 的增强近景整视角注入已有正结果：同等续训对照下，近景 LPIPS 降低、训练视角脸部
  锐度提高且相对原图 LPIPS 未上升。其 `06d` 默认 `DENSIFY_UNTIL=0`，不能把收益归因为新增点。
- 近景来自 `render_closeup.py` 的虚拟相机渲染再增强；“已知准确的虚拟相机参数”不等于
  “实拍的新视角”。相对增强目标的 LPIPS 改善不能单独证明真实身份细节恢复。

迁移时建议保持原始 RGB 驱动前馈几何，先在后处理引入增强监督。逐帧生成的皮肤纹理、眼睛、
牙齿可能不一致，直接喂回 DA3 会同时改变几何与外观，难以归因。增强前的渲染共享一份 3D 场景，
不代表逐张增强后仍多视角一致；固定随机种子也不提供该保证。

保留真实原图锚定，增强视角低权重、固定版本生成，不默认无限“渲染→增强→再训练”循环。
L1/SSIM 必须使用一致目标与权重。对表情不同的眼口区域先做状态筛选/参数化对齐，再谈增强。

## 4. 外插视角增强：能做自蒸馏，不能创造观测证据

可复用 `render_closeup.py` 的近景构造思想，以及 `render_novel.py` / `denoise_images.py`
的渲染→增强→附加监督流程；旧脚本依赖传统 GS/Scene/COLMAP 接口，不能直接假定兼容当前 `14`。
新视角必须与高斯处于同一 RDNorm 坐标系，用统一 gsplat 渲染器生成，避免再估一遍伪图位姿。

首轮只取有多视角支持的脸部近景和较小偏移，按人物覆盖与遮挡筛选。旧 `render_novel.py`
用相机中心均值估场景中心，这对不完整弧段不可靠，迁移时应复用经验证的主体中心/视线交汇方法。

辅助相机建议字段：`image, c2w, K, width, height, source_kind, person_id, target_state,
weight, validity_mask, source_frames`。真实裁剪、原始渲染、增强渲染三类不能混成同一种 GT。
曝光已规范化的伪图不应随意继承某个真实相机的曝光矩阵，避免重复补偿。

主要风险是把初始重建的错误自蒸馏固化、增强身份漂移、把未观测表面“画真”。必须用没有参与
前馈、精调、增强参考选择的真实留出图验证；无外推 GT 时只报告伪影体检，不承诺几何正确。
只有 alpha 高、没有孔洞，也可能是错误背景/错误表面填满了画面。

## 5. 矩阵曝光：容易移植，但先证明它是瓶颈

`som_human/exposure.py` 已有逐相机 4×3 齐次仿射，等价于 RGB 上 `I_i = A_i R_i + b_i`，
含闭式初始化、抗外点、恒等正则、独立优化器和测试帧时间插值。可借实现思想接到 `14` 渲染后，
同时校正 L1 和 SSIM。原类含 SOM 的帧索引/保存约定，不能无适配直接复用。

已测边界：double_wave @10k 严格配对 PSNR 21.265 → 20.953（−0.31 dB），SSIM/LPIPS 同向
变差，默认关闭。此负结果不证明 InfiniSplat 必然无收益，也不能把它列为已有成功优化。

建议先对可靠静态对应区域测颜色残差，对比“无补偿 / RGB 增益偏置 / 完整矩阵”，而不是
直接开最大自由度。固定参考相机或约束全局平均变换，防止 SH 颜色与曝光相互补偿导致不唯一。
用前景/静态有效区做拟合，排除动态手脸、饱和像素、错误几何和白背景；矩阵不能解释空间变化的 HDR。

真实新视角没有天然的 frame-id 曝光。产品输出应约定统一参考色彩空间；留出评测不允许根据
测试 RGB 拟合曝光再称为纯 NVS。若另报曝光对齐指标，必须独立标注，保留未经测试图优化的指标。

## 6. 高斯裁剪与按人拆分：价值大，但阶段决定能省什么

可复用资产有两类：SOM `01g/01h` 的跨帧人物 mask/训练场景拆分，以及 vggt_human
`split_person_scene.py` 的多视角点投票。前者没有自动完成 GS 切分；后者依赖 head_fit/mesh
及旧相机解析，而且含头包围盒删除逻辑，不能在没有头部替代模型时直接运行。

| 接入阶段 | 能节省 | 不能自动节省/风险 |
|---|---|---|
| 导出后按人/背景分层与贡献裁剪 | 下载量、移动渲染、后续精调显存 | 已完成的前馈计算与峰值不会倒退消失 |
| 属性解码后、体素合并前筛选 | 部分 raw/merge 内存与融合开销 | 主干特征计算仍然存在；需保留逐像素来源 |
| 缩小输入/分支预测/网络内稀疏化 | 有机会省前馈计算 | 会改上下文/模型结构；逐人重复完整前馈可能反而更慢 |

当前每视角像素产生原始高斯，融合均值之后丢失逐帧来源。要处理动态区域，应在 merge 前记录
`source_view/pixel/person/part/state/confidence`，不同人物/部位/状态避免无条件融合。仅在 `14`
里把动态手 mask 从 loss 排除，前馈已经产生的两态手高斯仍在，不会自动消失。

剪枝先区分：无效点、场景范围裁剪、人物/背景分层、冗余压缩。按可见贡献、多视角一致性和
软边界保留判断，不把“落在一个人 mask 外”直接视为无效：遮挡、mask 漏检、细发丝都可能误删。
点中心投票也不能完全代表大椭球的屏幕贡献；分割边界与深度遮挡需要联合检查。

不能照搬 SOM 的 60 万点上限、opacity 阈值或尺寸阈值。SOM 的“只剪不增却按历史屏幕半径
删大点”发生过死亡螺旋；当前固定中心又无补点，更须保守。先离线裁剪→短程恢复精调→评测，
若训练中增删参数，还要同步 Adam 状态、绑定/来源索引。输出回读对拍不可省略（log-scale/logit-opacity）。
SOM 按人点数/体积约 1/6、速度 3→32 it/s 是旧训练链的结果，不是 InfiniSplat 的加速承诺。

## 7. 脸与手的参数化先验：应怎样接上前馈

### 7.1 先选输出契约

- **静态人像照片/有限视角模型**：选一个参考时刻的表情和手势，跨帧拟合后统一到该状态，
  最后烘焙成普通 PLY。手机不必运行动态模型，但生成阶段仍要解释各帧运动。
- **可驱动人像/动态回放**：保存 canonical 高斯、绑定、逐帧姿态/表情，渲染时形变。
  单个普通 PLY 无法保存完整动画语义，需另定义资产和手机运行时。

### 7.2 两条实现路径

**优先验证：静态背景/躯干 + 独立脸/手绑定分支。** 原图前馈保留场景上下文；对静态分支
显式过滤运动区域生成的高斯，并在后处理排除对应动态监督。人脸拟合共享身份与逐帧头部姿态/
表情，手部拟合共享手型与逐帧关节。绑定分支在各帧姿态下渲染，对真实观测优化外观，再统一
到参考状态导出。前馈深度可作初始化参考，不能强迫先验追随已经混合多状态的错误表面。

**后续研究：逐视角原始高斯逆形变到 canonical，再融合。** 用每帧拟合网格给原始点分配表面
对应/局部坐标，在 merge 前统一状态。须同时变换高斯协方差，局部近似为
`Sigma_c = J Sigma_i J^T`，仅移动中心而保留原旋转/尺度会造成拖影。遮挡、左右手对应、
接触物体、逆蒙皮多解和深度错误会使这条路径不稳定；前馈特征已经跨帧交互，也不会因后置 warp
自动变成动态感知网络。本路线未实现，不能称为低成本修复。

### 7.3 仓内资产状态与缺口

- `vggt_human/DESIGN_face_pipeline.md` 是 FLAME + 表情 + 重心绑定的设计评审，不是本项目
  可直接启用的完整实现。其旧中性脸 + 刚体头部路线不能解释眼口非刚性表情。
- `flame_human/init_avatar_gs.py` 和 `train_avatar.py` 有 `(face_id,bary)` 绑定和逐帧顶点
  驱动代码骨架；“代码存在”不等于已在 InfiniSplat 或目标手机数据上验证。
- MHR 只有 5 维手部 identity，不等于只有 5 个姿态自由度。仓内拓扑探针确认每手 27 DOF，
  可先评估已有关节/网格输出；MANO 是备选，不必先否掉 MHR。手部顶点集合、资产权限与稳健拟合仍要解决。
- 关键点数量/自由度比不能独自证明可观测性；侧脸、遮挡、低分辨率、相关 landmark 和单目深度
  歧义仍存在。共享身份、多帧约束、置信度/时序正则、固定相机与尺度锚定都需要。
- 不沿用“所有光度学习运动方法都失败”的泛化。SOM E-07 限定了既有弱纹理小手实验；
  HiMoR 未实测。这里优先先验是利用外部运动信息，不是证明其它路线不可能。

背景/人体分支和脸/手分支必须在同一世界/RDNorm 空间并共享色彩规范；高斯联合深度排序后
合成，不能简单把几张 RGB 结果叠起来。替换时删除对应的旧脸/手点，保留头发、袖口、衣物、
持物和遮挡关系；点到三角面距离比到最近顶点距离更不依赖网格密度。接缝需明确归属和软过渡，
不能照搬某个场景的固定厘米阈值。头发、牙齿/口腔、手中物体不是裸 FLAME/MANO 自动解决的内容。

## 8. 手机相机链路约束

1. **输入**：同步 RGB/时间戳/逐帧内参/VIO 位姿/跟踪状态；固定镜头与变焦；审查防抖裁剪、
   HDR、多帧融合、EXIF、rolling shutter。以清晰度、平移视差、覆盖和姿态一致性选帧，
   原地转动与真实绕拍不能只靠光轴夹角判断。AR 位姿是测量初值，不能天然当 GT。
2. **位姿**：优先 `provided`，必要时用静态可靠区域做带先验的 BA；别让相机去吸收表情/手动。
   低纹理物体上 DA3 曾静默塌缩，COLMAP 也并非万能。记录归一化变换供 AR 回贴和尺度恢复。
3. **传输**：边采边传关键帧，支持恢复、取消、版本与元数据完整配对。假设 32×0.5 MB、
   上行 10 Mbps，理想上传约 13 s；404 MB PLY、下行 50 Mbps，理想下载约 65 s。
   均不含协议/重试/解码。减点、量化、分块 LOD 同时做，先交压缩预览再更新最终版。
4. **延迟/算力**：分开测采集、上传、排队、解码、前馈、融合、精调、导出、下载、首帧。
   161 s 精调不能混进“前馈几秒”宣传；250/500/1000 步的收益-延迟曲线**尚未测**
   （仓内精调记录全部是 3000 步，没有中间步数的留出数据）。
   BF16、逐视角属性解码和条件主干共享在当前源码已有实现，不能重复计入待实现收益。
5. **手机渲染**：验证点数、排序、透明覆盖、内存峰值、持续帧时间和温升；可打开 PLY 不代表
   可以稳定交互。固定运镜视频与自由视角高斯模型应分别设计交付预算。
6. **几何精度**：PSNR/锐度不是尺度、表面或厚度精度。人像摄影可先限定已采集覆盖内浏览；
   测量/AR 碰撞另需真值与几何误差。无观测背面不可由伪视角监督证明真实恢复。
7. **发布依赖**：本机包 `LICENSE` 为 PRL v1.0，组织项目使用要求事先登记且完整登记后自动授权；
   权重/DA3/增强模型/人体先验另核对实际版本条款。本文未进行完整许可审查。

## 9. 建议实验顺序（均为计划，未新增 GPU 实验）

| 顺序 | 最小实验 | 主要判据 |
|---|---|---|
| T0 | 静态人物、表情变化、两态手势、持续手指动作分组；建立固定真实留出 | 不把合成模糊、动态冲突与视角缺失混成一个均值 |
| T1 | 同一前馈 PLY：整图精调 vs 原图脸/手裁剪监督；均固定中心，匹配采样/计算预算 | 脸/手真实留出 PSNR/LPIPS、边缘、身份稳定性和总耗时 |
| T2 | 无裁剪 vs 按人/贡献裁剪到不同点数；裁剪后短程恢复 | 点数/字节、mask 外泄漏、细结构保留、手机帧时间 |
| T3 | 固定同一起点：纯续训 vs 未增强虚拟近景 vs 增强虚拟近景 | 分离额外采样与增强收益；保留真实图锚定；不拿增强目标独自报质量 |
| T4 | 有明确曝光漂移的数据：无补偿 vs 增益偏置 vs 全矩阵 | 未用测试图拟合的留出指标、色彩稳定性；无收益保持关 |
| T5 | 单一脸或单只手：先验拟合→绑定→参考状态烘焙；与一致姿态选帧对比 | 嘴眼/指尖误差、运动解释、重影、接缝；随后才扩展多人 |
| T6 | 对已有效组合测 250/500/1000/3000 步及蒸馏可行性 | 质量-总延迟曲线、P50/P95、显存与移动端预算 |

严格留出必须在前馈之前划分，不能只用 `14 --holdout-every` 把已经参与前馈的图留出于精调。
增强模型的条件图、姿态拟合与超参选择不得使用最终测试 RGB；可用同源采集元数据定位测试相机，
需记录协议。动态单目序列的“新时间 + 新视角”有混淆，优先补同步多视角或可复现状态数据，
没有时分别报告动态帧重投影与静态子段 NVS，不声称已测得同一时刻任意视角质量。

固定分辨率、裁剪映射、视角/姿态覆盖、背景合成与计算预算；至少报告脸/手局部和最差视角，
以及 mask 外泄漏、alpha/轮廓、时间稳定性。锐度可能被噪点抬高；mask 内 PSNR 会漏掉外部鬼影。
所有迁移要与“只做相同步数精调”的基线对照，必要时再匹配墙钟时间，不以更多训练冒充模块收益。

## 10. 本次复核更正与证据索引

### 10.1 更正 ROI 的因果解释

E-26 旧文把 `raw_scale` 写成 `[B,S]`。本次核对当前 `geometry.align_rdnorm_gt_via_legacy_da3`
及 DA3 `batch_align_poses_umeyama`：后者按 batch 遍历轨迹，每条轨迹返回一个 scale，即 `[B]`；
`(raw_scale/radius)[:,None,None]` 给同场景全部相机乘同一尺度。因而不能据当前源码声称逐帧
相机间距被各自缩放。历史 ROI 质量差异保留，主因需要用实验版本、深度/对齐输出再验证。

> 2026-11-03 补证（把"版本不同"这个退路关掉）：运行时 `import infinisplat` 解析到
> `~/repos/InfiniSplat/InfiniSplat_v2/src/infinisplat/`，该仓 2026-10-30 11:55 clone 后
> 未再 pull/checkout，`geometry.py` mtime 10-30 12:33 早于 ROI 实验（10-31）。即 ROI 那组
> 跑的就是读到的这份 `[B]` 代码，旧解释是**记错形状**，不是版本差异。
> 另：`align_depth_to_input_extrinsics` 里 `scales.view(*view_shape)` 的 `view_shape=[B,1,1,1]`
> 也只容得下 numel=B——若真是 `[B,S]` 会直接 RuntimeError，不会静默跑通。
“固定框较好”是这组前馈实验的经验，不是所有 ROI/跟踪窗口必须固定的几何定理。

### 10.2 收紧其它归因

- 精调自洽 +8.11 dB、留出 +2.11 dB 的比值不能当作其它场景的固定 26% 折扣。
- E-35 是一个场景的无真值外推体检，不能推出“弧外 30° 安全”或“精调无副作用”。
  中心固定也不禁止协方差变成扁薄形状；能否出现类似贴片的效果需观察协方差和多视角质量。
- 缩小体素没有收益，不等于任意受约束增点都无效；前馈 ROI 失败，不等于后处理原图 ROI 监督无效。
- 增加锐度、位置冻结精调有效，不能唯一证明所有模糊都由同一种 alpha 合成机理造成。
