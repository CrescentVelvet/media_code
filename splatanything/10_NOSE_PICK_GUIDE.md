## 二、每块怎么看

每块是**竖排两张**，同一裁窗、同一缩放：

```
┌──────────────────┐
│ A01          v001│  ← 左上编号(绿/橙) + 右上视角号
│ ┌──────────────┐ │
│ │   GT 原始照片 │ │  ← 上：GT（走 1439 原生分辨率，无虚假放大）
│ ├──────────────┤ │
│ │   RD 重建渲染 │ │  ← 下：RD（504 原生）
│ └──────────────┘ │
│ GT            RD │
└──────────────────┘
```

- **绿号** = 检测到人脸，鼻部特写窗 → **可以指认鼻宽**
- **橙号** = 没检测到脸，显示**整幅全景** → 多为纯侧面/背面，**不能判鼻宽**，
  只用来确认"这个视角确实拍不到正脸"

单块的原始文件在 `tiles/<sub>/<视角>_gt.png` 和 `_rd.png`（360×360），想放更大直接开这两个。

## 三、看什么（四类症状）

对照 RD 与上方 GT：

| symptom | 长什么样 | 为什么重要 |
|---|---|---|
| `wide` | 鼻翼整体变宽、鼻头变大，但边界还算干净 | 对应 N3（合并/footprint）或 N4（像素预算） |
| `ghost` | 鼻孔或鼻翼边缘**出现第二层轮廓**、半透明双影 | 对应 N2（跨视角中心不一致）——这是"重影"的字面证据 |
| `blur` | 糊、发虚，但没有明显变宽、没有双层 | 对应 N4（分辨率/域）或重建过平滑 |
| `ok` | 与 GT 基本一致 | **务必也指几个**——没有正常对照就无法判断是不是全盘变差 |

**注意**：`ghost` 与 `wide` 经常同时出现。若两层轮廓都能看出，优先填 `ghost`，
并在备注里写"同时偏宽"。

## 五、几条必须知道的口径（否则会误判）

1. **同一视角的 GT 在不同 run 里是同一张图**。裁窗只由 GT 决定，所以 `roi_norm`
   cross-run 完全相同（已验证：24 个共享视角的 GT tile **逐像素一致**）。
   如果你看到某个视角在不同 sheet 上位置不一样，那是 bug，告诉我。

2. **GT 显示用的是原生分辨率**，不是先降到 504 再放大。GT 原生 ROI 边长 342~440 px，
   出图 360 px → 缩放 **0.82~1.05×**，基本 1:1。所以你在 GT 上看到的清晰度就是
   真实照片的清晰度，**GT 糊不是脚本造成的**。

3. **GT 与 RD 已经同框对齐**：两边肤色重心差 |Δ| ≤ 0.035（归一化），
   检测框中心差中位 0.005。可以直接上下对比，不存在位置偏移。

4. **橙号块不要用来判鼻宽**。本数据 99 个视角里有 36 个检不到脸（纯侧脸/背面），
   这些块给的是全景，脸可能只占画面 10%。拿它说"鼻子变宽"是无效的。

5. **本批只有佳佳一个人**。R2-N 原文要求"原坏例 + 另一独立人像 + 一个正常人像"三组对照，
   目前只满足第一组。`jiajia_hold_3v/8v/13v/24v` 是**同一次采集的不同视角子集**，
   不是独立人物。所以本轮结论只能标"单人验证"，跨人泛化要等第二个人像包。

## 六、指认完之后我会做什么

按 `da3_human/EXPERIMENT_PLAN.md` §0.0 R2-N 的预案：

1. 用填好的 `pick` 建 `nose_diagnosis.csv`：每个目标视角量
   **鼻翼宽度误差**（归一化为同视角眼间距，避免"整体放大"冒充"鼻子变宽"）
   + 对应点误差，**每个视角都量，不只量最差那张**。
2. 出 `nose_contact_sheet.png`：原始 RGB、预处理输入、GT/RD 鼻部同像素裁图、
   **alpha / depth / source 分层投影**——用来区分"几何真的宽了"与"半透明糊成一片"。
3. 按 N0~N4 逐条判：相机模式是否一致、相机估计误差、跨视角中心深度一致性、
   合并/footprint、域与像素预算。
4. **晋级信号（预注册，不改）**：鼻宽绝对误差或对应点误差相对降低 **≥20%**，
   且超过重复标注误差，且在**至少两个独立坏例的相同 held-out 上方向一致**。
   达不到就只写"宽化/模糊，重影未证实"。
